# DB Migration Page

## Purpose

数据迁移（SQLite ⇄ PostgreSQL 单向快照）原内联于数据库管理页，随功能生长挤占连接注册表主视图。本能力将迁移整体独立为「数据迁移」页面（系统管理分类），数据库管理页仅保留状态摘要卡与导航入口：页面承载迁移发起、SSE 进度、进行中恢复、历史管理与护栏提示，迁移期间全局写锁语义与后端端点行为保持不变。

## Requirements

### Requirement: 数据迁移独立页面
系统 SHALL 提供独立「数据迁移」页面（系统管理分类、数据库管理旁），承载迁移全部能力：源/目标连接选择与迁移模式选择、SSE 迁移进度流（`/migrate-stream`，断连不中断后台迁移）、迁移进行中状态恢复（`GET /database/running-tasks` 将 running/pending/interrupted 视为进行中）、迁移历史管理（**历史列表 + 清理预览与清理执行**——`/database/history`、`/database/history/cleanup-preview`、`/database/history/cleanup` 能力随段迁移，不得丢失）、以及迁移期间全局写锁的 UX 提示（写请求 503 的界面层拦截与防二次启动）与迁移语境护栏提示（**「静态资源存储于服务器磁盘，迁移/切换不影响」提示随迁移段迁入本页**）；**注册表中可用连接不足以同时提供源与目标时 MUST 禁用发起并提示**。页面与菜单可见性 MUST 挂 `database_management` 权限键（迁移端点权限不变，不新增后端资源或权限键）；页面 MUST 注册导航搜索元数据。

#### Scenario: 从数据库管理摘要卡进入迁移页
- **WHEN** 有 database_management 权限的用户在数据库管理页点击摘要卡的「开始迁移」入口
- **THEN** 进入数据迁移独立页，可直接完成源/目标选择并发起迁移

#### Scenario: 迁移页承载完整迁移流程
- **WHEN** 用户在独立页选择源与目标连接并启动迁移
- **THEN** SSE 进度实时展示（当前表/行数/阶段），行为与拆分前完全一致（后端端点零改动）

#### Scenario: 迁移进行中再次进入页面
- **WHEN** 迁移后台执行中（含客户端断连后）用户重新打开迁移页或数据库管理页
- **THEN** 页面展示进行中状态与可恢复的进度信息，不提供二次启动入口

#### Scenario: 可用连接不足
- **WHEN** 连接注册表中可用连接少于 2 个（无法同时提供源与目标）时打开迁移页
- **THEN** 发起入口禁用并提示需要源与目标连接，页面其余信息正常展示

### Requirement: 数据库管理页迁移摘要卡
数据库管理页 SHALL 在原迁移位置保留**状态摘要卡**：当前 active 连接、最近一次迁移结果、迁移进行中状态，以及「开始迁移」入口（**纯导航——进入独立页，摘要卡 MUST NOT 就地触发迁移**）；**摘要卡数据为挂载时单次拉取，MUST NOT 建立常驻轮询（对齐备份摘要卡模式，进行中状态以打开时为准）**；**摘要卡与入口渲染 MUST 挂 `database_management` 权限**；`DatabaseManagement.vue` 页面 SHALL 不再内联迁移执行 UI（迁移执行能力整体迁移至独立页与迁移组件）。

#### Scenario: 摘要卡与双入口
- **WHEN** 有权限的用户打开数据库管理页
- **THEN** 迁移摘要卡显示当前活动连接与最近一次迁移结果，并提供进入迁移页的导航入口；页面本体不再包含迁移表单与进度 UI

#### Scenario: 无权限不渲染
- **WHEN** 无 database_management 权限的用户打开相关页面
- **THEN** 摘要卡与迁移页菜单项均不可见

### Requirement: 迁移全局写锁提示不变
迁移运行期间，系统 SHALL 保持既有全局写锁语义（写请求统一 503、`running/pending/interrupted` 视为进行中）——独立页面拆分 MUST NOT 改变锁语义、SSE 事件格式或迁移端点行为；前端只做 UX 层拦截（提示 + 阻止二次启动），不在前后端新增并发控制。

#### Scenario: 拆分后锁语义不变
- **WHEN** 迁移进行中时任意页面发起写操作
- **THEN** 行为与拆分前一致（503 与既有提示），迁移期间登录/只读端点行为不变
