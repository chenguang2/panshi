# SQLite Remote Backup

## Purpose

将平台注册的全部 SQLite 库定时快照打包，并经 SSH 推送到异地远端目录（含保留清理），实现本机数据损坏或丢失场景下的异地容灾备份；与活动连接类型无关（活动为 PostgreSQL 时站点库照常备份）。

## Requirements

### Requirement: 备份调度触发
系统 SHALL 在备份配置启用时，以后台调度循环按配置间隔（分钟，默认 60，最小 1）自动触发备份——**节奏按上次运行时间计时（成败均计），不按上次完整成功**；触发前 MUST 检查无进行中的备份或恢复任务（共用互斥，防重入，**互斥覆盖全部位置的扇出过程**）；数据库迁移运行中 MUST 跳过调度（避免快照迁移中间态）；db_config 注册表中不存在任何 SQLite 连接时 MUST 跳过调度并显示不适用；**不存在任何启用的备份位置时 MUST 跳过调度并显示不适用（未配置启用的备份位置）**；启用或保存配置（含位置保存）后 MUST 在一个调度周期内（30 秒）触发首次备份。

#### Scenario: 到期自动触发
- **WHEN** 备份已启用且距上次**运行**（不论成败）达到配置间隔
- **THEN** 系统自动执行一次备份，历史记录触发来源为 scheduled

#### Scenario: 备份进行中防重入
- **WHEN** 上一次备份尚未完成且调度周期到期
- **THEN** 本次周期跳过，不产生并发备份

#### Scenario: 恢复进行中推迟备份
- **WHEN** 恢复向导流程进行中且调度周期到期
- **THEN** 本次周期跳过，恢复完成后下一周期恢复调度

#### Scenario: 迁移运行中跳过
- **WHEN** 数据库迁移任务运行中且调度周期到期
- **THEN** 本次周期跳过，不产生对迁移中间态库的快照

#### Scenario: 注册表中无 SQLite 连接
- **WHEN** db_config 注册的所有连接均为 PostgreSQL
- **THEN** 调度跳过备份，UI 显示「不适用（无已注册的 SQLite 数据库）」

#### Scenario: 无启用备份位置跳过
- **WHEN** 备份总开关已启用但不存在任何启用的备份位置
- **THEN** 调度跳过备份，UI 显示不适用（未配置启用的备份位置）

#### Scenario: 启用后快速首备
- **WHEN** 用户保存并启用备份配置或新增首个启用位置（此前从未成功备份）
- **THEN** 30 秒内触发首次备份

### Requirement: SQLite 库在线快照
系统 SHALL 对 db_config 注册的**每个 SQLite 连接库**执行 `VACUUM INTO` 生成一致快照，**与活动连接类型无关**（活动连接为 PostgreSQL 时注册的 SQLite 库照常备份）；快照 MUST 在运行中的 WAL 模式库上安全执行且不阻塞业务；**活动库文件缺失 MUST 使整次备份失败**；**非活动注册库文件缺失或不可读 MUST 跳过该库并在 meta.json 记入 skipped 清单**；未注册的库文件 MUST NOT 进入备份包。

#### Scenario: 多站点库全部快照
- **WHEN** db_config 注册了 panshi.db 与 nanchang/panshi.db 两个 SQLite 连接且备份触发
- **THEN** 两个库各自生成快照并进入包内 databases/ 段（按连接 id 命名）

#### Scenario: 活动库为 PostgreSQL 时站点库照常备份
- **WHEN** 活动连接为 PostgreSQL 且注册表中有 SQLite 站点库
- **THEN** 备份正常执行，覆盖全部注册的 SQLite 库

#### Scenario: 非活动库缺失跳过并记录
- **WHEN** 某非活动注册库的文件已被删除
- **THEN** 该库被跳过、meta.json 的 skipped 清单记录该连接，备份整体继续成功

#### Scenario: 活动库缺失整体失败
- **WHEN** 活动连接对应的库文件不存在
- **THEN** 本次备份终止并记录失败历史

#### Scenario: 未注册的垃圾库不打包
- **WHEN** data/ 目录存在 test.db、sample.db 等未在 db_config 注册的库文件
- **THEN** 这些文件不出现在备份包中

### Requirement: 备份包内容与环境一致性
备份包 SHALL 为 tar.gz，包含：meta.json、databases/（注册库快照，**按连接 id 平铺命名，meta 记录每个库的原路径**）、config/（db_config.json、features.yaml、clickhouse.yaml、.jwt_secret、**全部存在的 .env.\***）、ansible/（inventory/host、inventory/backups/、group_vars/）、data/（仅勾选开关项）；data/ 下 static/、task-scripts/、task-logs/ 三项 MUST 为配置开关且默认全部不勾选。meta.json SHALL 记录 app 版本标识（pyproject version，部署目录存在 .git 时附 commit hash，皆不可得记 unknown）、备份时间（UTC）、active 连接 id、**来源标识**、每个文件的字节大小与 SHA256、各库原路径与 skipped 清单。

#### Scenario: A 类配置文件必含
- **WHEN** 备份执行
- **THEN** 包内包含 db_config.json、features.yaml、clickhouse.yaml，且 .jwt_secret 与全部已存在的 .env.* 一并打包

#### Scenario: 库原路径记录
- **WHEN** 某注册库位于 data/ 相对路径、另一注册库位于绝对路径
- **THEN** 两者均以连接 id 平铺进入 databases/，meta.json 分别记录其原路径供恢复落位

#### Scenario: B 类开关默认关闭
- **WHEN** 用户未修改打包开关配置即触发备份
- **THEN** 包内 data/ 段不含 static/、task-scripts/、task-logs/

#### Scenario: 勾选后随包
- **WHEN** 用户勾选 static 与 task-scripts 后触发备份
- **THEN** 包内 data/ 段包含 static/ 与 task-scripts/，不含 task-logs/

#### Scenario: 元数据记录版本与校验和
- **WHEN** 备份包生成
- **THEN** meta.json 记录 app 版本标识（尽力而为，不可得记 unknown）、active 连接 id、每个文件的字节大小与 SHA256、skipped 清单

#### Scenario: 元数据记录来源标识
- **WHEN** 备份包生成
- **THEN** meta.json 记录本机来源标识，供恢复侧展示与核对

### Requirement: SSH 推送与远端保留清理
系统 SHALL 构建备份包**一次**，并对**每个启用的备份位置**通过 SSH 按序串行推送（先 `mkdir -p`，再以 `.part` 临时名上传，成功后原子改名；**单位置失败记录子结果后继续下一位置，不中断整体**）；备份包名 SHALL 为 `panshi_backup_{source}_{YYYYMMDD_HHMMSS}.tar.gz`（source 为来源标识，取值规则见「备份配置模型与安全存储」；同一包名推送到各位置）；远端列表与保留清理 MUST 仅匹配**组合白名单正则**——同时接受新格式与升级前旧格式 `panshi_backup_{YYYYMMDD_HHMMSS}.tar.gz`（正则 MUST 单点定义于备份服务并由恢复服务复用，禁止两处硬编码各自演化）；**每个位置 MUST 按各自的保留份数独立清理**，候选集 MUST 为「来源标识等于本机的包 ∪ 旧格式包」，**MUST NOT 删除来源标识不同的新格式包**；候选集内 MUST 按包名中的时间戳倒序保留该位置的保留份数、删除更旧的；密码认证 MUST 经 SSHPASS 环境变量传递且绝不进入命令行参数；密钥认证 MUST NOT 依赖 sshpass；日志与审计中的命令 MUST 脱敏密码；**远端侧命令中拼接的路径与文件名参数 MUST 经 `shlex.quote` 转义**。

#### Scenario: 多位置扇出
- **WHEN** 配置了两个启用位置（局内DR 保留 7 份、中心机房保留 30 份）且备份触发
- **THEN** 包构建一次，两个位置各自收到同一包名文件，并按各自保留份数独立清理

#### Scenario: 单位置失败不中断
- **WHEN** 扇出推送中第一个位置连接失败
- **THEN** 该位置记录失败子结果，第二个位置照常推送，整体状态为 partial

#### Scenario: 包名含来源标识
- **WHEN** 来源标识为 `192.168.0.5` 的平台实例执行备份
- **THEN** 生成的备份包名形如 `panshi_backup_192.168.0.5_20260930_153000.tar.gz`

#### Scenario: 共享目录同秒互不覆盖
- **WHEN** 两台平台实例（来源标识不同）同一秒内备份到同一远端目录
- **THEN** 两个包文件名不同，互不覆盖

#### Scenario: 密码认证推送
- **WHEN** 配置为密码认证且 sshpass 已安装
- **THEN** 远端目录自动创建，备份包上传并原子改名完成，命令行参数中不含密码明文

#### Scenario: 上传中断不留半截文件
- **WHEN** 上传过程中连接中断
- **THEN** 远端仅存在 `.part` 临时文件（不计入保留份数、不出现在备份列表），下次备份不受影响

#### Scenario: sshpass 缺失提示
- **WHEN** 配置为密码认证且 sshpass 未安装
- **THEN** 备份失败并给出包含安装指引的明确错误信息

#### Scenario: 超保留量清理最旧
- **WHEN** 本机来源的包数达到该位置的保留份数且新备份上传成功
- **THEN** 系统删除该位置候选集内最旧的超出份，保持候选集份数不超过该位置的保留份数

#### Scenario: 不删他源新格式包
- **WHEN** 远端共享目录存在来源标识为其他实例的新格式包且本机清理触发
- **THEN** 那些包不被删除、不计入本机保留份数

#### Scenario: 旧格式包自然老化
- **WHEN** 升级后远端仍存在本机升级前产生的旧格式包
- **THEN** 旧格式包参与本机保留窗口排序，随新备份增加自然老化删除，不永久堆积

#### Scenario: 远端命令参数转义
- **WHEN** 远端目录配置含空格或特殊字符
- **THEN** 拼接进远端命令的路径经 shlex.quote 转义，命令按预期执行且无注入风险

### Requirement: 备份配置模型与安全存储
系统 SHALL 以两层模型存储备份配置：**全局单行**（总开关、间隔、来源标识、三个打包开关、最近状态）与**备份位置表**（可多行：名称、主机、端口、用户、认证方式、密码、密钥路径、远端目录、保留份数、启用开关）；配置保存 MUST 校验间隔 ≥ 1 分钟；**位置保存 MUST 校验名称非空、≤ 64 字符、不含路径分隔符与文件系统保留字符（`/ \ : * ? " < > |`）及控制字符、首尾无空白，且全库唯一（名称允许中文——仅用于下拉与历史快照展示，不进文件名与 shell 命令，文件名安全由来源标识正则单独负责）；保留份数 ≥ 1；密码编辑留空表示不修改**；**来源标识非空时 MUST 匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`（首字符必须字母/数字），否则校验拒绝**；**来源标识为空或未提供时 MUST 自动解析并持久化**（解析顺序：到第一个启用备份位置方向的出口 IP → 主机名 → 兜底常量；配置保存时与存量空值首次备份时各解析一次并回写）；**备份执行 MUST 使用已存储的来源标识，MUST NOT 每次备份动态重新探测**；**容灾恢复落位后新机 MUST 保留恢复包配置内的来源标识（保证远端旧包的保留清理连续性）**；位置密码 MUST 以 Fernet 加密落库且 API 响应 MUST NOT 回显明文；**升级部署后存量单行配置 MUST 迁移一次且仅一次为一条「默认位置」+ 全局行（全局行 `targets_migrated` 标志为假且旧目标字段非空时触发，迁移后置位；旧目标字段保留不删，保证回滚可用；标志防「用户删光位置后重启 → 默认位置复活」）**；系统 SHALL 以历史主表记录每次备份（时间、状态、包体积、耗时、错误信息、触发来源），并以**位置子结果表记录推送阶段每个启用位置的推送结果**（位置名称快照——位置删除后历史不丢失、状态、错误、耗时；**构建阶段失败时整体 failed、无子结果行**）。

#### Scenario: 两层配置读写
- **WHEN** 用户配置了两个备份位置并保存全局开关与间隔
- **THEN** 全局行与位置表分别落库，配置响应返回全局字段与位置列表（密码不回显）

#### Scenario: 位置名称重复被拒
- **WHEN** 新增位置名称与既有位置重复
- **THEN** 返回校验错误，位置不落库

#### Scenario: 中文名称可用
- **WHEN** 保存名称为「中心机房」的位置
- **THEN** 校验通过，下拉与历史快照正常展示中文名称

#### Scenario: 位置非法值被拒
- **WHEN** 保存保留份数为 0、名称含路径分隔符/控制字符或首尾空白的位置
- **THEN** 返回校验错误，位置不落库

#### Scenario: 位置密码留空不修改
- **WHEN** 编辑位置时密码留空提交
- **THEN** 该位置已存密码保持不变，响应不回显明文

#### Scenario: 全局非法值被拒
- **WHEN** 保存间隔为 0 分钟的全局配置
- **THEN** 返回校验错误，配置不落库

#### Scenario: 来源标识非法字符被拒
- **WHEN** 保存含 `/`、空格、首字符非字母数字（如 `..`、`-x`）或超过 64 字符的来源标识
- **THEN** 返回校验错误，配置不落库

#### Scenario: 来源标识空值自动解析
- **WHEN** 保存备份配置时未填写来源标识
- **THEN** 系统解析出口 IP（不可得时取主机名，再不可得取兜底常量）并持久化，配置响应回显该值

#### Scenario: 存量空值首次备份回写
- **WHEN** 升级部署后存量配置的来源标识为空且首次备份执行
- **THEN** 备份前解析并回写配置行，本次及后续包名均使用该值

#### Scenario: 恢复继承来源标识
- **WHEN** 容灾恢复将备份包内的站点库落位到新机
- **THEN** 新机的备份配置保留恢复包内的来源标识，后续备份沿用该标识（旧机产生的远端包被新机视为己方，保留清理连续）

#### Scenario: 存量单行一次性迁移
- **WHEN** 升级部署后启动且迁移标志为假、旧单行含目标主机字段
- **THEN** 自动创建一条「默认位置」（复制旧目标字段与保留份数，启用）并置位迁移标志，重复启动不重复创建

#### Scenario: 删光位置后重启不复活
- **WHEN** 用户已迁移后删除全部位置并重启服务
- **THEN** 迁移标志已置位，不再自动创建默认位置

#### Scenario: 备份历史含位置子结果
- **WHEN** 一次完成推送阶段的备份（任意状态）结束
- **THEN** 历史主表记录三态状态（success/partial/failed）、耗时、包体积与触发来源，且每个启用位置各有一条子结果（状态、错误、耗时），UI 历史展开行可见

#### Scenario: 构建失败无子结果
- **WHEN** 包构建阶段失败（如活动库缺失）导致备份失败
- **THEN** 历史主记录为 failed 并记录构建错误，不产生位置子结果行

#### Scenario: 删除位置保留历史
- **WHEN** 某位置被删除后查看其参与过的历史记录
- **THEN** 子结果仍以名称快照展示，不因位置删除而丢失

### Requirement: 手动立即备份与审计
系统 SHALL 提供「立即备份」操作（触发来源记 manual）；立即备份 MUST NOT 要求启用开关，但 MUST 要求**至少一个启用的备份位置**（允许只跑一次不开定时）；不存在启用位置时 MUST 返回明确的配置不完整错误；备份或恢复任务进行中时手动触发 MUST 被拒绝并提示；**全局配置变更、位置增删改、手动备份 MUST 写操作审计**。

#### Scenario: 未启用时立即备份
- **WHEN** 备份位置已配置且至少一个启用，但未勾选总开关，用户点击「立即备份」
- **THEN** 立即执行一次备份，历史触发来源为 manual

#### Scenario: 无启用位置明确报错
- **WHEN** 不存在任何启用的备份位置，用户点击「立即备份」
- **THEN** 返回明确的配置不完整错误，不执行备份

#### Scenario: 配置变更审计
- **WHEN** 用户保存全局配置、增删改备份位置或执行立即备份
- **THEN** 操作审计日志记录对应操作

### Requirement: 权限与鉴权
备份全部端点 MUST 挂鉴权并使用**独立的 `db_backup` 权限键**（不再复用 `database_management`）；新增端点（位置 CRUD、位置测连）MUST 纳入 `tests/test_security_guard.py` 的 UNAUTHENTICATED_SAMPLES 采样。

#### Scenario: 未认证访问被拒
- **WHEN** 未携带认证信息访问备份任一端点
- **THEN** 返回 401，且该端点已列入安全守卫测试采样

#### Scenario: 无备份权限被拒
- **WHEN** 已认证但无 db_backup 权限的用户访问备份端点
- **THEN** 返回 403

### Requirement: 备份管理页面与导航
系统 SHALL 提供独立「备份与容灾」页面（系统管理分类、数据库管理旁）承载备份全局配置、位置管理、历史与恢复向导；数据库管理页 SHALL 在原备份位置保留**状态摘要卡**（状态统计、最近一次备份结果、「进入备份管理」与「灾难恢复」双入口——后者直达新页恢复向导；无任何配置时显示引导文案）作为下钻入口；**摘要卡渲染 MUST 挂 `db_backup` 权限（无权限整卡不渲染，避免接口 403 噪音）**；页面与菜单可见性 MUST 挂 `db_backup` 权限键，并注册导航搜索元数据。

#### Scenario: 独立页面与摘要入口
- **WHEN** 有 db_backup 权限的用户分别打开数据库管理页与备份与容灾页
- **THEN** 前者显示摘要卡（含进入备份管理与灾难恢复双入口），后者承载完整备份管理功能

#### Scenario: 无备份权限不渲染摘要卡
- **WHEN** 有 database_management 但无 db_backup 权限的用户打开数据库管理页
- **THEN** 摘要卡整卡不渲染，页面其余部分正常

#### Scenario: 无权限不可见
- **WHEN** 无 db_backup 权限的用户查看左侧菜单
- **THEN** 备份与容灾菜单项不可见，直接访问路由被权限拦截

### Requirement: 备份页编辑态与已保存态隔离
备份管理页 SHALL 将「已保存状态」与「编辑中表单」分为两个数据源：状态区（调度徽章、下一轮预计、最近成功、不适用原因）MUST 仅读取服务端已保存配置与 status 数据；编辑表单的未保存修改 MUST NOT 改变状态区展示；存在未保存修改时页面 SHALL 显示显式「有未保存修改」标记，保存按钮与全局配置表单 MUST 在视觉上构成贴近的可操作单元；「刷新」操作在存在未保存修改时 MUST 先经确认，确认后放弃修改并重新加载。

#### Scenario: 未保存修改不污染状态区
- **WHEN** 已保存配置为启用、间隔 60 分钟，用户把表单开关拨到停用但未保存
- **THEN** 状态区调度徽章仍显示「已启用」、下一轮预计仍显示已保存配置的具体时间，页面出现「有未保存修改」标记

#### Scenario: 下一轮预计单一数据源
- **WHEN** status 返回 next_run_at
- **THEN** 状态区「下一轮预计」显示该具体时间而非配置间隔，且该值不随表单未保存修改变化

#### Scenario: 刷新脏守卫
- **WHEN** 存在未保存修改且用户点击「刷新」
- **THEN** 弹出确认（说明将丢弃未保存修改），确认后重新加载并清空编辑态，取消则保持现状

### Requirement: 立即备份未保存守卫与执行预期
「立即备份」在存在未保存修改时 MUST 弹出三选确认：保存并备份、按已保存配置备份、取消；选择「保存并备份」MUST 先保存成功再触发备份；执行期间按钮 MUST 锁定并显示耗时预期（按启用位置数给出推送范围提示）；触发被拒（409 已有任务进行中）时 MUST 展示后端原因且不静默。

#### Scenario: 脏状态下三选确认
- **WHEN** 存在未保存修改且用户点击「立即备份」
- **THEN** 弹出「保存并备份 / 按已保存配置备份 / 取消」三选，选择后按所选路径执行，取消不执行

#### Scenario: 按已保存配置备份提示
- **WHEN** 用户在脏状态下选择「按已保存配置备份」
- **THEN** 备份按服务端已保存配置执行，提示说明实际执行的是已保存配置而非屏幕所见

#### Scenario: 执行期耗时预期
- **WHEN** 立即备份请求进行中
- **THEN** 按钮锁定不可重复点击，等待文案包含启用位置数量与耗时预期

#### Scenario: 冲突拒绝可见
- **WHEN** 备份或恢复任务进行中触发立即备份返回 409
- **THEN** 展示「已有备份/恢复任务进行中」类明确提示，不静默失败

### Requirement: 位置健康信号与安全交互
备份位置表格 SHALL 展示每个位置的「最近推送」状态（状态点 + 最近推送时间，数据从备份历史的位置子结果聚合派生，删除位置后以名称快照参与聚合，不新增后端接口）与「最近测试」结果；位置测连文案 MUST 明示校验范围（仅 SSH 连通与凭据正确，不校验远端目录可写性与磁盘空间）；停用位置 MUST 经确认（提示将停止接收新备份、容灾能力下降）；位置启用开关 MUST 与全站控件风格一致。

#### Scenario: 最近推送状态点
- **WHEN** 某位置最近一次推送子结果为失败
- **THEN** 该位置行显示红色状态点，tooltip 显示最近推送时间与结果

#### Scenario: 删除位置的名称快照参与聚合
- **WHEN** 某位置被删除后查看其参与过的历史
- **THEN** 健康聚合仍按名称快照计算，不因位置删除而丢失信号

#### Scenario: 测连范围明示
- **WHEN** 用户点击位置「测试连接」
- **THEN** 提示或结果说明明确校验范围仅含 SSH 连通与凭据，不含远端目录可写性与磁盘空间

#### Scenario: 停用确认
- **WHEN** 用户关闭某启用位置的开关
- **THEN** 弹出确认（说明该位置将不再接收新备份、容灾能力下降），确认后方生效

### Requirement: 历史可读性与恢复打通
备份历史列表 SHALL 支持按状态与触发来源筛选；失败记录的失败原因 MUST 行内可见（展开或折叠区内，不依赖 hover title；构建阶段失败 MUST 同样有可展开的原因区）；每条含包名的历史记录 SHALL 提供「恢复此包」入口，仅在存在已配置备份位置时显示，点击后打开恢复向导并预选该包；手动输入来源路径不参与预选。

#### Scenario: 失败原因行内展开
- **WHEN** 历史列表存在失败记录（含构建阶段失败）
- **THEN** 行内提供展开操作，展开后直接可见失败原因，无需 hover

#### Scenario: 历史筛选
- **WHEN** 用户按状态「失败」或触发来源「手动」筛选
- **THEN** 列表仅显示匹配记录，筛选与分页组合正确

#### Scenario: 从历史发起恢复
- **WHEN** 已配置备份位置且用户点击某成功历史记录的「恢复此包」
- **THEN** 恢复向导打开并预选该包（高亮/勾选状态可见），用户从校验步骤继续

### Requirement: 摘要卡口径与入口样式对齐
数据库管理页备份摘要卡 SHALL 与主卡口径一致：下一轮显示具体时间（无计划时显示「未启用定时」）、备份进行中显示进行中状态、状态徽章全部为中文（含 running 态）；摘要卡与主卡上的「灾难恢复 / 恢复向导」入口 MUST 为次级样式（非危险描边常驻态），执行恢复的高危视觉仅保留在实际执行步骤内。

#### Scenario: 摘要卡显示具体下一轮时间
- **WHEN** 定时备份已启用且 status 返回 next_run_at
- **THEN** 摘要卡显示与主卡一致的具体时间，而非「间隔 N 分钟」

#### Scenario: 摘要卡进行中状态
- **WHEN** 备份任务执行中
- **THEN** 摘要卡显示「备份中」进行中状态（中文徽章），不显示英文原文

#### Scenario: 危险入口降级
- **WHEN** 用户浏览备份页与数据库管理页常态界面
- **THEN** 恢复类入口为次级按钮样式，无危险色描边常驻

### Requirement: 备份页分区结构与常驻状态层
「备份与容灾」页 SHALL 采用「常驻状态操作层 + 页内 Tab 内容区」结构：状态四格、错误横幅、立即备份、恢复数据主入口、刷新与「有未保存修改」徽标 MUST 位于常驻层（页内任何 Tab 下可见，sticky 化滚动时不离场）；内容区 MUST 以页内 Tab 分为「备份位置」「策略与保留」「备份历史」三页，默认落在「备份位置」；Tab 切换 MUST NOT 销毁非激活 pane（表单内存态保留），「有未保存修改」时切换 Tab MUST NOT 弹窗拦截，未保存状态的可见性由常驻层徽标承担（点击跳回策略 Tab）；恢复向导 MUST 保持 modal 形态与三入口语义，入口文案统一为「恢复数据」系；Tab 选中状态 MUST NOT 进入 URL。

#### Scenario: 常驻层跨 Tab 可见
- **WHEN** 用户停留在「备份历史」Tab
- **THEN** 状态四格、立即备份按钮、「有未保存修改」徽标（若有）仍在页面常驻层可见可点

#### Scenario: 切换不丢表单态
- **WHEN** 用户在「策略与保留」Tab 修改间隔但未保存，切到「备份历史」再切回
- **THEN** 输入保留原值、dirty 徽标仍显示，无任何内容丢失或拦截弹窗

#### Scenario: 未保存徽标跳回
- **WHEN** 存在未保存修改且用户在「备份历史」Tab 点击常驻层徽标
- **THEN** 页面切回「策略与保留」Tab，表单与徽标可见

#### Scenario: 恢复入口统一命名
- **WHEN** 用户查看常驻层主按钮、历史行内动作与数据库管理页摘要卡入口
- **THEN** 三处均为「恢复数据」系命名（行内保留「此包」指向性），语义上可识别为同一功能的三个入口

#### Scenario: 刷新历史不丢选中状态之外的信息
- **WHEN** 用户在「备份历史」Tab 使用筛选并翻页
- **THEN** 常驻层状态不因筛选/翻页变化，历史 Tab 内容独立响应筛选
