# Proposal: 备份多目标（多位置扇出与独立页面）

## Why

1. **单一容灾目标是单点**：DR 机磁盘损坏、被勒索加密、网络长期分区，任一情况都会让整条备份链失效。灾备 3-2-1 原则要求多目的地（局内近线一台恢复快 + 中心机房离线一台真异地是典型形态）。
2. **与来源标识（db-backup-source-tag）正交互补**：source-tag 解决「多机 → 同一目录」的互删；本变更解决「一机 → 多位置」的副本冗余，合起来支撑完整的多机多副本拓扑。
3. **信息架构**：备份状态是日常巡检职能（今天成没成、哪个目标红了），当前埋在数据库管理页（1474 行）深处，与迁移/切换等高危低频操作混排；独立页面 + 摘要入口让巡检路径更短。

## What Changes

- **配置两层化**：`ps_db_backup_config` 退化为全局单行（总开关、间隔、来源标识、三个打包开关、调度状态列）；新增 `ps_db_backup_target` 目标表（名称、主机、端口、用户、认证方式、密码/密钥、远端目录、保留份数、启用开关），可配置多个位置。
- **差异化粒度**：仅**保留份数**按位置差异化；内容段、频率、来源标识全局统一（机器身份与目的地无关；包构建一次与目标数无关）。
- **执行扇出**：一次构建 → 串行推送到每个**启用**目标 → 每目标独立保留清理（own-source ∪ legacy 语义原样沿用）。
- **部分失败三态**：`success` / `partial`（黄色警示 + `N/M 目标` 小注）/ `failed`；`last_success_at` 仅全绿更新；历史 1 条主记录 + N 条目标子结果（新表，展开行展示每目标 ✓/✗/−）。
- **恢复向导**：备份来源改为单选卡片——「从已配置位置选择」（下拉含**全部位置**＝按包名聚合去重，停用目标列出并标注）或「手动输入」（换机场景保留）。
- **独立页面与权限**：新页「备份与容灾」（系统管理分类、数据库管理旁）承载完整功能；数据库管理页原位置换状态摘要卡（四格统计 + 最近一次结果 + 入口按钮）；权限键独立 `db_backup`。
- **存量迁移**：旧单行的目标字段自动拆为 1 个「默认位置」目标行 + 全局行，幂等，零手工。
- 设计文档 `docs/design/sqlite-backup-dr.md` 同步。

## Impact

- **能力 spec**：
  - `sqlite-remote-backup`：MODIFIED「备份调度触发」「SSH 推送与远端保留清理」「备份配置模型与安全存储」「手动立即备份与审计」「权限与鉴权」5 个需求 + ADDED「备份管理页面与导航」。
  - `sqlite-backup-restore`：MODIFIED「临时目标输入的恢复入口」。
- **代码**：`models/db_backup.py`（新两表）、`services/db_backup_service.py`（扇出/三态/迁移）、`services/db_restore_service.py`（按目标列包/聚合）、`api/v1/db_backup.py`（目标 CRUD + config 两层）、`schemas/db_backup.py`；前端新增 `views/BackupManagement.vue`、`DbBackupCard.vue` 改造（目标表格 + 编辑抽屉）、向导 step1 改造、`DatabaseManagement.vue` 换摘要卡、路由/菜单/navMeta/权限 keys 双端注册。
- **权限**：新键 `db_backup`——已授 `database_management` 的非 admin 用户**不会自动**获得新页访问权，需重新授权（admin 直通不受影响）。
- **兼容性**：`GET /db-backup/config` 响应形态扩展（增 targets 数组）、恢复 list 支持按目标查询——前后端同仓同发，无外部消费方；旧库升级经幂等迁移无损承接。
