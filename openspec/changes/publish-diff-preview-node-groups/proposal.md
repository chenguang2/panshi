# Proposal

## Why

发布差异预览的逐节点矩阵按节点铺列，列数随节点数线性增长（20 节点 = 22 列、200 = 202 列），且当前弹窗无任何宽表适配（列被压缩折行、表撑出弹窗）——节点数增长后呈现不可用。用户裁决采用 **E1d 阈值混合**：小集群（≤5 节点）保持现有矩阵（信息全景），大集群（>5 节点）自动切换「按差异形态分组」呈现（列数 = 形态组数，与节点数彻底解耦）。分组是现有矩阵的前端聚合视图，同一份响应数据两种呈现，后端零改动。

## What Changes

- PublishPreviewModal 呈现模式按节点数自适应（纯前端，响应契约不变）：
  - **≤5 节点**：保持现有逐节点矩阵（行为零变化）
  - **>5 节点**：按「与待发布的差异形态」分组呈现——每节点的差异指纹（差异路径集 + 各路径值）相同的节点归一组：差异组展示 组头描述 + 组内节点 IP chips + 组内差异表（字段路径 × 待发布 × 组内同值）；「与待发布一致」「资源缺失」「不可达」各归其组，仅列 IP chips（不可达附原因）
  - 既有交互不受影响：「显示一致字段」开关在差异组内生效（追加该组与候选一致的字段行）、「去发布」、重新检测、结论条与汇总 chips 均保持
- 分组聚合为纯函数实现（可独立单测）；阈值 5 以常量承载
- 组内呈现采用代表值（同组节点值全同，E2a）；「与待发布一致」组只列 IP（E3a）；后端零改动（E4a）

### Modified Capabilities

- `publish-diff-preview`: 「预览弹窗呈现」需求扩展——矩阵呈现 SHALL 随节点数自适应（≤5 逐节点矩阵，>5 差异形态分组），分组不改变对比口径、逐节点数据完整性与既有交互。

## Impact

- 前端：`components/PublishPreviewModal.vue`（分组聚合与呈现分支；聚合逻辑提为可单测的纯函数/独立计算属性）；`components/__tests__/PublishPreviewModal.test.ts`（新增 >5 节点分组用例）。
- 后端零改动（响应含全量 per-node 数据，前端聚合在几百节点规模仅几百 KB）。
- 阈值混合保证当前 ≤3 节点部署的呈现与交互完全不变。
