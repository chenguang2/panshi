# proposal: ansible-inventory-ux-review-fixes

## Why

用户以标准评审简报要求对 Ansible 主机清单模块做体验评审（易用性 / 易理解 / 美观层级 / 安全风险四维），输出 openspec 需求文档，批准前不动代码。证据链：`AnsibleInventory.vue`（973 行）与 `ansible_inventory.py` / `inventory_service.py` 全文走读、`utils/ansibleInventory.ts` 纯函数核对、主规格 `ansible-inventory-management` 对照、既有测试断言核对（`test_ansible_inventory_api.py`）、真实页面 Playwright 走查 6 张截图（表格/高级展开/删除保护弹窗/批量导入/源码视图/脏状态）+ API 探针 5 组（parse 错误文案采样，全部不落盘，现场已还原）。

**模块本质**：单页双模式（表格 ⇄ 源码）的凭据管理页，`PUT /ansible/inventory` 二选一载荷，保存护栏链 = 载荷校验 → 运行中任务 409 → 解析校验 → 结构校验（hosts 路径）→ 备份 + 原子写回。页面成熟度高（脏护栏 / Ctrl+S / beforeunload / 路由守卫 / 未知键保真 / 未纳管提醒 / 删除保护齐备）；问题集中在**护栏一致性、恢复记录可见性、保存反馈**。

**关键语义实锤（影响问题定级）**：

- **源码模式保存绕过删除保护**：`put_inventory` 的 `raw_text` 分支只做 `parse_inventory`（L113-117），**不执行** `validate_structure`（含删除保护与主机键合法性，仅 hosts 路径 L123-127 调用）。主规格场景「删除平台已录入的主机被阻止 → 保存被拒绝」未限定视图；表格视图的前端拦截（`removeRow`）在**同一页面**切到源码视图即可绕过。测试只钉了 hosts 路径（`test_put_deletion_protection_returns_400`），raw 路径无断言。
- **备份存在但不可见**：每次保存自动备份（`inventory/backups/host.bak.<ts>`，保留 10 份，含遗留文件自愈迁移），页面零入口——误保存后只能 SSH 翻文件。审计已覆盖（PUT → `ansible_inventory.save`，audit_hook L178），页面无操作日志入口。
- **保存反馈过弱**：成功仅 toast「已生效」三字——不说明保存规模（N 台主机）与生效对象；GET 响应不带文件 mtime，页面无法显示「最后修改时间」。
- **批量导入口径静默宽松**（截图 04 实锤）：`bad ip here` 被解析为合法主机键 `bad` 零提示通过（placeholder 写「IP [SSH用户] [SSH密码]」，实际口径是 IPv4 **或主机名**）；预览只有「将覆盖 1 条」，无「将新增 N 台」摘要。
- **明文口径不动**（约定 #10 铁律）：密码明文存储与展示，页面 description 已说明历史原因；本变更不触碰该口径。

## 问题清单

### P1（护栏 / 风险感知）

1. **源码模式保存绕过删除保护与结构校验**：`raw_text` 路径缺 `validate_structure`（删除保护 + 主机键合法性检查），违反主规格场景字面；同页内即可绕过表格视图的前端拦截，误删平台节点会导致节点任务找不到主机。
2. **恢复记录不可见**：10 份自动备份零 UI——维度 4「是否提供恢复记录」直接缺失；无备份列表、无一键恢复、无备份内容预览。

### P2（易理解 / 易用）

3. **保存反馈过弱**：「已生效」无规模与对象信息；无「清单最后修改：{时间}」元数据（mtime 未暴露）；无操作日志入口（审计数据已在）。
4. **批量导入预览不足**：主机键口径与 placeholder 文案不一致；非 IP 主机键静默通过；预览缺「将新增 N 台」摘要，覆盖提示只在其一分支显示。
5. **高级字段校验错误不定位**：保存前校验失败以 toast 汇总（`第 2 行（…）：SSH 端口必须为…` 拼接），不自动展开出错行、不定位字段。
6. **空源码文案误导**：`parse('')` 报「结构错误（第 1 行）: …hosts 必须是映射」——用户意图是「清空清单」，错误性质是「空清单场景不支持」而非结构错误（GET 对文件不存在返回无错误，两处口径不一致）。

### P3（文案 / 打磨）

7. 页头 description 冗长：历史事故说明（「脱敏占位曾被误写回清单…」）占小半段，对无需背景的管理员是噪声。
8. 「SSH 密码（明文）」列头在组级与主机列表两处重复标注「（明文）」。
9. 保存成功后整页 GET 重载，行展开状态与滚动位置丢失（行键经 WeakMap 随对象重建失效）。

## Goals

- 保存护栏跨载荷形态一致：删除保护与结构校验对 `raw_text` 与 `hosts` 两种载荷同等生效
- 恢复记录可见可用：备份列表 + 内容预览 + 一键恢复（恢复走既有保存全护栏 + 审计）
- 保存反馈完整：规模（N 台主机）、生效语义、最后修改时间、操作日志入口
- 批量导入预览诚实：新增/覆盖双摘要、口径与 placeholder 一致、非 IP 主机键显式提示

## Non-goals

- 不改明文存储与展示口径（约定 #10 铁律；掩码机制已由历史事故证伪）
- 不做连通性验证（清单页内 ansible ping——见决策点 3，推荐独立立项）
- 不扩展多组管理（固定 `all.children.edge_cluster` 是产品边界）
- 不做凭据与节点管理的数据同源合并（两处各自维护是既有设计）

## 分批

- **批 1（护栏与恢复，P1-1/2）**：`raw_text` 保存补 `validate_structure(platform_ips)`（400 带既有文案格式）；备份列表 + 内容预览 + 一键恢复（新端点只读列表 + 恢复走 `save_inventory` 全护栏含 409 互斥；恢复前确认弹窗显示目标备份时间与当前差异摘要；恢复动作写审计）
- **批 2（反馈与表单，P2-3/4/5/6 + P3-7）**：保存成功 toast 增强（「已保存并生效：N 台主机」）；GET 响应带 `last_modified`（文件 mtime）+ 页头元数据行 + 「操作日志」入口；批量导入预览重构（将新增 N 台 / 覆盖 N 条双摘要 + 口径说明 + 非 IP 主机键警示行）；高级校验失败自动展开首个出错行 + 行内标红；空源码语义文案区分（「清单为空」引导 vs 结构错误）；页头 description 精简（保留一句明文口径说明）
- **批 3（打磨收尾，P3-8/9 + 决策点裁决项）**：列头「（明文）」标注收敛；保存后保持行展开状态（行键稳定化）；全量验证 + 真页走查

## 需补充（待确认）

- **角色口吻**：`ansible_inventory` 为 admin-only（侧边栏注释「后端 admin-only，管理全部节点 SSH 凭据」）——本档按「管理员」口吻撰写，不做角色分支。如与实际权限配置不符请指出。

## 决策点（待用户裁决）

1. **raw_text 删除保护**：A 补齐——源码模式保存同样执行结构校验 + 删除保护，400 文案复用既有格式（**推荐**：对齐主规格场景字面，堵同页绕过）/ B 维持豁免——源码视图定位为专家后门，主规格场景改口「表格视图保存被拒绝」
2. **备份能力**：A 列表 + 内容预览 + 一键恢复（**推荐**：完整闭环「恢复记录」维度；恢复 = 以备份内容走既有保存护栏，复用度高）/ B 仅列表 + 预览，恢复仍手动 / C 不做（维持 SSH 手工兜底）
3. **连通性验证（清单页 ansible ping 按钮）**：A 纳入本变更批 3——对单台/全部主机发起 ad-hoc ping 并流式展示结果 / B 独立立项（**推荐**：涉及后台 ansible 执行、409 互斥与超时语义，与节点任务域交叉，规模超出体验修复边界）
