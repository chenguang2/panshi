# 设计：edge-env-port-validation

## D1 校验位置：双端同语义，后端权威

- 后端 `validate_edge_env` 为**权威校验**（部署端点 `cluster_edge_env.py:88` 既有 `(is_valid, error_msg)` → 422 分支，校验器内增强即自动生效，端点零改动）。
- 前端 `EdgeEnv.vue::validateFields` 增加**同语义检查**做发布前即时反馈（后端 422 前早退，避免无谓弹发布流程）。这与既有结构检查的「前端/后端双端重复」模式一致（该模式为现状，本变更不治理）。
- 错误文案两端措辞一致，用户在任一侧看到同一句话。

## D2 端口提取与判定规则（核心）

条目形态按实机实测（v32 真实内容解析）：

1. **主形态** `dict`：`{"addr": "0.0.0.0:16610", "ssl": true}` —— 取 `addr` 字段。
2. **兼容形态** `str`：`"0.0.0.0:16610"` —— 直接使用（防御旧版本/手写内容）。
3. **跳过**（不校验、不报错）：
   - `unix:` 前缀（实机存在 `unix:conf/edge_stream_monitor.sock`）
   - 无 `addr` 键的 dict 条目（未知扩展字段，不误伤）
   - 注释行不进 YAML 解析结果，天然不涉及
4. **端口提取**：取**最后一个 `:`** 之后的部分（兼容 IPv6 `[::]:80` bracket 形态的防御处理；实机当前仅 IPv4）。无 `:` 视为缺端口 → 非法。
5. **判定**：端口须为纯整数字符串且 `1 <= port <= 65535`。拒绝 `99999`、`0`、负数、`abc`、空串、浮点字符串。

## D3 错误文案（含字段路径 + 定位 + 原值 + 解法）

定稿格式（两端一致）：

```
deploy → http → edge → listen 第 1 项端口非法: 0.0.0.0:99999（端口须为 1-65535 的整数）
```

- 字段路径沿用既有 ` → ` 分隔风格（与「缺少必填字段」文案同款）。
- 「第 N 项」为 listen 列表 1-based 序号；str 条目原值直接展示，dict 条目展示 `addr` 原值。
- 尾部附合法范围，用户可直接修正（对齐 S 评审「错误提示须给原因与解法」基线）。

## D4 非目标（见 proposal）

节点侧校验、custom/lua 扩展扫描、端点/playbook 改动均不做。

## D5 测试面与验收

- **后端单测**（`backend/tests/test_yaml_validator.py` 扩展，既有文件）：非法值参数化（99999/0/-1/abc/空串/无冒号）+ 合法边界（1/65535）+ `unix:` 跳过 + str 条目兼容 + dict 无 addr 跳过 + **实机真实内容全文通过**（防误伤的护栏用例，内容取 v32 脱敏样本）。
- **后端集成**：`test_cluster_edge_env.py` 部署端点用 99999 内容 → 422 且消息含字段路径（校验在 ansible 之前，无需 mock 执行流）。
- **前端组件测试**（`EdgeEnv.test.ts`）：validateFields 经发布链路断言——99999 内容点发布 → 不打开发布弹窗、提示含「端口非法」；合法内容照常打开。
- **实机验收**：API 直接部署 99999 → 422（不触节点）；test 集群正常注释行发布不受影响（收尾一次）。
- **回归**：后端 `pytest -k "edge_env or cluster"`；前端 `EdgeEnv.test.ts` + 触碰文件全量三连（#208 串行）。PG 冒烟不触发（纯校验，无 schema/写库路径变更，#103 不适用）。
