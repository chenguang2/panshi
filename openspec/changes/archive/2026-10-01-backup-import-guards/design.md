# Design: 2026-10-01-backup-import-guards

## Context

BAK-08 是前向兼容问题（新版备份 → 旧版平台导入），PLG-07 是引用完整性问题（删除插件组留下失效引用）。

## Decisions

- **D1 白名单 = ORM 属性键 ∪ 列名**：只取属性键会漏 `SslCertificate.private_key`（列名 `key`，约定 #23 错位）——先以列名通过白名单、再由 `_ssl_kwargs` 改名为属性名；其余实体两条集合等价，多出的列名集合无副作用。
- **D2 丢弃而非报错**：未知字段按「本版本不认识」处理直接过滤，导入继续——与「结构缺失（必备键非法）→ 400」的硬校验分层：缺必需信息才拒，多出信息宽容。
- **D3 PLG-07 对齐 SSL CA 守卫形态**：delete_db=true 时先扫描引用，有引用 400 列明细（≤3 条 + 「等」）；`delete_edge` 分支（不删库记录）不受限——Edge 侧删除不影响本地路由引用有效性。
- **D4 畸形 plugin_config_ids 按「不含引用」**：JSON 解析失败视为无引用放行删除，与 cluster_backup 导入期对畸形 JSON 的清理语义一致，不让脏数据永久锁死删除。
