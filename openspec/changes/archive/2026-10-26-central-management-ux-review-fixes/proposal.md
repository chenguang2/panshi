# Proposal: central-management-ux-review-fixes

## 背景

对「统一管理」模块（/central-management：CentralList + ClusterCard + ClusterBackupDialog + useClusterBackup + 节点/路由等 Tab 组件）完成一轮体验评审：全量代码走读 + Playwright 真实页面走查（默认视图 / 最大化面板 / 备份下载弹窗 / 导入弹窗 / 节点 Tab，5 张全页截图），结论逐条对照源码核验。评审期间发现并实锤恢复功能 P0 缺陷（`last_published_at` 字符串绑定 DateTime → 导入 500），**该缺陷已分立为 `cluster-backup-restore-fix` 变更**，本变更引用不重复。

## 主要问题（按严重度）

### P1（高危误解 / 风险不可见）

- **P1-1 「恢复」措辞与 clone-only 单向语义冲突**（约定 #17）：入口「从备份恢复」/ 标题「从备份恢复集群」/ 按钮「开始恢复」，用户合理期待「原集群原地恢复」，实际是「新建未发布集群」。弹窗正文虽有解释，但术语先行误导；且「恢复」与版本管理的「恢复（回滚）」在同一系统内语义撞车。
- **P1-2 新集群名称规则不可见**：NAME_PATTERN（小写字母/数字/中划线、首尾禁中划线）只在提交后 400 才暴露（评审实测 `restore_probe_tmp` 即踩 400）。弹窗无规则说明、无前置校验。
- **P1-3 完整性校验和从未接线**：后端已实现 `X-Backup-Checksum` 响应头 + `expected_checksum` 校验参数（设计 D1），前端下载时丢弃响应头、导入时不传——防损坏/防篡改能力在真实链路中不存在。
- **P1-4 导入失败错误裸奔**：失败仅见「服务器内部错误」无原因无建议（后端转译已列入 `cluster-backup-restore-fix` D5；本变更承接前端呈现与建议动作文案）。

### P2（易用性 / 一致性缺口）

- **P2-1 卡片与展开面板动作集不一致**：网格卡片仅 详情/连接测试/编辑/删除；「备份下载」「导出 Excel」必须先展开面板才能触达——高频保护性操作埋两层。
- **P2-2 组名双重冗余**：分组头已显示组名，卡片 topbar 再次显示同一组名（7 卡片 8 次重复），占用视觉层级却零信息增量。
- **P2-3 「插件元数据」Tab 缺计数徽章**：展开面板 7 个 Tab 中唯一无计数，与其他 6 个不一致。
- **P2-4 分页与全站标准脱钩**：`pageSize: 100` 硬编码，与约定 #54 卡片网格标准 `PAGE_SIZE_CARD_GRID=500` 不符；>100 集群时第 101 个起静默消失（UserList 同型 bug 的翻版，约定 #54 教训）。
- **P2-5 刷新模型粗放**：`loadClusters` 重建全部 cluster 对象——任何 Tab `@refresh`、连接测试后均把展开面板 Tab 重置回「集群节点」、已加载子表数据清空（#203 已知陷阱的全局版）；且挂载时对每个集群 eager `loadNodes+loadUpstreams`（7 集群 = 15+ 请求/次，未展开也加载）。
- **P2-6 导入弹窗原生文件控件**：`Choose File / No file chosen` 英文浏览器默认样式，与全站中文 + AntV 视觉割裂。
- **P2-7 下载弹窗无内容摘要**：不勾选两个开关时用户不知道「备份会包含什么、有多大」；cluster 对象上现成统计数未利用。
- **P2-8 备份 vs 导出 Excel 语义无解释**：两个导出动作并列，无任何说明哪个用于恢复、哪个用于阅读。
- **P2-9 组头集群 chips 无状态文字**：仅色点 + 名称，色义（绿=已启用）不可知（卡片本体有「已启用」badge，chips 没有）。
- **P2-10 资源表空态无引导**：路由/上游等空表仅「暂无数据」，未提供「添加第一条」主行动（约定 #57：空态槽名注意用 `#emptyText`）。

### P3（小瑕疵 / 润色）

- **P3-1 节点表「reload」英文按钮**：中文界面夹英文小写按钮（启动/停止/reload）。
- **P3-2 两套状态维度无区分标注**：节点表「运行中/已停止/未检测」= 运行态（node-management spec 定案，按 nginx 判定）；连接测试弹窗「在线/离线」= 管理面连通性。术语各自正确（不合并），但同屏出现无维度标注，评审者初次也误读。
- **P3-3 `catch (e: any)` 两处**（runTest/exportCluster）：约定 #5 精神下的类型卫生项。
- **P3-4 展开动画 `max-height: 500px` forwards 残留**：动画结束后 max-height 锁 500px，长内容面板有裁切/布局隐患（待实测确认后修复）。

## 拟议变更（分 4 批，低风险先行）

1. **批 1·文案与校验前置（纯前端低风险）**：P1-1 术语诚实化（恢复→导入）+ P1-2 名称规则前置校验 + P2-3 Tab 计数补齐 + P2-4 分页对齐 PAGE_SIZE_CARD_GRID + P2-9 chips title + P3-1/P3-3。
2. **批 2·备份弹窗体验**：P2-6 上传控件重绘 + P2-7 下载摘要行 + P2-8 双导出语义说明 + P1-3 校验和接线（方案见决策点）+ P1-4 错误建议文案框架。
3. **批 3·刷新与加载模型（共享语义，消费方断言清单先行，约定 #217）**：P2-5 刷新保状态（按 id merge 保留 activeTab/已加载数据）+ 节点/上游延迟到展开时加载 + 挂载请求合并。
4. **批 4·结构润色**：P2-1 卡片动作集对齐（方案见决策点）+ P2-2 topbar 冗余处置（决策点）+ P2-10 空态引导 + P3-2 维度标注 + P3-4 动画残留。

## 决策点（待确认）

1. **P1-3 校验和接线**：A 同会话自动携带（下载时存内存映射，同会话导入同文件自动带校验和，推荐）/ B 导入弹窗加可选校验和输入框 / C 不做（维持现状，记录为已接受缺口）。
2. **P2-1 卡片动作集**：A 卡片加「更多」下拉收纳 备份/导出 Excel（推荐，防按钮溢出）/ B 平铺补两按钮。
3. **P2-2 topbar 组名冗余**：A topbar 不再显示组名、只留最大化按钮（推荐）/ B 保持现状。
4. **批 3 是否纳入本轮**：A 纳入（收益大：状态保持 + 请求数下降，推荐）/ B 延后单独立项（本轮只做 1/2/4 批）。

## 待补充信息（不阻塞批 1/2）

- 统一管理的主要使用者角色与高频路径（管理员全局运维 vs 受限用户管自己集群），影响批 4 动作取舍。
- 预期集群规模（是否可能 >100，验证 P2-4 修复优先级——已按对齐标准处理，仅确认）。
- 备份文件的实际流转方式（同机重导 or 跨机迁移），影响校验和方案的会话内假设是否成立。

## Impact

- 前端：CentralList.vue、ClusterBackupDialog.vue、useClusterBackup.ts、ClusterCard.vue（slot 消费侧）、clusters/Tab 组件空态（小改）；共享侧仅 useClusterUtils 刷新链路（批 3，断言清单先行）。
- 后端：零改动（P1-4 后端部分已在 `cluster-backup-restore-fix`）。
- 兼容性：无 schema/接口变更；批 3 改变刷新行为需回归 #203 面板局部刷新语义（既有测试覆盖）。
