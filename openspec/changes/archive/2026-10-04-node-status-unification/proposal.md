# Proposal: node-status-unification

## Why

两处用户可见缺陷（2026-10-04 用户验收报告）：

1. **后果不可见**：节点编辑表单的启用/停用勾选框语义含混，且「停用节点静默退出中继网关流量白名单」的后果完全不可见——areatest 事件实证（4 节点全部停用 → 网关 map 空 → 发布全 403），没人知道因果。
2. **措辞三套混用**：节点管理表单「启用/停用」、统一管理节点表单「正常/禁用」且无提示——同一个管理开关在不同页面叫不同的名字。

## What Changes

- 节点表单（添加/编辑）状态控件由勾选框改为原生 select 下拉框（启用/禁用），与集群表单「状态」控件形态一致；脚本层零改动（statusCheck 布尔语义原样）
- 表单附后果说明：「禁用的节点不进入中继网关流量白名单（不承载业务流量），但仍可执行节点任务与状态查询」——节点管理与统一管理两处字面完全一致，源码守卫钉死（漂移即红）
- 节点管理表格：禁用节点行首显示「已禁用」红徽章，与 nginx 运行态列（运行中/已停止）并存——管理开关与进程状态是两个维度，此前禁用节点在表格完全隐形
- 措辞统一：节点维度一律「启用/禁用」（「停用」「正常」在节点语境废弃）；集群维度保持「正常/禁用/运行中」不动（集群=运行状态、节点=管理开关，语义不同，用户明确不统一）

## Capabilities

- `node-management`：「节点状态控件与措辞统一」需求（下拉形态 + 后果说明两页一致 + 已禁用徽章 + 措辞规范）
