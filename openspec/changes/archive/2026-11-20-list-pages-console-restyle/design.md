# Design

## Context

三张独立列表页（`NodeList.vue` / `UpstreamList.vue` / `RouteList.vue`）基于 a-table + `useColumnConfig`/`ColumnConfigPopover`/`useColumnDragColumns`/`usePagination` 构建，2026-11-15 刚完成独立页列配置统一（standalone-list-column-config）。设计基线：`frontend/src/styles/theme.css`（OKLCH tokens，禁止新色系）。已批准的视觉与交互规格：`docs/ui/Live-Artifact-5/proposal-c/`（九页示例 + `routes-sort-demo.html` 双模式交互演示 + README 裁决记录）。约束：后端零接口改动（分组与徽标均为前端聚合）；统一管理页三张 Tab 子表不在范围；列配置存储键（`*_standalone`）与既有持久化兼容。

## Goals / Non-Goals

**Goals:**

- 三页统一升级为集群分组 + 显式双模式，共享实现单点，禁止三页各复制一份。
- 全部既有功能零删减（筛选项、列配置、拖拽调宽调序、行内动作、批量、发布/删除/版本入口）。
- 守卫测试体系（tableAnatomy、SearchInput、权限键等）保持有效。

**Non-Goals:**

- 后端分组接口 / 按集群整组分页（后续增强）。
- 统一管理页三张 Tab 子表改造。
- 页首 KPI 统计卡（用户否决）、i18n、新色系、暗色内容区。
- route-management 排序字段清单中 `status` 的 spec/code 分叉纠偏（既有分叉，另行处理）。

## Decisions

### D1 分组为纯前端呈现层聚合

当页数据按「集群 → 组内固定序」稳定排序后，在数据源中注入**组头标记行**渲染分组（a-table 无原生分组行；标记行以专用标记识别，行渲染定制 colspan 与组头内容，勾选/排序交互对标记行禁用）。接口、参数、分页模型零改动。

- *备选否决*：后端 group-by 分页 API——动端点契约、超出本轮零后端边界；a-table `expandable`/`summary`——语义不符（组头不是汇总行/展开行）。
- 组内固定序：路由=优先级升序、上游=名称、节点=IP 数值序（服务端返回序基础上前端稳定排序，当页 ≤500 行开销可忽略）。

### D2 双模式为单份状态机

每页三份状态：`viewMode('group'|'flat')`（默认 group）、`sortState({key,dir}，跨模式持久)`、`foldState(map，仅 group 模式消费)`。分组模式请求**不带**排序参数（组内固定序），平铺模式带 `sort_by/sort_order`（仅生产可排序列：路由 name/uri/priority/created_at；节点/上游无可排序列）。切换模式不清筛选、不清排序键（裁决：排序键休眠——分组期间箭头与清除入口隐藏、不参与组内序；回平铺原样恢复）。切换器落工具条右端最右（toolbar-ux delta）。

- *备选否决*：隐式「排序自动切平铺 + 提示条」——排序动作不应隐式改变表格结构（用户裁决显式双模式）；分组模式组内排序（页内局部排序与全局服务端排序两套语义并存，必被误读）。

### D3 页头徽标统计取数口径

服务端分页下「全局统计」通过**一次大分页统计请求**实现：进入页面与筛选变化时，以 `page_size=500`（MAX_PAGE_SIZE）请求一份当前筛选的统计副本（仅用于徽标聚合，不渲染表格），`total` 直接取响应 total。部署规模内（≤18 集群 × ≤3 节点，#257 语境）数据量恒小于分页上限。

- *备选否决*：按当页行聚合——「27 节点 · 21 运行中」会混用全局 total 与页内分布，数字自相矛盾；后端响应附带 `status_summary` 聚合字段——更准但违反本轮零后端边界，留作后续增强（见 Risks）。

### D4 共享实现单点

新增共享组合式 + 组件承担三页共性：分组/双模式状态机（组合式，如 `useListClusterGrouping`）、集群组头行渲染、模式切换器、页头统计徽标、状态胶囊。三页只做装配。批量条选中态强调、发布状态胶囊化、「⋯」两行式菜单等共享语言按既有单实现约定落共享层，禁止页面复制（仓库约定 #24/#51）。

### D5 列配置与存储兼容

- 列配置字段集合调整：三页移除「集群」勾选项；**节点页保留「Edge 安装路径」「OpenResty 安装路径」两个独立存储键**（呈现层合并为「安装路径」单列两行堆叠，按勾选状态决定单行/双行）；**路由页保留「方法」「URI」独立键**（呈现层合并为「请求匹配」列，按勾选状态渲染 chips/URI）。零存储迁移、与既有持久化完全兼容。
- 序号列恒展示、拖拽调宽调序、重置列宽入口唯一在弹窗内等既有规则不变。

### D6 刷新按钮统一

三页工具条刷新 = 各页既有加载函数（`loadNodes`/`loadUpstreams`/`loadRoutes`），不触发状态检测、不重置筛选/排序键/视图模式。路由页规格此前已承诺刷新（CSS 注释「后续的刷新」），本次兑现。

### D7 上游目标健康与权重条

健康点与权重数据取自上游列表响应的真实 target 字段（**实现前先 curl 实测响应形状**，遵守 #43「mock/渲染必须取自真实后端响应」教训）；权重占比 = target 权重 / 该上游权重合计，纯前端计算。

## Risks / Trade-offs

- [页内分组跨页组聚散，找某集群需翻页] → 集群筛选下拉保留为快捷路径；整组翻页留后续增强（spec 已注明）。
- [统计副本 500 上限截断] → 部署规模内恒达标；超限时 total 仍准、状态分布可能偏低 → 后续加后端聚合字段增强。
- [组头标记行与 rowSelection/排序/hover 交互兼容] → 标记行禁用勾选与排序命中；组件测试钉住。
- [共享层改动波及三页既有断言] → 按约定 #217 先 grep 消费方产出断言反转清单（「列配置靠左」类断言、tableToolbarUx source 守卫等），全量单测收口；落地按低风险先行分批（节点页 → 上游页 → 路由页）。
- [双模式状态与既有分页/筛选联动回归面大] → 每页组件测试覆盖四步主流程（切平铺→排序→切分组→回平铺恢复），交互语义以 `routes-sort-demo.html` 为准。

## Migration Plan

无数据迁移、无后端部署依赖，纯前端独立上线。localStorage 新增折叠/模式键（列配置键不变）。回滚 = revert 前端提交。

## Open Questions

无——统计口径（D3）、合并列配置策略（D5）已定；组件命名与标记行实现细节留 tasks 按本设计执行。
