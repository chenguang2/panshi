# Design: 2026-10-02-db-backup-followups

## Context

备份页 UX 硬化后的三笔跟进：样式两处（页签/间距）、直达链路一处、时间格式一处。

## Decisions

- **D1 直达链路复用既有预选机制**：`preselectTargetId`（位置级）与既有 `preselectPackageName`（包级）叠加——开门 `initSource` 切「已配置位置」模式并选中该位置后触发列包，列包成功走既有包名预选 + 后续 prescroll 定位，不新增平行状态；`null` 表示通用入口（仅加载位置列表），行为不变。
- **D2 位置已删回退聚合**：预选位置 id 在开门时已不存在（配置被删），回退「全部位置」聚合并照常列包——预选是便利而非前提，不让脏引用卡死向导。
- **D3 安全闸不因直达缩短**：直达只省「选来源 + 列包 + 选包」三步，「校验此包 → 高危确认 → 执行」闸门完整保留。
- **D4 恢复入口危险化递进**：常驻层「恢复数据…」与摘要卡「恢复数据」改 btn-danger-outline（红描边常驻提示），向导内「执行恢复」保持 btn-danger 实心——「入口提示 → 执行确认」两级高危视觉；与既有「次级样式」决策相反，以本变更为准（用户体验回归后落定）。
- **D5 created_local 双端修**：后端新包记裸 ISO8601（不再带时区注记），前端 `parseBackendDate` 兼容剥离存量注记后缀——存量包无需重做即可正常显示。
