# metrics-dashboard-ux-optimization 设计

## Context

评审基线：`docs/refactoring/metrics-dashboard-ux-review-2026-11-02.md`（19 项：4 高 / 7 中 / 8 低；含实测证据摘录）。页面为只读观测页（无危险操作），风险维度集中在数据可信与新鲜度感知。数据链路：ClickHouse（otel 表）→ `metrics_service` → `metrics.py` → 5 个前端组件。

约束：
- 前端日期/文件大小格式化只用 `utils/format.ts`（AGENTS #26）；组件语义变更前先 grep 消费方 + 断言反转清单，全量单测收口（#217）。
- `last_seen` 来自 ClickHouse `now()`（服务器时区），**不是**平台 naive-UTC 约定——不能直接套 `parseBackendDate` 的 UTC 解析，否则时区错位；故走 epoch（D4）。
- 数据源横幅为 prop 驱动、`source_ok===false` 才出现、恢复后随刷新周期自动消失（`metrics-source-status` 既有语义，勿改）。

## Goals / Non-Goals

**Goals**：页面每个数字可读、每种状态诚实（加载/空/错/陈旧四态可区分）、刷新口径全页一致、IA 有叙事。
**Non-Goals**：不改指标采集链路与 ClickHouse 查询口径（除 node-health 增列）；不加集群/节点筛选；不加图表坐标轴；不动指标查询页。

## Decisions

### D1 周对比修复 = 前端适配载荷（修 H1）

`TimeComparisonCard` 增加类型→字段映射：`day_over_day` 用 `today_requests/yesterday_requests`，`week_over_week` 用 `this_week_requests/last_week_requests`；`data_quality`/采样数同理映射。守卫改为按类型校验对应字段。
标签随类型切换：今日请求/昨日请求 ↔ 本周请求/上周请求；变化率后缀「较昨日」/「较上周」。
*备选「砍掉周对比选项」否决*：后端与 `time-comparison` spec（Weekly Comparison）均已交付，砍功能是倒退。

### D2 卡片三态机（修 M3/M4/M6）

每张指标卡统一状态优先级：**loading > error > empty > data**。

- **loading**：骨架占位（a-skeleton 或等高 shimmer），无文字；首载、切时间范围、单卡重试期间进入。时间范围切换不再清空后闪「当前无数据」（`setTimeRange` 清数据的现状行为随 loading 态自然消解）。
- **error**：文案归因两类——`source_ok === false` 时「数据源不可用，无法读取指标」（与横幅同语义，避免三种表述）；否则「加载失败」+ 文字按钮「重试」（仅重发本卡请求）。既有「数据加载失败」文案全页退役。
- **empty（语境化）**：流量类（HTTP 状态码分析、路由统计）「统计窗口内暂无请求」；上报类（QPS、连接状态、基础设施、节点健康、采集错误率）「暂无上报数据」。**QPS 归入上报类是实现期语义修正**：`edge_http_requests_total` 计数器在零流量下仍有采样（增量 0），空态只意味着采集端没有上报——与实机观测一致（route-stats 采样 1440、请求 0）。
- 扩展四卡注入 `sourceOk`（父组件传 store 值）：`source_ok === false` 时**不发请求**直接进 error 态，恢复后随刷新周期自动恢复（与横幅 5A 决策同语义）。附带收益：数据源断开时不再空发 4 个必败请求。

### D3 数值人性化（修 H3）

- 新增/复用 `utils/format.ts`：字节用既有 `formatFileSize`；速率（bytes/s）= `formatFileSize + '/s'`；百分比保留 2 位 + `%`；epoch 时间新增 `formatEpochDateTime`（`new Date(ts*1000)` 后按本地时区格式化，绕开 naive-UTC 解析）。
- `INFRA_CHARTS` 定义补 `unit: 'bytes'`（共享字典容量/剩余）；`MetricChartCard` 头部值按 unit 渲染。
- 采集耗时保留秒（值域小，无需换算）；采集样本数/新增序列整数 `toLocaleString`。

### D4 节点健康可读化（修 H2/M7）

- **状态列**：BadgeStatus 复用——`up=1` → `status="online"` 文案「正常」；`up=0` → `status="offline"` 文案「采集中断」。措辞裁决：「采集中断」而非「离线」——`up` 反映的是采集目标（exporter）无响应，不等于节点关机，「离线」会过度承诺。
- **最后上报**：后端 `_query_node_status` 的 SQL 改 `toUnixTimestamp(max(TimeUnix)) AS last_seen_ts`，响应新增 `last_seen_ts`（int 秒）；`last_seen` 字符串**保留**（兼容既有消费方/测试）。前端用 `formatEpochDateTime` 展示 + `formatRelativeTime` 附相对时间（「（3 分钟前）」）。
- **资源视图**：使用率列 = 进度条 + 「0.6%」；阈值色 <70% 常规蓝、70–85% 橙、>85% 红（复用 BadgeStatus 色板变量）；增列「容量」（formatFileSize）；`free_bytes` 收进 tooltip（列数控制）。
- **切换器文案**：「状态」→「在线状态」，「资源」→「字典内存」。
- **双请求修复**：删 `onTypeChange` 内手动 `loadData()`（`watch(currentType)` 已覆盖）。
- **刷新联动**：纳入 D6 全页刷新编排（现状首载后永不刷新）。

### D5 数据质量诚实化（修 H4）

- tag 保留 `完整/部分`（success/warning 色）但文本改「采样完整 / 采样部分」；tooltip：「今日已采样 {today}/{1440} 分钟。统计日未结束时会显示部分，属正常现象」（周对比用 {this_week}/{10080}、措辞换「本周」）。
- 卡内数据质量行下加弱色小字：`今日 501/1440 · 昨日 1440/1440`（后端已返回，零成本）。
- *备选「后端改判定（当日未结束不算 partial）」否决*：会把「真缺数据」也藏掉，诊断价值归零。

### D6 刷新一致性 + 新鲜度感知（修 M1/M2）

- 手动「刷新」与自动定时器统一走页面级刷新编排：业务图（既有 `loadAllCharts`）+ 扩展四卡 + 已展开的基础设施区。实现机制（store 编排 or 父组件 `defineExpose` 调子卡 reload）由实现定，spec 只钉行为。
- 基础设施**收起时不拉**（按需原则不变）；展开状态下跟随刷新周期。
- 控制区右侧新增弱色「更新于 HH:mm:ss」（store 记 `lastUpdated`，任一刷新周期完成即更新）。
- 扩展四卡的类型内切换（QPS→带宽等）仍为局部行为，不触发全页刷新。

### D7 IA 四分区重排（修 M5 组位、L1/L3）

```
§ 核心流量    QPS ｜ Nginx 连接状态            （2 列，齐）
§ 流量分析    路由统计（全宽）｜ HTTP 状态码分析 + 时间对比（2 列，齐）
§ 运行健康    节点健康 ｜ 采集错误率              （2 列，齐）
§ 更多指标    折叠 6 卡                          （不变）
```

- 「采集错误率」从业务格移入运行健康组：业务格从 3 卡变 2 卡（消除独占行），运行健康凑齐 2 卡（消除半行空白）；语义上「节点采集是否中断」与「采集错误率」同属链路健康。
- 分区标题：弱色 13px 小标题（非卡片、不占视觉重量），样式细节由 @designer 实现时定。
- **口径标注**：卡片标题右侧弱色小字，回答「这张卡受不受上面的时间范围控制」——路由统计/HTTP 状态码分析「近 1小时…近 7天」（随全局范围变）；时间对比「今日 vs 昨日 / 本周 vs 上周」（随卡内切换变）；节点健康「实时快照」；业务 sparkline 卡不标（全局控件就在页顶）。
- 连接状态卡头部值加「活跃」小字标注（修 M5，归入本决策一并实现）。

### D8 路由统计列打磨（修 L5）

「路由ID」列 220→120px + ellipsis + tooltip 全值；「未纳管」加 tooltip「该路由未在平台纳管，可能由 Edge 侧直接创建」；带宽/总流量 `formatFileSize`；错误率值带 %；延迟值带 ms；QPS 值保留 ≤3 位小数（列头 QPS 已含单位语义）。

### D9 基础设施折叠条 button 语义（修 L6）

`div @click` → `<button type="button">`（保留样式），键盘可达；「(6 项)」对比度随实现微调。两行级改动，顺带做。

### D10 范围裁剪（P2 不做，留待办）

- **坐标轴/时间刻度**：保持 sparkline 极简——160px 卡高加轴会挤压图形且 10+ 卡同屏噪音翻倍；tooltip 已有精确值。24h/7d 加稀疏刻度列为后续可选项。
- **变化率红涨绿跌**：流量涨跌无善恶，保持现状仅加 tooltip「请求量较昨日上升/下降 X%」。
- **指标查询互链**：需先核查查询页是否支持 URL 预填指标名，另行立项。
- **集群/节点筛选**：多集群聚合口径下的下钻能力，独立立项。
- **主 spec 菜单场景漂移**（旧「指标监控/仪表盘」措辞）：不属本变更行为范围，归档合并时单独同步。

## 状态展示设计

**每张指标卡的状态机**（`MetricChartCard` 与四扩展卡统一语义，各自实现）：

```
[请求中] loading ──成功──▶ data
   │  \──失败──▶ error（source_ok=false → 「数据源不可用，无法读取指标」
   │                              其他 → 「加载失败」＋「重试」）
   └──成功但空──▶ empty（流量类「统计窗口内暂无请求」／上报类「暂无上报数据」）
重试：仅重发本卡请求；时间范围/类型切换回到 loading
```

**页面级状态**：
- 数据源不可用：横幅（既有）＋ 全部指标卡 error 态统一文案（扩展卡此时不发请求）。
- 新鲜度：控制区「更新于 HH:mm:ss」；自动刷新开/关不改变文案位置。
- 节点健康行内状态：正常（绿点）/ 采集中断（红点）；排序保持「异常在前」（后端既有）。

## Risks / Trade-offs

- **`MetricChartCard` 组件语义变更**：实现前必须 grep 全部消费方与既有断言、产出断言反转清单（#217）；已知直接消费方为 `MetricsDashboard.vue`，如有其他消费方（如概览页复用）需一并评估。
- **`last_seen_ts` 新字段**：`last_seen` 字符串保留，向后兼容；前端切换为 epoch 后老字段仅作兜底。
- **刷新编排改 store**：`metricsDashboard.test.ts` 既有断言（单飞守卫、清空行为）需反转/扩展；扩展卡 reload 与业务刷新并发发出约 +5 个请求/周期，采集端（ClickHouse）压力可控（原自动刷新本就每 60s 发 7 个请求）。
- **loading 骨架与「清空重载」**：`setTimeRange` 清空 `chartDataMap` 的现状在 loading 态下用户不可见，保留清空（内存释放）不保留旧图（口径已变，显示旧数据反而误导）。
