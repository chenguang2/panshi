# Design: DB Migration UX Optimization

## Context

迁移模块现状（评审实据 2026-10-31）：迁移发起 = 「我了解将清空目标库」勾选框 + 点击直发（`DbMigrationCard.vue`）；「终止迁移」仅 abort 客户端 SSE（L759-767），后端断连路径注释明确 Do NOT cancel（`database.py` L609-614），cancel_event 仅超时路径置位；G8（禁止迁入活动库）仅后端 400（`db_migration_service.py` L97-102）；历史接口已返回 `error_message`/`backup_path`（`database.py` L81/L99/L472-478）但历史表 7 列不展示；`DatabaseManagement.vue` 写操作零 try-catch；`maintenance.py` L51 `started_at=datetime.now()` 违反站内 naive UTC 约定（AGENTS.md #26）；503 锁文案「正在迁移数据库，暂时禁止写操作，请稍后重试」无出口。

既有约束：迁移 SSE 单实现（AGENTS.md #33 收尾规范）；后端时间列 naive UTC（#26）；共享流程单一实现精神（#7，SwitchConnectionModal 据此组件化）；TDD（#16）；替换模式为唯一语义（merge 已下线返回 400）。

主规格存在两处漂移，本次随需求修订一并裁决（详见 specs delta 内 HTML 注释）：① `migration-progress-stream`「断连→协作式取消」vs 代码「断连不取消」；② `database-management` B1 需求场景 1「先备份目标库」vs 场景 6「备份源库」，代码实据 `db_archive_service.export_archive(source, …)` 裁决为源库。

## Goals / Non-Goals

**Goals:**
- 消灭「无确认直发清空目标库」的唯一危险路径（确认弹窗）
- 高危约束前置表达（G8 下拉禁用、活动库预选源、空态闭环）
- 失败可排障：失败原因与备份路径离开迁移页即可见
- 全部文案与真实语义一致（断开监视、备份源库、10 份保留、写锁出口）
- 锁状态全局可感知（App 层横幅，事件驱动零轮询）
- DatabaseManagement 写操作失败必上屏；表单必填校验前置
- 迁移完成到切换生效的动线缩短（10 步 → 6 步，见下文流程对比）

**Non-Goals:**
- 真取消（后端 cancel 端点 + 目标库清理语义）——用户决策 2026-10-31 留待未来变更
- P2 项：「从迁移备份导入」入口（`POST /database/import` 后端已就绪、前端零消费）、运行耗时计时器、静态资源提示折叠
- 「保存并测试」合并按钮、摘要卡四格去重、历史表「查看操作日志」链接（列入后续变更候选）
- 后端迁移引擎/SSE 事件格式/权限键/数据模型变更（零后端端点新增）
- `/backup-management` 备份页的全面 UX 评审（仅评审与迁移的衔接）

## Decisions

### D1 终止语义：诚实化「断开实时进度」（用户决策 2026-10-31）
按钮改名 + 文案如实（后台继续、写锁保持、轮询恢复）；移除永不命中的 `cancelled → 已取消` 映射。**备选**「后端补 cancel 端点真取消」被否：需定义目标库已写数据的清理语义（回滚 or 保留待覆盖）、线程有界等待、并发窗口处理，成本与风险显著高于本轮范围。

### D2 确认弹窗替代勾选框直发
弹窗要素：源/目标标识与地址、清空覆盖警告（空库降级为中性说明）、自动备份**源库** + 保留最近 10 份说明、写锁影响、超时摘要；确认按钮 danger 样式。含 `include_logs` 勾选保留在表单（不属于危险确认）。**备选**「保留勾选框、仅加二次弹窗」被否：双重确认徒增步骤，且勾选框文案「先备份再替换」的备份对象表述（目标库口径错误的历史遗留）一并消除。

### D3 G8 前置 + 源预选
目标下拉禁用活动库选项（标注「当前活动库，不可作为目标」），源下拉默认预选活动库（标注「当前」），联动 `GET /database/status`。后端 400 保留为最终防线（与「删除激活连接」同款前端前置模式）。消灭「选了活动库 → 提交 → 400 → 重选」试错循环。

### D4 历史行展开而非加列
`a-table` `expandable` 行展开承载 `error_message`（失败样式段落 + 中文分类转译）与 `backup_path`（等宽 + 复制）。**备选**「加两列」被否：7 列已满宽，且失败原因长文本会撑爆行高（客户端分页行高一致性约束，AGENTS.md #54）。

### D5 全局锁横幅：503 事件驱动，零轮询
axios 拦截器识别 503 + 锁标记 → 拉起 App 层横幅 + 一次性 `running-tasks` 拉取填充源→目标与进度入口；后续写请求成功或刷新时无锁则移除。**备选**「App 层定时轮询 running-tasks」被否：全站用户为极低频的迁移窗口付出常驻轮询成本，违反最小惊扰。

### D6 `SwitchConnectionModal` 共享组件
现有切换确认弹窗（`DatabaseManagement.vue` L192-222）提升为共享组件，迁移页结果条「去切换」原页弹窗预选目标连接；切换成功即时展示重启指引横幅（复用既有待重启指引文案，质量已达标）。对齐 #7「共享流程单一实现」精神。消灭「迁移页 → 跳列表页 → 找连接 → 再确认」的纯导航浪费。

### D7 `maintenance.started_at` 修正 naive UTC
`datetime.now()` → `datetime.utcnow()`（#26）。注意该字段仅用于锁状态展示与 running-tasks，无持久化列，无存量数据迁移问题。

### D8 错误反馈统一模式
DatabaseManagement 全部写操作包 try-catch：后端 detail（400/422/503）直出中文；503 锁响应追加出口指引；网络错误给「网络异常，请检查连接后重试」。必填校验前置（PG 主机/数据库名），空值不提交。

### D9 迁移卡两栏布局 + 状态带组件化
横排 7 元素（源卡/箭头/目标卡/模式/超时/双勾选/按钮）改两栏：左 = 流向表单，右 = 固定风险说明面板（替换语义、备份与保留、写锁影响）；移除卡片内 h3（与 PageHeader 双标题）；补 `@media` 断点修复窄屏溢出（现状 `flex-shrink:0` 无断点）。状态带（活动库/待重启/锁态）组件化供迁移页使用，数据源复用既有 status/running-tasks 接口。模式下拉移除，替换语义以危险标签陈述。

## 交互流程对比（首次迁移全链路）

| 现状（10 步 + 重启） | 建议（6 步 + 重启） |
|---|---|
| 1. 进迁移页 | 1. 进迁移页（摘要卡直达，已有） |
| 2. 选源 | 2. 选源（活动库已预选） |
| 3. 选目标（可能撞 G8 试错） | 3. 选目标（活动库已禁用，无试错） |
| 4. 勾「我了解将清空目标库」 | 4. 点「开始迁移」→ 确认弹窗一次完成知情与确认 |
| 5. 点开始（**立即执行**） | 5. 完成后「去切换」→ 原页弹切换确认（预选目标） |
| 6. 完成 | 6. 确认切换 → 重启指引横幅 |
| 7. 点「去切换」（仅跳转列表页） | — |
| 8. 在连接列表找目标连接 | — |
| 9. 设为当前 → 确认弹窗 | — |
| 10. 手动重启（指引需自行回忆） | — |

依据：现状第 7-8 步是纯导航浪费（`DbMigrationPage.vue` L32-34 忽略卡片已发出的目标连接对象直接 `router.push`）；「开始迁移即执行」与站内删除/发布均走确认弹窗的惯例不一致，也与同域恢复向导「高危确认与执行」独立步骤模式不一致。

## 状态展示设计

1. **连接状态**：`unverified 未验证` / `ok 已验证连通` / `fail 验证失败`（圆点升级为文字 tag，title 保留细节并披露「仅保留到页面刷新」）；正交维度：`active 当前`、`pending_restart 待重启生效`（黄徽章，现状保留）
2. **迁移任务态**：`idle` → `备份中(backup_progress)` → `迁移中(table i/N、当前表、行数)` → `success / failed（含原因）`；断开后由轮询态代偿展示「后台执行中」。载具：页内锁横幅 + 进度条（现状结构正确）+ 状态带 + 历史行展开
3. **写锁态**：`unlocked` / `locked(源→目标, started_at)`；载具：迁移页状态带 + App 层全局横幅（D5）
4. **切换生效态**：`synced` / `pending_restart`；载具：数据库管理顶部卡（现状质量好，保留）+ 状态带复用组件

## Risks / Trade-offs

- [视觉层结论未经实图验证（评审时前后端服务未运行，0 截图）] → 实施首任务补三页截图复核问题严重度与布局改造必要性；溢出/密度结论以截图为准修正
- [移除勾选框/模式下拉会破坏既有组件测试] → `DbMigrationCard.test.ts` 勾选框相关用例随交互改造同步改写（TDD 先行：新确认弹窗用例先红后绿）
- [全局横幅由 503 拦截器触发，非锁来源页面首次渲染不知道锁存在] → 接受（横幅定位是「解释写失败」，无写失败则无需横幅）；刷新后无锁感由迁移页状态带兜底
- [Vue 模板内多语句被 prettier 重排导致编译错（#25 教训，vue-tsc -b 不报）] → 弹窗/横幅 handler 一律提取为 script 函数；挂载类 vitest 全量跑
- [503 文案变更可能影响断言旧文案的既有后端测试] → 改语义后按 #51 跑 `pytest -k "database or migration or maintenance"` 全域回归
- [微库亚秒级迁移下「断开实时进度」的边缘措辞] → 断开若落在备份阶段（真实数据量下占比可忽略），迁移实际未开始，「迁移在后台继续执行」措辞在该亚秒窗口不精确；历史仍如实记「迁移中断」。实测（2026-10-31）：22 表微库全程 ~1s，E2E 已按双真实终态（成功/迁移中断）断言；真实规模库不受影响
- [确认弹窗内展示目标库表数/空库判定需额外查询] → 修正：`target_is_empty` 并无端点暴露（评审阶段误判），空目标降级以保守恒显警告落地，降级分支接入缝已预留（specs delta 已按此修订）；表数摘要列为增强项，不阻塞

## Open Questions

- `db_migration` 与 `database_management` 权限是否授予不同人群？（决定 `/db-migration` 页挂 `GET /status`+`/connections` 的 403 是否为真实场景；当前实现按同权限处理）
- 目标 PG 的典型库规模？（校准确认弹窗是否需要表数摘要与超时档位适用性）
- 迁移运行期间其他域写操作的实际体验录屏？（校准全局横幅优先级与文案密度）——可用 test 集群实测补齐
- 用户角色是否有权登录服务器执行重启？（决定切换后指引是否需升级为运维工单式引导）
