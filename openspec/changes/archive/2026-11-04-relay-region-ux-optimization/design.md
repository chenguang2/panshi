# Design: relay-region-ux-optimization

## Context

页面现状（2026-11-03 实机 + 代码勘察）：2 区域（areatest/kjc）各 8 个行内操作按钮 wrap 两行；连通性测试走 `relayHealthCheck(code)` 单区域端点，结果以 `message.success/warning` 多行 toast 呈现（约 3 秒消失，实测 8 秒后无痕）；无持久健康状态列；表单仅 code 有 inline 校验，三个路径字段无格式校验（后端 `strip_path_fields` 仅去空白）；`busy` computed 全局禁用所有行所有按钮；`GET /relay/health-check` 无参调用返回 `{regions: RelayHealthResult[]}`（`check_all`）——前端未消费。

既有资产（复用，不新造）：
- `check_all` / `check_region`（`relay_health.check_region/check_all`，已按「串行读库 → commit → 并发纯网络探测」拆分，AGENTS #29）
- `NodeExecutionResultDrawer` + `useInstallStream`（执行抽屉，SSE）
- `showOverlayModal`（确认弹窗，约定 #25）
- 既有测试 `RelayGateways.test.ts` 11 用例覆盖全部既有流程（改动须过 #217 断言普查）

## Goals / Non-Goals

- **Goals**：健康状态可见可回看；一键全量体检；表单坏值在提交前被拦住；操作层级清晰（高频直达、危险收纳）；文案去绕。
- **Non-Goals**：不做健康自动轮询（网关探测是真实网络 IO，页面常开时周期探测开销与打扰不成比例——手动触发 + 持久展示已够）；不改通道寻址/配置渲染/ansible 执行路径；不做执行历史列表（执行日志已在抽屉内有终态，历史留待执行中心统一立项）；不动 `relay_gateways` 表结构。

## Decisions

### D1 一键全量体检（复用无参 health-check，零后端）
页头「+ 新建区域」旁新增次级按钮「全量体检」：调 `relayHealthCheck()`（无参 → `check_all`），完成后逐行更新健康状态列 + 打开结果弹窗汇总。单区域「连通性测试」按钮保留，走原单区域端点。加载态按钮文案「体检中…」（探测预算 60s，`RELAY_LONG_TIMEOUT` 180s 已有）。

### D2 健康状态列（持久、可回看）
状态列扩展为双行：第一行 `启用/禁用` badge + 清单缺组 tag（既有）；第二行健康态：`✓ 正常`（绿）/ `✗ HTTP 腿不可达` 等**首失败段摘要**（红）/ `未检测`（灰）+ 体检时间（`formatDateTime`，#26 工具）。结果存组件 state（不落库——体检是只读探测，持久化历史属执行中心范畴；刷新页面后显示「未检测」，可接受）。失败摘要 tooltip 展示全部分段明细。

### D3 体检结果弹窗（替代 toast）
新增「体检结果」弹窗（视图级内联弹窗，约定 #25 视图级例外）：标题带区域名/区域数，body 按 segment 逐条渲染（名称 + ✓/✗ + 耗时 + error + 节点 ssh_skipped note 缩进），底部「复制结果」。单区域与全量共用同一弹窗（全量按区域分组）。`message` 仅保留终态一行提示（成功/异常）。

### D4 表单格式校验（前端 inline + 后端 validator 双层）
| 字段 | 规则 | 错误文案（inline / 400） |
| --- | --- | --- |
| `http_base_url` | `^https?://[A-Za-z0-9.\-]+(:\d{1,5})?$`（host 段含 IPv4/域名；不带路径） | 「网关 HTTP 腿格式错误：须以 http:// 或 https:// 开头，如 http://10.10.1.1:8443」 |
| `ssh_jump` | `^[A-Za-z0-9._\-]+@[A-Za-z0-9.\-]+(:\d{1,5})?$` | 「SSH 跳板格式错误：须为 账号@主机[:端口]，如 tunnel@10.10.1.1:22」 |
| `openresty_prefix` | 以 `/` 开头的绝对路径 | 「OpenResty 前缀格式错误：须为绝对路径，如 /work/jboss/tunnel/openresty-1.21.4.1/nginx」 |

后端 `RelayGatewayCreate`/`RelayGatewayUpdate` 各加 `@field_validator`（复用同一 pattern 常量，与 strip 校验并存：先 strip 后格式校验）；前端提交前校验（inline error，同 code 风格），400 时 `getApiErrorMessage` 兜底。校验是**硬失败**（阻断提交）——坏配置的代价（init 静默失败/探测误报）远大于填写成本；存量坏值不受影响（仅提交时校验）。展示名错误从 `message.error` 改 inline error（与 code 一致）。

### D5 操作收纳（行内 3 + 更多下拉）
行内保留：`编辑`、`连通性测试`、`下发配置`（主操作，primary）。`更多 ▾` 下拉（a-dropdown）：`初始化网关`、`配置跳板转发`、`查看配置`、`启用/禁用`（随状态切换）、分隔线、`删除`（红色）。动作列宽 400 → 240。理由：初始化（首次装机一次性）、跳板（一次性安全加固）、删除均为低频操作；下拉项内文案与现有一致，不新增术语。

### D6 busy 粒度（裁决点，推荐行级）
现状 `busy` 全局禁用所有行所有按钮；后端 `_INFLIGHT` 按 `region_code` 守卫（跨区域并行后端本就允许）。改为：执行中的行整体禁用 + 行内按钮文案带进度；其他行仅禁用同名操作？——**推荐：行级禁用**（activeId 匹配行禁用，跨区域操作可用），与后端并发语义对齐；保守备选：维持全局禁用（心智简单，但多区域场景体验差）。

### D7 文案
| 位置 | 现文案 | 改为 |
| --- | --- | --- |
| 页头 description | 三句技术长文（HTTP 腿/SSH 跳板/初始化/下发指引） | 「维护各局中继网关注册信息：配置网关地址与 SSH 跳板后，该局节点的管理与数据通道将经由网关中转；未配置区域的集群按直连执行。」 |
| 空态 | 「暂无区域。未配置任何区域时，全部集群按现状直连执行。」 | 保留 + 追加引导「点击右上角「新建区域」开始；首次装机流程：新建区域 → 初始化网关 → 集群挂接区域 → 下发配置。」 |
| 禁用确认 | 「禁用后「X」的节点将回退直连执行（直连通常不可达，操作会失败并附提示）。确认禁用？」 | 「禁用后「X」区域的节点不再经网关中转，将按直连路径执行（跨中心场景通常不可达，相关操作会失败）。确认禁用？」 |
| 删除确认 | 保留 | 保留（已含挂接拒绝说明） |
| sshd 弹窗提示 | 既有两段 | 追加一句「若网关 sshd 不接受端口白名单格式（部分系统如 LinxOS），将自动降级为仅放行转发并回显原因；校验失败会自动回滚。」 |

### D8 列与信息
表格追加「更新时间」列（`updated_at` 已返回未展示，`formatDateTime` #26）；列序：区域码 / 展示名 / 网关 HTTP 腿 / SSH 跳板 / OpenResty 前缀 / 状态（含健康态）/ 更新时间 / 操作。全列 `white-space: nowrap` 保持，超宽横向滚动可接受（区域数量个位数）。

## Risks / Trade-offs

- 健康状态为组件态、刷新即失（不落库）——接受：体检是时点探测，落库反而制造「状态正确性」错觉；列上保留体检时间明示时点。
- 全量体检在区域多、链路慢时可达 60s——按钮加载态 + 可关弹窗（关闭不中断探测，完成后状态列仍更新）。
- 下拉收纳多一步点击才能到初始化/跳板——低频操作可接受；高频三项直达不变。
- 行级 busy 若两个区域同时执行，两个执行抽屉互踩（单抽屉单流）——**行级方案下同时只允许一个执行流**（第二行点击时若 `execInstalling` 仍整体禁用其它行的 init/push/sshd 流式操作，仅放行非流式操作：编辑/测试/预览/删除/启停）。即：**流式操作全局串行（单抽屉约束），非流式操作行级并行**——这是 D6 的精确语义。

## Open Questions

1. busy 粒度按 D6 推荐语义（流式全局串行 + 非流式行级并行）？备选：维持现状全局禁用。
2. 体检结果是否需要保留最近 N 次历史（组件态 vs 落库）？推荐不做（见 Non-Goals）。
3. 后端格式校验是 400 硬失败（推荐）还是仅告警放行？
