## 2. 信息架构（不变式 + 调整点）

页面骨架「页头动作区 → 筛选条 → 表格 → 分页」不动。调整：
1. **筛选条**：`[搜索(a-input-search)] [角色▾a-select] [状态▾a-select] | 共 X 个用户`。
2. **状态列**：`BadgeStatus` 静态徽章 → `a-switch`（内联文案「启用/禁用」），点击即确认流程。
3. **操作列**：`编辑` + `⋯`（只留「删除」）。

## 5. 争议点备选方案（推荐 A，待用户裁决）

1. **假排序**：A✅ 移除列头 sorter（后端无 order 参数，与 audit-log-ui 裁决同型）；B 后端加 order 参数（用户数基数小，排序价值低）。
2. **状态切换形态**：A✅ 状态列显式 a-switch + 确认弹窗（状态与操作合一、禁用语义前置）；B 保留 ⋯ dropdown + 确认弹窗（少改，但高频操作仍两次点击）。
3. **集群 picker**：A✅ 暂存态（打开快照/确认应用/取消还原）——「取消」诚实；B 去掉「取消」只留「完成」（无反悔，误触代价高）。
4. **重置密码**：A✅ 二次确认弹窗；B 保持直接执行（高危不可接受）。
5. **角色切换权限**：A✅ 保留勾选（admin 时隐藏权限区但内存保留，切回恢复；保存时 admin 不提交权限，无副作用）；B 清空前弹确认（多一次打断）。

## 6. 交互流程

**禁用/启用（批 2）**：开关点击 → 确认弹窗（语义文案）→ 确认调 `PUT /users/{id}` → 成功 toast + 列表原地刷新；取消 → 开关回弹（以 record.status 回填，不发请求）。

**集群 picker（批 3）**：`+ 选择集群` → 打开时 `pickerDraft = [...selectedClusterIds]` → 勾选改 draft → 「确认」`selectedClusterIds = draft` 关闭；「取消」直接关闭（draft 丢弃）。表单层仍以 `selectedClusterIds` 为真值，保存时统一提交。

**角色切换（批 3）**：`onRoleChange` 不再清空 `selectedPermKeys`；权限区以 `v-if="formState.role !== 'admin'"` 隐藏但状态保留（Vue v-if 销毁的是 DOM，`selectedPermKeys` 是组件级 ref 不受影响——现状清空是显式代码，删掉即可）。

**重置密码（批 3）**：输入新密码（≥6 位校验不变）→「重置」→ 确认弹窗 → 确认调 `PUT /users/{id}/password` → 成功清空输入框 + toast。

**编辑保存（批 3）**：update 成功后 permissions/clusters 各自 try/catch，失败用分步定位文案，不再整体吞成「操作失败」。

## 7. 状态展示规范

- **状态列**：a-switch（checkedChildren「启」/unCheckedChildren「禁」，或纯开关 + aria-label）——启用 = 开、禁用 = 关；切换中 loading 态由确认后请求期间锁定。
- **角色徽章**：保持 admin 蓝系 / user 绿系（低优不动）。
- **权限/集群标签**：3 个 +N 截断与 tooltip 保持（主 spec 既有 requirement）。
- **危险确认弹窗**：手写 modal-overlay 同款三弹窗结构（全站 Modal.confirm 已清零——约定 #25），danger 主按钮 + 后果说明段。
