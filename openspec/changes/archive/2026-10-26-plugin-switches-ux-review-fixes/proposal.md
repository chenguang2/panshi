# proposal: plugin-switches-ux-review-fixes

## Why

用户以标准评审简报要求对插件开关模块做体验评审（易用性/易理解/美观层级/安全风险四维），输出 openspec 需求文档，批准前不动代码。证据链：PluginSwitches.vue 全文走读、plugin_switches.py 契约核验、真实页面 Playwright 交互走查（默认页/未保存态/保存警告弹窗/离开守卫 5 张截图，test 环境实测后已还原 13/13）。

**关键语义实锤（影响全部风险文案与警告强度）**：`PluginEnabled` 仅被 `GET /plugins/builtin` 的清单过滤消费——**禁用插件 = 从全站插件可选清单移除；既有引用（路由插件/插件组/全局规则）不受影响、继续随发布生效**。发布链（edge_sync）不查该表。因此「引用警告」是可选性提示而非故障告警，当前文案「但仍有配置引用」未说明后果、未给动作，且只在保存后才出现。

## 问题清单

### P1（安全与信任）

1. **保存模型不可感知**：toggle 即时变色像「已生效」，实际需滚动到页底点「保存配置」；「有未保存的更改」为 12px 灰字且位于视口外（截图 61 实证）。误判已生效属信任级缺陷。
2. **「全部禁用」一键全灭无确认**：一次点击将全部插件标记禁用（再保存即全站可选清单清空），无二次确认、无影响说明；且「全部启用/禁用」只改本地态，与两段式保存叠加加重误解。
3. **引用影响后置且无动作**：禁用被引用插件仅在保存后弹「插件引用警告」（截图 62：`traffic_limit_count：路由: 2 个`），不解释后果（引用照常生效，仅新配置不可选）、无「查看引用/还原该插件」动作。后端引用扫描能力已在（`_detect_plugin_refs`），完全可以前移到保存前。
4. **无放弃更改途径**：手滑后只能逐个拨回；离开守卫仅 取消/离开（无「保存并离开」）；刷新/关闭标签页无 beforeunload 守卫（`onBeforeRouteLeave` 只覆盖路由内导航）。

### P2（易理解/易用）

5. **面包屑错误（批 9 遗留缺陷）**：面包屑仍显示「系统管理 / 插件开关」，菜单已迁核心功能（截图 60 实证）。
6. **「插件版本」名不副实**：卡片 footer 的 version 位显示的是 `plugin_name`（技术名）而非版本。
7. **三行过滤区信息重复**：状态条「已启用 13 / 13 个插件」与过滤条「共 13 个插件」双计数并存，形态不一。
8. **保存成功强模态打断**：无警告时也弹「保存成功/知道了」模态，低价值高打断。
9. **术语**：header「查看插件配置 schema」、卡片「⚙ schema」——对运维用户偏术语；无中文解释。
10. **禁用态语义模糊**：整卡 opacity 0.55 连名称都变淡（禁用≠不可读）；「未保存的禁用」与「已保存的禁用」视觉无区分。

### P3（一致性/打磨）

11. 自定义 CSS toggle 是全站第三种开关样式（`a-switch` 已在 MetricsDashboard/AnsibleAdvancedFields 使用）。
12. 空 schema 卡 footer 单边失衡（仅技术名，无右侧配平元素）。
13. 无操作痕迹入口：PUT 已入审计（ROUTE_MAP），页面不提供「查看操作日志」链接（数据安全类产品维度 4）。

## Goals

- 保存意图显式化：改动未保存这件事在任何滚动位置都可见、可放弃、可救（保存并离开）
- 引用影响前移：切换前即可见引用计数；警告必须解释后果并给动作
- 批量操作有闸门：全部禁用/启用需确认并列影响
- 术语与状态诚实：技术名标签化、schema 中文化、禁用态可读且区分已存/未存

## Non-goals

- 不改保存契约（PUT 全量替换语义保留）与权限门控（plugin_management）
- 不做逐插件即时保存（写放大 + 破坏引用批量扫描的一次性语义，见 design 取舍）
- 不做插件级操作日志新表（复用既有 sys_audit_log 查询页，仅加入口）

## 分批

- **批 1（保存模型 + 风险闸门）**：sticky 保存条（未保存计数/放弃/保存）、beforeunload、全部禁用/启用确认弹窗、保存成功 toast 化、离开守卫加「保存并离开」
- **批 2（引用感知前移）**：GET /plugin-switches 响应带每插件引用计数（复用 `_detect_plugin_refs` 扫描）；卡片「被引用：路由 2」徽标；禁用被引用插件时行内即时警示；警告弹窗升级（后果解释 + 引用清单 + 还原动作）
- **批 3（文案与一致性）**：面包屑修复、术语表落地（schema→配置结构、技术名标签）、a-switch 统一、禁用态样式、双计数合并、审计入口

## 需补充（已确认）

- **角色**：`plugin_management` 实际仅授予管理员——全部文案口吻按「管理员」表达（确认弹窗、警告弹窗、header 说明），不考虑普通运维视角措辞。

## 决策点（待用户裁决）


1. 保存模型：A sticky 保存条（推荐）/ B 逐插件即时保存
2. 引用计数前移：A GET 带计数 + 卡片徽标 + 行内警示（推荐，动后端 GET）/ B 仅前端文案提示
3. 全部禁用/启用：A 确认弹窗列影响（推荐）/ B 保持现状
4. schema 术语：A 改「配置结构」+ 悬浮说明（推荐）/ B 维持 schema
5. 面包屑修复：A 本变更批 3 顺手修（推荐）/ B 另立变更
