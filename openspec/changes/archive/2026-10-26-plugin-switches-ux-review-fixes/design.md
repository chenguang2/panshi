# design: plugin-switches-ux-review-fixes

## 关键语义（文案与交互的依据）

`PluginEnabled` 表仅被 `GET /plugins/builtin`（不带 all=1）消费：禁用插件 = 从全站插件可选清单移除；**既有引用继续存在且随发布照常生效**（edge_sync 不查该表）。据此：

- 引用警告的正确文案是「以下插件已从可选清单移除；既有配置中的引用将继续生效」——不是故障
- 警告的价值在「让用户知道引用还在哪」，动作应是「查看引用」而非恐慌性回滚
- 「全部禁用」的后果是「新配置无插件可选」，严重但可逆——确认弹窗强度中等即可（列影响 + 需保存）

## 决策记录

### D0 角色口诀（用户确认）

`plugin_management` 实际仅授予管理员——确认弹窗、警告弹窗、header 说明一律按「管理员」口吻表达。

### D1 保存模型 = sticky 保存条（决策点 1A，用户批准后生效）

- 出现条件：`hasUnsavedChanges`；固定视口底部右侧；内容 = 「N 项未保存」+ 放弃更改 + 保存配置
- 放弃更改 = 还原 `originalPlugins` 快照（已有数据结构，零新接口）
- `beforeunload` 补浏览器级守卫（与 onBeforeRouteLeave 并存）
- 离开守卫三选项：取消 / 离开（放弃）/ 保存并离开（复用 saveSwitches 后 next(true)）
- 否决 B（逐插件即时保存）：每次 toggle 一次 PUT 全量替换 28 行，写放大；且引用扫描退化为逐次扫描、批量调整（全部启用）语义破碎
- 保存成功反馈降为 `message.success('已保存')`；仅引用警告保留模态（D3）

### D2 引用计数前移（决策点 2A）

- 后端：GET /plugin-switches 响应每项增加 `refs: {routes, plugin_configs, global_rules}`——实现为把 `_detect_plugin_refs` 的扫描改为对「当前禁用集合 ∪ 本次将展示的全部插件」跑一遍？不：GET 语义应为「该插件**若禁用**将影响的引用数」，对全部 builtin 插件扫描成本 = 3 组查询（RoutePlugin 按 name 分组计数 / PluginConfig、GlobalRule 各一次全表 JSON 扫描），13 插件 × 低频管理页，可接受；抽取 `_count_plugin_refs(all_names, db) -> dict[name, refs]` 供 GET 使用（`_detect_plugin_refs` 保留给 PUT，或统一收敛为单实现 + 两个包装）
- 前端：卡片 footer 徽标 `被引用 路由 2`（refs 全 0 则不显示）；toggle 关且 refs 非空 → 卡片内行内警示条「该插件仍被 2 处引用，禁用后新配置不可选，既有配置不受影响」
- 警告弹窗升级：标题「插件已从可选清单移除」；正文按插件列出引用计数；每个插件行加「查看引用」（跳转对应列表页带搜索词）+ 顶部「还原被引用插件」快捷动作（把 refs 非空且本次被禁用的插件拨回 enabled，回到未保存态）

### D3 批量操作闸门（决策点 3A）

- 全部禁用：确认弹窗「将把全部 N 个插件标记为禁用（需再点击保存生效）。禁用后新配置将无法选择任何插件」+ 取消/继续标记
- 全部启用：轻确认（message.confirm 级）——正向操作风险低
- 均只改本地态，文案必须带「需保存生效」

### D4 术语与状态（决策点 4A + P2 修复）

| 现状 | 改为 | 位置 |
|---|---|---|
| 管理内置插件的启用/禁用状态，查看插件配置 schema | 控制各插件在新配置中的可选性；禁用不影响既有配置 | PageHeader description |
| ⚙ schema | ⚙ 配置结构（hover：插件参数定义，只读） | 卡片 footer |
| plugin-version 位显示 plugin_name | 标签改为「技术名」前缀样式（mono 弱色保留，去除版本语义） | 卡片 footer |
| 以下插件已被禁用，但仍有配置引用 | 以下插件已从可选清单移除；既有配置中的引用将继续生效 | 警告弹窗 |
| 有未保存的更改 | N 项未保存 | sticky 保存条 |
| 插件引用警告（弹窗标题） | 插件已从可选清单移除 | 警告弹窗 |

- 禁用态：卡片仅标题行微淡（opacity 0.75）+ 描述保持可读；「未保存」的禁用加虚线边框 + toggle 旁小圆点（与已保存禁用区分）
- 开关控件统一 `a-switch`（size small），删除自定义 toggle CSS（全站第三种开关样式收敛）
- 双计数合并：状态条保留「已启用 X / N 个插件」，删除过滤条「共 N 个插件」
- 空 schema 卡 footer 配平：无配置结构时显示「无参数」弱文本（占位平衡，不再单边）

### D5 面包屑修复（P2-5，缺陷非决策）

- 排查面包屑数据源（路由 meta.breadcrumb 或派生组件），与批 9 菜单结构对齐为「核心功能 / 插件开关」；回归断言进 AppSidebar/布局测试

### D6 审计入口（P3-13）

- PageHeader 右侧加「操作日志」次级链接 → `/audit-log`（既有查询页，按 path 过滤提示由用户自行操作；不做深度集成）
