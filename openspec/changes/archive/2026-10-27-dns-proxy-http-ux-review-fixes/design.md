# design: dns-proxy-http-ux-review-fixes

## 关键语义

- DNS 代理路由 = 带 `dns_upstream` 插件的 HTTP 路由；URI 是 DoH 流量入口路径（约定 `/dns-query`），对典型用户是一次性配置——**不构成卡片间的区分度**，域名列才是
- 健康检查结构：`{type: "https", active: {...}, passive: {...}}`；`type` 是协议选择（http/https），active/passive 是 APISIX 风格检查配置（复杂、低频改动）——半结构化可覆盖 90% 场景
- 创建两步写（POST route + PUT plugins）无后端组合端点；前端补偿回滚即可保证「失败即无痕」（与 cluster-backup-restore-fix 的失败无副作用哲学一致）

## 决策记录

### D1 健康检查 = 半结构化（决策点 1A，待批）

- `type`：下拉（http / https，默认 https）
- `active` / `passive`：两个折叠区（默认收起，标题「主动检查（高级）/ 被动检查（高级）」），各自 JSON 文本框保留（该层结构复杂、低频，结构化收益低）——但提交前 `JSON.parse` 校验失败 SHALL 阻止提交并在框下报错「JSON 格式不合法：{原因}」，MUST NOT 静默替换
- 勾选「健康检查」= 启用；取消勾选 = 不写 checks 字段（与现状一致）
- 兼容还原：存量配置 `checks.type` → 下拉选中；缺 type 显示 http 默认；active/passive JSON 原样还原

### D2 保存原子性（决策点 5A）

- **创建**：POST 成功 + PUT plugins 失败 → 自动 `DELETE /clusters/{cid}/routes/{id}` 补偿删除 → 报错「保存失败：路由已回滚（原因）。请重试」→ 列表刷新后无残留
- **编辑**：PUT route 成功 + PUT plugins 失败 → 不回滚（基础信息合法变更保留），message 改为分步说明弹窗/toast：「路由基础信息已保存，但域名配置保存失败：{原因}。可重试保存域名配置」→ 提供「重试保存」动作（仅重发 PUT plugins）
- 补偿删除自身失败 → message.error 追加「警告：残留了一条空路由 {name}，请手动删除」

### D3 跨 Tab 错误引导（P1-3）

- `validateForm` 改为返回错误分布 `{basic: string[], domains: string[]}`；保存时：
  1. 目标 Tab 有错 → 自动切换到第一个含错 Tab（用户始终能看到至少一条具体报错）
  2. Tab 按钮加错误角标（红点 + 数量，如「域名配置 ●3」）
  3. 弹窗底部固定汇总条：「还有 4 项问题在「域名配置」」——单 Tab 有错时不显示
- 域名卡标题在含错时显示红色感叹标识

### D4 术语统一（决策点 2A + 3A）

| 现状 | 改为 | 位置 |

| + 新建 DNS 查询 | + 新建 DNS 代理路由 | 页头按钮 |

| 共 N 条 DNS 查询 | 共 N 条 DNS 代理路由 | 过滤条计数 |
| 搜索路由名称... | 搜索 DNS 代理路由名称... | 搜索占位 |

- `dnsLbLabel` 补 `ewma: 'EWMA'`

### D5 卡片身份重排（决策点 4A）

- 顶栏：`URI + DNS badge + group badge` → **名称（主）+ DNS badge + group badge**；URI 移入详情区（集群行旁），带解释「DoH 入口路径」
- 详情区：集群行 + URI 行（URI 用 mono 弱色 + title 解释）
- 域名区标题行加「N 个域名」计数（无配置时保持「无 DNS 配置」→ 文案改「无域名配置」）
- 查看弹窗同步：加「编辑」次级按钮（关闭查看 → 打开编辑，一次点击完成跳转）

### D6 杂项（批 3）

- 健康检查 tag：`host.checks.type` → 大写显示（https→HTTPS；未知值原样）
- 搜索框原生 input 保留（页面手写控件体系一致），仅 emoji 🔍 换 CSS 放大镜符号（与 DnsQueryList 现有 .search-icon 一致化——保留现状亦可，标为可选项）
