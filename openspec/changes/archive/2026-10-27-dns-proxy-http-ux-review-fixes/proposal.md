# proposal: dns-proxy-http-ux-review-fixes

## Why

用户以标准评审简报要求对 DNS 代理（HTTP）模块做体验评审（易用性/易理解/美观层级/安全风险四维），输出 openspec 需求文档，批准前不动代码。证据链：DnsQueryList.vue + DnsQueryFormModal.vue 全文走读、主规格 `dns-query-management` 对照、真实页面 Playwright 走查（列表/新建校验/编辑域名 Tab 4 张截图，test 环境 doh 规则实测）。

**模块本质**：DNS 代理路由 = 带 `dns_upstream` 插件的 HTTP 路由（DoH 入口），复用通用 /routes 端点；发布/删除/版本已走共享单实现（#7/#18 合规）。问题集中在**表单安全与文案**，不在链路。

## 问题清单

### P1（数据风险/信任）

1. **健康检查 JSON 静默吞错（数据丢失）**：`checksJson` 提交时 `JSON.parse` 失败 → 静默替换为 `{active:{},passive:{}}`（连 `type` 都丢，与默认值 `{"type":"https",...}` 不一致），用户输入无提示消失（DnsQueryFormModal buildPluginsPayload L379-384）。健康检查本身是裸 JSON 文本框（截图 84），普通用户无法自证合法。
2. **两步保存非原子**：创建 = POST route → PUT plugins；编辑 = PUT route → PUT plugins。第二步失败时：新建残留「无 DNS 配置的孤儿路由」、编辑残留「基础信息已改但域名配置未改」，前端只报「保存失败」，不说明部分成功状态。
3. **跨 Tab 错误不可见（截图 85 实证）**：空表单保存产生 6 个校验错误，基础 Tab 只显示 2 个——域名/节点 4 个错误在隐藏的「域名配置」Tab 里，用户看不到任何域名相关报错，只觉得「保存没反应」。

### P2（易理解/一致性）

4. **实体叫法三合一**：「+ 新建 DNS 查询」（页头按钮）/「新建 DNS 查询路由」（弹窗标题、空态按钮）/「共 N 条 DNS 查询」（计数）/「DNS 代理（HTTP）」（页面标题）。主规格已规定「不再使用旧标题 DNS 查询」（列表视图需求场景 1），但按钮/占位/计数仍在用旧叫法。
5. **URI 被当作卡片主身份**：顶栏大字显示 URI——所有 DNS 代理路由实际都是 `/dns-query`（DoH 入口约定值），该行零信息量；真正的身份（名称 + 域名列表）反而次要。表单 URI 字段亦无任何解释（用户不知其作用）。
6. **EWMA 缺失映射**：表单负载均衡下拉含 `ewma`，列表 `dnsLbLabel` 映射表无 ewma → 卡片显示原文 "ewma"（其他算法均显示中文）。
7. **「节点」术语撞车**：域名配置里「目标节点 / N 个节点」指 DNS 上游服务器，与平台「节点管理」的 Edge 节点重名，易误解为要选平台节点。
8. **编辑打开时域名全部折叠**：`parseDnsConfig` 还原后 `expanded: false`，多域名规则需逐个点开检查。

### P3（打磨）

9. 查看弹窗无「编辑」快捷入口（查看 → 关闭 → 编辑三步）。
10. 卡片健康检查 tag 显示原始值 `https`（小写协议原文），可规范化显示。
11. 搜索框为原生 input + 🔍 emoji 图标，与全站搜索控件形态不一（低价值，随批顺带）。

## Goals

- 任何校验失败都必须可见且可到达（Tab 引导/自动切换），任何用户输入都不得被静默丢弃
- 保存的部分成功状态如实告知（create 回滚 / edit 分步说明）
- 全页单一实体叫法（DNS 代理路由 / DNS 上游服务器），与页面标题、菜单术语呼应

## Non-goals

- 不改发布/删除/版本链路（已是共享单实现）
- 不改 URI 的技术语义与默认值（`/dns-query` 是 DoH 约定入口）
- 不做 DNS 连通性测试（独立立项）

## 分批

- **批 1（表单安全与原子性）**：跨 Tab 错误引导（自动切换 + Tab 角标 + 汇总）；健康检查 JSON 校验失败阻止提交并报错（先堵静默丢弃）；创建失败补偿回滚；编辑失败如实分步提示；编辑打开展开第一个域名
- **批 2（术语统一）**：全页统一「DNS 代理路由」；「节点」→「DNS 上游服务器」（N 个上游）；EWMA 映射补齐；搜索占位/计数/删除文案随批
- **批 3（卡片与查看）**：卡片身份重排（名称+域名数为主，URI 降级至详情区带解释）；查看弹窗加「编辑」按钮；健康检查类型显示规范化（https→HTTPS）
