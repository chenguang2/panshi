# Proposal: overview-page-ux

## Why

概览页（`frontend/src/views/Dashboard.vue`，侧边栏「核心功能 → 概览」）UX 评审（2026-10-10，设计师五维度评审 + 代码/数据契约核实）发现 **3 个 P0 误导性缺陷**与一组系统性问题：

1. **集群状态文案与数据语义错位（P0）**——`Cluster.status` 是平台侧启用/禁用开关（后端 `cluster_export.py` 渲染口径即「启用/禁用」，`cluster-ux-close-loop` 已在全站统一该术语），概览页却显示「正常运行 / 离线」。用户会把「已禁用」集群误读为「宕机」，也会因「正常运行」误以为系统做过健康探测。
2. **四个接口静默吞错，故障时显示全 0 假象（P0）**——`onMounted` 中每个请求 `.catch(() => null)`，无错误提示、无重试入口。后端故障时页面安静显示「集群 0、节点 0」，运维会误判「系统没有集群」，可能诱发误重建——对运维系统而言是最危险的一类静默失败。
3. **节点「离线」实为「上次连通性检测失败」（P0）**——`Node.status` 由上次连通性测试结果写入（`clusters.py` 测试通过置 1、失败置 0），非实时心跳。红点 +「离线」是强实时语义，实际可能只是从未测过或上次测失败。
4. **入口不做权限过滤（P1）**——12 个快捷链接 + 4 张统计卡全部硬编码展示。非管理员点击「用户管理」「数据库管理」等无权限入口，被 `router.beforeEach` 静默弹回概览页（`return '/'`）——**点了没反应**，比报错更迷惑。AppSidebar 已有现成的 `permission + feature + adminOnly` 三元过滤机制，概览未复用；侧边栏「数据库管理」还有 feature 门控，概览却无条件展示，同站不一致。
5. **零刷新机制、零时间锚点（P1）**——无轮询、无手动刷新、无「数据更新于」。运维常驻此页看到的是进页面那一刻的快照，且无从判断数据新鲜度。PageHeader 的 `actions` 插槽空置未用。
6. **「最近路由」无时间列，排序依据不可见（P1）**——接口按 `Route.created_at` 倒序取 10 条，但响应与前端表格都没有时间字段，「最近」按什么排的无从建立信任。
7. **节点数据源不统一（P1）**——「节点在线」卡片用 `listNodes({pageSize:500})` 全量拉取再前端过滤，而 `/dashboard/stats` 已返回 `nodes` 总数却未用于此卡；节点超 500 时统计静默截断出错。
8. **数据区与请求不做权限联动（P1，评审确认时补识别）**——集群卡/节点卡/最近路由卡无任何显隐规则，`loadAll()` 无条件发全部请求；而后端 `GET /clusters` 需 `clusters` 权限、`GET /nodes` 需 `nodes` 权限——受限用户进概览即命中 403，被错误横幅伪装成「系统故障」（预期的权限拒绝 ≠ 故障）；空态 CTA 也指向会被守卫弹回的路由。
9. **「检测通过」把未检测节点算成通过（P1，评审确认时补识别）**——`Node.status` 默认值为 1、`status_detail` 未测试时为 NULL：新建从未测试的节点会被计入「检测通过」，把「未知」表述成「健康」，与本变更「只说数据真实承载的话」的原则相悖。
10. 一致性瑕疵（P2/P3）：无加载态（闪 0）、空态无引导、node-card 手写实现与 TableCard 双轨漂移、离线节点清单无溢出保护、行不可点击定位、`ref<any[]>` 违反类型治理、「快捷入口/更多资源」分组无语义、高危入口（数据库管理）零风险标注、stats 其余 5 个计数取回即弃。

## What Changes

- **语义诚实化（P0）**：集群状态徽章改「已启用 / 已禁用」（消灭「正常运行 / 离线」）；节点连通状态改「检测通过 / 检测失败」表述（卡片标题「节点连通状态」、全通过横幅「全部 N 个节点上次检测通过」）；页面副标题改「平台资源统计与快捷入口」——页面只承诺数据真实承载的语义（资源清点 + 上次检测结果 + 最近变化），不承诺实时健康。
- **三态补齐（P0）**：加载态（TableCard `:loading`，刷新时保留旧数据）；错误态（**全部已发起的请求**失败 → 页头下方 danger 横幅「数据加载失败，请检查后端服务是否可用 [重试]」；局部失败 → 横幅列出失败资源 + 失败区轻量错误条；重试只重发失败请求；后端 403 属预期的权限拒绝，防御性视为隐藏该区而非错误横幅；**任何失败不得以 0 值或空表伪装成功**）；空态（「还没有集群，去创建 →」等引导 CTA，CTA 同样受对应权限约束）。
- **权限过滤（P1）**：快捷入口 / 更多资源 / 统计卡 / 三张数据卡（集群、节点、最近路由）的每项增加 `permission / feature / adminOnly` 字段，复用与 AppSidebar 同源的三元过滤（`authStore.hasPermission` + `featuresStore.has`）；**无权限的数据区不渲染且不发起对应请求**（fetch-visible-only，从源头消除 403 噪声）；过滤后为空的分组整卡隐藏；不改路由守卫（守卫仍作兜底）。
- **刷新与时间锚点（P1）**：PageHeader 操作区加「更新于 HH:mm」时间戳（首次成功加载前不渲染，无假时间）+「刷新」按钮（刷新期间禁用显示「刷新中…」；in-flight 防并发守卫统一覆盖头部刷新与分区重试）；加载逻辑抽 `loadAll()` 单点。
- **节点摘要数据源统一（P1，后端小改）**：`/dashboard/stats` 增加 `nodes_online` 与 `nodes_untested` 计数；节点摘要三态「检测通过 X · 未检测 Z · 失败 Y」（通过 = nodes_online − nodes_untested，未检测 = nodes_untested，失败 = nodes − nodes_online；未检测用中性灰徽章），统计卡副标题与节点卡头部徽章以 stats 为准，`listNodes` 降级为失败节点明细来源；明细命中分页上限（`PAGE_SIZE_CARD_GRID`=500）时提示「明细可能不完整」。
- **最近路由时间列（P1，后端小改）**：`RecentRouteItem` 增加 `created_at`；标题改「最近创建的路由」，表格加「创建时间」列（`formatMonthDayTime`），行点击跳 `/routes`（仅对具备 `routes` 权限的用户启用）。
- **打磨（P2/P3）**：node-card 收敛 TableCard 单实现 + 明细区 max-height 滚动；`ref<any[]>` 改类型化；「用户管理」移入快捷入口、两组重新定义为「运维操作」vs「配置与查询」；「更多资源」chip 带计数徽章（消费 stats 闲置的 5 个计数）；「数据库管理」chip 加「含恢复/迁移等高危操作」副标注；集群显示名称空值占位「—」。

## Capabilities

### Added

- `platform-overview-page`：磐石平台概览页（Dashboard.vue）能力规格——数据语义诚实化（启用开关 ≠ 运行健康、检测结果 ≠ 实时心跳）、数据加载三态、入口权限过滤、手动刷新与时间锚点、节点摘要数据源统一、最近创建路由的时间列与行定位、高危入口风险标注。

## Non-Goals（本轮不做）

- **`/dashboard/stats` 的 API 层权限收敛（评审确认：记入 Non-Goals）**：该接口对任意登录用户返回全部全局计数（含 users 总数），属既有后端行为、非本次引入；本变更 UI 侧已按权限渲染计数可控风险，API 层按用户权限过滤计数的语义（隐藏 or 置 0）需单独设计，另行立项评估。
- **受限用户的数据口径收敛（9.4 验收发现，平台既有行为非本变更引入）**：非管理员 `GET /clusters` 按集群分配过滤（未分配 → 空表），而 `/dashboard/stats` 与 `/dashboard/recent-routes` 为全局口径——受限视角存在「统计卡集群计数 vs 集群卡空态」与「最近路由含不可见集群路由」的不一致，空态文案「还没有集群，去创建 →」对受限用户亦有歧义。属平台数据层口径问题（涉及 stats/recent-routes 按权限或分配收敛、或空态按角色区分文案），另行立项评估。
- **实时健康探测 / 心跳**：后端无实时探测数据源，硬做即语义造假；概览定位诚实化为「资源清点 + 上次检测结果 + 最近变化」。
- **`Node.last_checked_at` 字段**：展示「上次检测时间」需新增模型列（含 COLUMN_MIGRATIONS 与回归），另行立项。
- **自动轮询刷新**：本轮仅手动刷新；60s 自动刷新作为后续可选增强（MetricsDashboard 已有先例可循）。
- **全站节点「在线/离线」术语统一**：节点管理页、连接测试等页面的术语语境不同，需独立评估后另行变更；本轮仅治理概览页表述。
- **路由守卫行为调整**：`router.beforeEach` 静默弹回保留为兜底，本轮靠入口过滤消除触发场景。
- **`/dashboard/recent-routes` 行级深链**：行点击仅跳 `/routes` 列表页，不做定位到具体路由行的深链。
- **节点明细服务端分页**：>500 节点仅做截断提示，不做明细分页。

## Impact

- **后端（极小，无模型/迁移变更）**：`backend/app/api/v1/dashboard.py` —— `DashboardStatsResponse` 增 `nodes_online` 与 `nodes_untested`（两个只读 count 聚合，后者 = `count where status==1 AND status_detail IS NULL`）、`RecentRouteItem` 增 `created_at`；不改 `COLUMN_MIGRATIONS`、不触 schema/写库路径。
- **前端（主体）**：`views/Dashboard.vue` 重写加载编排与状态区；组件仅复用（StatCard / TableCard / BadgeStatus / PageHeader 的 `actions` 插槽）；`utils/format.ts` 复用 `formatMonthDayTime`；权限键与 AppSidebar 严格同源（含三张数据卡显隐与 fetch-visible-only）。
- **测试（全部新建，现无任何 Dashboard 测试）**：后端 dashboard 接口用例（nodes_online / nodes_untested / created_at）；前端 Dashboard 组件测试（三态 / 权限过滤与数据区显隐 / 文案语义 / 刷新 / 403 特判）；`npx vue-tsc -b` + vitest；后端 `pytest -k dashboard`。
- **验收纪律（约定 #51②）**：三态、权限过滤、时间列必须在真实页面（localhost:12345 概览页）实机截图核验，组件断言不能替代；含管理员与受限账号两种视角。
- **行为微变（已确认接受）**：非管理员不再看到无权限入口与无权限数据区（对应请求也不再发起，有权限用户无感）；接口故障时从「假 0」变为「错误横幅 + 重试」；节点摘要从两态变三态（未检测独立呈现）；节点计数超 500 时明细区出现截断提示。
