## 一、量测结论（真机数值）

### 差异 1 · 工具条第一行结构与尺寸（P1）

| 项 | 路由页（基准 `.l5-toolbar`） | 四层代理页（现状 `.sp-header-actions`） |
|---|---|---|
| 容器 | `.l5-toolbar`（`TableToolbar` 产出） | 页面自造 `.sp-header-actions` |
| 行高 / 内距 | **57px** / `12px 16px` | **36px** / `0` |
| 下边框（与下一行分隔） | **1px** `var(--border)` | **无** |
| gap | **6px** | 12px |
| 顺序 | 搜索 → 分组 → 集群 → 上游 → 插件 → 方法 → spacer → 刷新 → 列配置 → 全部收起 → seg | **状态 chips → 搜索 → 分组 → 集群 → 计数 → 全部收起 → seg** |
| 搜索宽 | 150 | **200** |
| 分组控件类 | `.l5-select`（原生） | **`.form-input`**（原生，但非共享类） |
| 计数「共 N 个」 | **不显示**（`show-count=false`，命中数只归分页条/chips） | **显示**（第 5 个元素） |
| 刷新按钮 | 有 | **无** |

**根因**：卡片页从未接入共享 `TableToolbar`（该组件承载工具条解剖 + `#filters/#config/#mode-extra` 槽），页面自造了一行 flex 容器，因此尺寸/边框/gap/右侧簇顺序全部自定。状态 chips 也被塞进这一行（见差异 2）。

### 差异 2 · 状态行未独立（P1）

| 项 | 路由页 `.l5-chiprow` | 四层代理现状 |
|---|---|---|
| 是否独立第二行 | 是（高 41、`padding 9/9/16`、下边框 1px） | **否**（chips 在第一行最左，宽 311px） |
| 「状态」标签 | 有（`.chiprow-label`） | **无** |
| chips 位置 | 左簇起始 | 工具条首位 |

**根因**：同差异 1——卡片页把 chips 当普通筛选项塞进自造行；列表页的 `.l5-chiprow`（共享类）在 style.css 已存在但卡片页未使用。

### 差异 3 · 集群带（band）视觉与路由组头不一致（P1）

| 项 | 路由表格组头 `.l5-group-inner` | 卡片带 `.l5-band` | 差 |
|---|---|---|---|
| 左色条 | **`var(--accent)`**（品牌蓝） | **`var(--cc)` 集群色相**（蓝/紫/绿…） | **不同（用户所指）** |
| 左条几何 | 3px / 上下 inset 6 / 圆角 0 2 2 0 | 同 | 同 |
| 内距 | `8px 12px 8px 16px` | `7px 12px 7px 16px` | 上 1px |
| gap | 10px | **8px** | 2px |
| 集群名 | 13px / 600 / `--fg` | 13px / 600 / `--fg` | 同 |
| 数量 | **`.g-chip` 灰胶囊**（11px mono、`oklch(50% 0.018 240 / 8%)` 底、muted 字） | **纯文本 `.b-count`** 11px muted | **形态不同** |
| 分组徽标 | 无（表格组头只有 chips） | `.lp-tag.group` 绿标签 | 卡片多一项 |
| 右端说明 | `.g-note` 11px muted | `.b-hint` 11px muted | 同 |
| 背景 | `--bg` | `--bg` | 同 |

**根因**：卡片带是 r7 新建的一套类（`.l5-band`），当时按「同集群全站同色」的设计意图把左条绑到集群色相；而列表页组头（r3）绑的是 accent。两套实现从不同轮次长出，**没有共同的视觉单点**。

### 差异 4 · 卡脚按钮消失 / ⋯ 菜单「没反应」（P1）

量测事实：

1. **菜单其实能打开**（首行卡片：`open=1`，215×196px），点「编辑」→ 向导弹窗正常打开（`wizard.dialog=true`）。
2. **但末行卡片弹出后跑到视口外**：实测最后一张卡的菜单 `top=893 / bottom=1089`，视口高 1000 → **底部 89px 看不见**。用户在最下方卡片点 ⋯ 时会以为「没反应」。
3. **卡脚只剩「发布」**：原先独立的 查看 / 编辑 / 删除 / 版本管理 四个按钮已收进 ⋯ 菜单（按设计页），菜单不显眼（无 hover 底色）+ 末行溢出 → 用户感知为「按钮都没了」。
4. 触发区无 hover 反馈（`.op-btn` 只压掉边框，未加 hover 背景）。

### 差异 5 · 批量态 checkbox 压住卡头文字（P1）

实测：`.lp-check` 左 275→291；`.lp-hero`（`:9970`）左 280 → **15px 重叠**（用户描述为「覆盖名称」，实际压的是端口 hero，其次是 proto/名称）。

**根因**：**设计页有而实现漏移植**。设计 `theme.css:2624`：

```css
.l5-card.batch .lp-head, .l5-card.batch .lp-strip { padding-left: 33px; }
```

实现只搬了 `.l5-card.batch .lp-check { display: block }`，漏了 33px 让位规则 → 卡头仍从 14px 起排。

### 差异 6 · 批量管理按钮位置（P2）

实测页头按钮序：`搜索框(Ctrl K) → + 新建四层代理 → 批量管理`。
设计页（`stream-proxies.html:78-79`）：**批量管理（secondary）在新建（primary）之前**。实现顺序反了。

### 差异 7 · 批量条位置与形态（P1）

| 项 | 设计 / 列表页规范 | 四层代理现状 |
|---|---|---|
| 位置 | **状态行之下、卡片网格之上**（`.l5-batchbar`，随内容流） | **底部固定条** `.sp-batch-bar`（`position: fixed; bottom: 0`，实测 top=1050） |
| 形态 | `padding 8/16`、下边框、`.has-sel` 淡蓝底 + 描边、`已选 N 项` + `批量发布` + `批量删除(danger)` + 右侧 `清除选择`；未选时 `need-sel` 按钮 45% 透明 | 自造 `.sp-batch-bar`（底栏 + 阴影 + `已选择 N 个四层代理`） |
| 页面底部留白 | 不需要 | 靠 `.sp-page:has(.sp-batch-bar){padding-bottom:80px}` 撑开 |

`.l5-batchbar` 的样式在 `style.css` **已存在**（列表页 2026-11 就落地了），卡片页未使用。

## 三、决策点（需你裁决）

**A. 集群带左色条**（用户明确要求「和路由一样，并更新设计页」）
- A1【推荐】统一为 **accent**：band 与路由组头逐值一致；集群色相只保留在**平铺视图左侧色条 + 列表页集群列色点 + 集群分组徽标底色**（仍保持「同集群同色」编码）。需同步改 `proposal-c/stream-proxies.html` 的 `.l5-band` 左条与 `theme.css`，并在 BRIEF 注明「band 左条 = accent，集群色相不在 band 上表达」。
- A2 保留集群色相：则 band 与路由组头永久不同，需在 BRIEF 写明「有意不同」——与你「要一样」的诉求冲突。

**B. band 的数量文案形态**
- B1【推荐】灰胶囊 `.g-chip`（与路由 `.g-chip` 完全同款，含 11px mono）
- B2 保持纯文本

**C. 卡脚动作暴露度**
- C1【推荐】按设计：`发布` + `⋯`（修好翻转与 hover），并在 ⋯ 内保留 查看/编辑/版本管理/删除 四条目
- C2 外露 `编辑` + `发布` 两个 inline 按钮，其余进 ⋯（偏离设计，但高频动作一步可达）
