# Proposal

## Why

`list-pages-console-restyle` 已交付三独立列表页的结构改造（分组/双模式/徽标/合并列），但实现页与已批准的设计页（`docs/ui/Live-Artifact-5/proposal-c/`，方案 C 网关控制台感）在**视觉还原度**上仍有系统性偏差：表头大写与底色、全表竖线分隔、行高与内距、操作列图标与分隔、悬停态、分页形态、控件宽度等。用户以「设计页符合美观要求」为准绳，要求实现页与设计页在**同数据渲染下逐元素一致**，并将该核对方法沉淀为可复用的验收标准。

## What Changes

- **同数据比对取证（已完成的基线）**：以 Playwright 拦截接口、将 `nodes.html` 设计页的原始数据（生产/预发/开发三集群 12 节点、27 总数徽标）注入实现页，两侧同视口截图并逐元素量测计算样式，产出 `parity-audit-nodes.md`（8 项用户维度 + 附加发现，每项含设计值/实现值/原因/建议修法）。
- **视觉还原修复（待用户逐项批准后实施）**：按批准的差异清单逐项修改——表头形态（去大写/底色/内距）、去全表竖线（保留行拖拽手柄锚线）、行高与内距对齐、操作列 v-sep + 图标风格、悬停态 accent 化、分页器形态对齐（保持 #54 分页机制不变，仅视觉重绘）、IP/名称字段字重、控件宽度微调。
- **验收标准固化（本变更的核心交付）**：新增能力 `mockup-parity-verification`——「同数据注入 + 逐元素计算样式比对 + 截图对照」的三步验收法与判定阈值，适用于所有以 mockup 为视觉基准的页面（本批为节点/上游/路由三页，后续页面复用同一标准）。
- 范围限定：仅视觉层（CSS/模板类名/图标），不动交互逻辑、数据流、列配置/分页/分组机制；统一管理页三张 Tab 子表不在本轮（其样式走共享层时需回归确认无外溢）。

## Capabilities

### New Capabilities

- `mockup-parity-verification`: 设计稿还原度验收标准——同数据注入比对法（拦截接口注入 mockup 原始数据 → 双侧同视口截图 → 逐元素计算样式比对 → 差异项清单化裁决），含允许偏差白名单（如框架性差异：antd 组件壳）与判定流程（先清单后批准再修改）。

### Modified Capabilities

- `node-management` / `upstream-management` / `route-management`：表格与工具条的视觉解剖对齐 mockup（表头形态、分隔符、行距、操作列、悬停、分页视觉），交互语义不变。

## Impact

- **前端（全部改动所在）**：`frontend/src/style.css`（列表页控制台层 + table-container 级联）、三页视图 scoped 样式与模板图标、`TableToolbar.vue`（列配置触发器形态）。
- **守卫影响**：`tableHeaderHitArea.source.test.ts`（th 内距下限）、`tableAnatomy.source.test.ts`（序号列）、`grid-table` 竖线相关断言——修改前逐个核对，产断言反转清单（约定 #217）。
- **不受影响**：后端零改动；列配置/分页/分组/批量机制不变；其余卡片网格页面不回归（L5 层类名限定三页作用域）。
- **验收方式**：同数据注入脚本截图对照（存档于本变更目录）+ 全量单测 + 真机抽查。
