## 一、用户项①：状态胶囊「标签与字仍比设计页小」

### 1.1 实测：胶囊本体与文字已与设计逐值相同（r5 已改对）

| 量测（4x 裁切 + 计算样式） | 设计 | 实现 | 判定 |
|---|---|---|---|
| 「已停止」胶囊盒 | 60.34 × 20 | 60.34 × 20 | ✓ |
| 「已禁用」胶囊盒 | 51.34 × 20（透明底 + 1px 虚线 + 无圆点） | 51.34 × 20（同） | ✓ |
| 胶囊内文字宽 | 44.34 / 33.34 | 44.34 / 33.34 | ✓ |
| font-size / weight | 11px / 600 | 11px / 600 | ✓ |
| 内距 / 字距 / 圆角 / 圆点 | 0 8px / 0.11px / 999px / 6px | 同 | ✓ |
| 4x 裁切图尺寸 | 520 × 188 | 524 × 188（宽度差 1px = 状态列 126.6 vs 127） | ✓ 高度一致 |

→ **本机（Linux 开发机）不可复现「实现比设计小」**：两边的胶囊、字号、内距、字距全部相等，像素级裁切高度一致。

### 1.2 最可能的两个原因（需你确认）

**（a）页面是改动前的旧渲染**：r5 的胶囊修正（撤销 `padding: 0 5px`、已禁用改虚线）落在 `style.css` / `BadgeStatus.vue`，若浏览器标签页在改动前就已打开且 HMR 掉线，会继续显示旧形态（旧形态：内距 5px → 每枚窄 6px，已禁用是灰实底 + 圆点）。
**自查三步**：① 硬刷新（Ctrl/Cmd+Shift+R）；② DevTools 选中「已停止」胶囊，`padding` 应为 `0px 8px`（旧值是 `0px 5px`）；③「已禁用」应为**空心虚线、无圆点**（旧值是灰实底带圆点）。

**（b）字体族声明错位（真实存在，可修）**：**表格内容走的是 antd 默认字体栈，不是应用的 `--font-body`**。

| | 声明 |
|---|---|
| 设计页 `.l5-table`（`--font-body`） | `-apple-system, BlinkMacSystemFont, "SF Pro Text", Inter, "Segoe UI", system-ui, sans-serif` |
| 实现页胶囊实测 | `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans", …`（antd 默认，**缺 SF Pro Text / Inter**） |

- 本开发机未安装 Inter / SF Pro / Segoe UI / Roboto（canvas 检测全为 0），两边都回退到同一字体 → 逐值相同（这就是我 r5 量测「一致」的原因）。
- **但你的机器上若装有 Inter 或 SF Pro**：设计页用 Inter/SF Pro 渲染，实现页回落到 Segoe UI/Roboto/Arial —— 同样 11px 下字形宽度与视觉体量确实会小一档，正是你看到的现象。
- **建议**：把 L5 表格（及全站表格，一并更稳）字体族统一为 `var(--font-body)`，从此同 px 同字体、跨机器一致。改动 1 条 CSS，零结构变化。

### 1.3 若你确认「已是新形态（虚线 + 0 8px）但字仍嫌小」

那就不属于还原偏差，而是**要改设计基准**：胶囊 11px/20px → 12px/22px（设计页三份 HTML 同步改，否则下轮 parity 会反报差异）。**需你裁决，默认不做**。

## 二、用户项②：点「重置列宽」后出现横向滚动条

### 2.1 实测（节点页；`重置列宽` = 清空拖拽覆盖 → 回到设计列宽）

| 视口宽 | 卡片宽 | 可用宽 | 表格宽 | 横向溢出 |
|---|---|---|---|---|
| 1600 | 1312 | 1310 | 1310 | 0（设计验收视口，正好相等） |
| 1536 | 1248 | 1246 | **1310** | **+64** |
| 1440 | 1152 | 1150 | **1310** | **+160** |
| 1366 | 1078 | 1076 | **1310** | **+234** |
| 1280 | 992 | 990 | **1310** | **+320** |
| 1200 | 912 | 910 | **1310** | **+400** |

另两页同源（上游合计 1079、路由合计 1247）：路由 1536 已溢 1px、1440 溢 97、1366 溢 171；上游 1366 起溢出。

### 2.2 根因

1. 三页表格都传 `:scroll="{ x: 'max-content' }"`，antd/vc-table 据此给 `<table>` 写入 **`width: max-content; min-width: 100%`**（`vc-table/Table.js:199`）。`max-content` = 列宽之和，故表格**永远等于列宽总和**，不随卡片收缩。
2. 列宽是 r4-E2 按「1600 视口卡片宽 1310」定死的一组像素值（48/149/82/82/377/147/87/298 + 选择列 40 = 1310）。卡片一旦窄于 1310 就必然溢出。
3. 所以：**只要窗口不是 1600 宽，「重置列宽」就会把表格从用户拖窄的宽度拉回 1310 → 立刻出现横向滚动条**（你看到的现象）。

### 2.3 设计页的做法（这才是基准）

| | 设计 | 实现 |
|---|---|---|
| `table` 宽度 | `width: 100%`（antd 等价于 `min-width: 100%`）+ **`min-width: 1086px`** | `width: max-content`（= 列宽总和） |
| 1536 视口 | 表格 1246（= 容器），列宽按比例收缩 | 表格 1310，溢出 64 |
| 1440 视口 | 表格 1150（= 容器） | 表格 1310，溢出 160 |
| 低于 min-width（节点 1086 / 上游 1054 / 路由 1130） | 才出现横向滚动 | 同左（我们的 min 是 1310，阈值过高） |

→ 设计页是「**列宽按比例随容器伸缩，低于最小总宽才滚动**」，实现页是「**列宽固定，容器窄就滚**」。

### 2.4 修法（二选一）

**方案 A（推荐）· 默认列宽按可用宽度等比缩放**
- 共享 composable（新增，`useFitColumnWidths`）：ResizeObserver 观察表格容器宽 → `factor = min(1, 可用宽 / 设计总宽)`，未被用户拖拽覆盖的列取 `设计宽 × factor`（取整后把余数补给最宽列，保证总和恰等于可用宽）。用户拖过的列保持 px（其选择优先）。
- 效果：≥1600 与设计逐值相同；1536/1440/1366 等比收缩、**零横向滚动**；低于设计最小总宽（节点 1086）才允许滚动，与设计页一致。
- 三页同改（节点 1310/1086、上游 1079/1054、路由 1247/1130）。
- 代价：新增 1 个 composable + 三页接线；守卫断言（r4-E2 的「列宽 = 设计值」）需改成「1600 视口下 = 设计值」。

**方案 B（最小改动）· 单列弹性**
- 每页指定一列吸收余量（节点=安装路径、上游=目标节点与健康、路由=请求匹配），其余列维持设计 px + 表格 `scroll.x` 改为数值（最小总宽）。
- 效果：窄屏只有该列收缩（1440 下安装路径 377 → 217），其余列不变，视觉比例与设计偏离。
- 代价：每页改 1 个列定义的 `width` + `scroll.x` 数值 + 守卫调整；不新增依赖。

### 7.3 与设计页的有意偏差（已记录）

1. **不向上拉伸**：容器宽 > 设计总宽时仍用设计值（设计页是 `width:100%` 会整体放大）。1600 验收视口两者等价。
2. **最小总宽下探**：设计页最小总宽为节点 1086 / 上游 1054 / 路由 1130；实现取 1076 / 1054 / 1036，使 1366 笔记本宽度下也零滚动（设计页在 1366 会滚动）。低于该值两页都滚动。
3. **状态列 / 操作列下限**：`status ≥ 140`、`actions ≥ 268`，避免等比收缩把两枚胶囊挤成两行、或把按钮组挤出单元格（1440 实测曾溢出 5px）。
