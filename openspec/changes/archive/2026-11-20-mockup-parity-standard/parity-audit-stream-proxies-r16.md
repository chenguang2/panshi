# 卡片页一致性与集群色编码 · r16 差异审计

> 触发：用户 2026-11-18 第二轮反馈（四层代理页）——① 要求保留「不同集群行左端颜色不同」；② 分组时集群行 hover 变白要改；③ 批量条去掉「批量发布」（功能不存在）。
> 方法：同 #82 五步法。真机量测脚本 `/tmp/opencode/parity-r8/audit-r16.mjs`，1600×1100，路由页作表格基准。
> 状态：**清单先行，未改代码**。

## 差异 1 · 集群带左条丢了集群色相（r15 裁决需要回退）

| 项 | 事实 |
|---|---|
| 现状 | `.l5-band::before { background: var(--accent) }` —— 所有集群同一条品牌蓝 |
| 元素仍在带色相类 | band 元素 class = `l5-band cluster-c5`，`--cc = oklch(55% 0.12 240)`（卡片页集群色相变量齐备但**未被使用**） |
| 路由组头 | 左条 `oklch(0.56 0.16 210)`（accent）—— 表格页靠「集群列 + 组头」双线索，色相不承担身份 |

**根因**：r15 我以「与表格组头逐值同构」为判据，把 band 左条统一成 accent。但**卡片页没有「集群列」**，band 左条与平铺左缘条是唯一的集群身份线索——把色相换成 accent 等于删掉了卡片页的集群区分能力。**该裁决在卡片语境下不成立，需回退。**

**修法**：`.l5-band::before` 恢复 `var(--cc, var(--accent))`（无 `--cc` 时回落 accent）；设计页 `theme.css` 同步；连带撤销 `AGENTS #88 ⑤` 中「左条 accent」与 `BRIEF §九 6` 的对应表述，改写为「band 左条 = 集群色相（卡片页唯一集群身份线索），与表格组头的 accent 有意不同」。灰胶囊数量、chevron muted、gap 10、内距 8-12-16 均保留（用户未反对，且与表格对齐不冲突）。

## 差异 2 · 集群带 hover 变纯白

| 状态 | 路由组头 `<td>` | 卡片 band |
|---|---|---|
| 常态 | `oklch(0.97 0.005 250)`（= `--bg`） | `oklch(0.97 0.005 250)`（= `--bg`，**同值**） |
| hover | `oklch(0.56 0.16 210 / 0.04)`（accent 4% 淡底） | **`oklch(1 0 0)`（纯白 `--surface`）** ← 比常态更亮，反向跳白 |

**根因**：`.l5-band[role='button']:hover { background: var(--surface) }` 的设计假设是「常态 = surface、hover 抬到 surface」，但 band 常态取的是 `--bg`（灰）。于是 hover 把灰底换成白底 —— 用户看到的「显示时白色」。

**可选方案**（需裁决）：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A【推荐】** | hover = `oklch(56% .16 210 / 4%)`（与路由**完全同值**） | 跨页同构；有 hover 反馈；不跳白 | hover 与「集群色相」无关 |
| B | hover = `var(--cc-bg)`（该集群 10% 淡底） | 强化「这行属于这个集群」 | 8 色轮换下每行 hover 底色不同，比路由重；与 A 的两页同构性丢失 |
| C | 不变色，仅边框加深 | 最轻 | 整行可点（折叠）但反馈弱 |

**建议 A**：首要诉求是「和路由一样」；集群色编码已由左端 3px 条 + 平铺左缘条承担，hover 再铺满整行属于过度表达。

## 差异 3 · 批量条含「批量发布」，功能不存在

| 项 | 事实 |
|---|---|
| 实现 | `batchPublish()` 只对选中第一项打开发布确认 + `message.info('批量发布：本次仅打开第一项…')` —— **半成品**（上一轮我临时补的，语义不成立） |
| 设计页 | `stream-proxies.html:137`、`dns-udp-proxies.html:127` **都画了「批量发布」** |
| 批量条其余按钮 | `已选 N 项 · 批量删除(danger) · 全选当前筛选结果 · 清除选择` |

**修法**：删除 `batchPublish()` 与按钮；两页设计稿同步删除（分隔线 `.b-sep` 位置随之调整，删除后 `已选 N 项 | 批量删除` 之间保留分隔线）；批量条保留 `已选 N 项 · 批量删除 · 全选当前筛选结果 · 清除选择`。`need-sel`（未选时 45% 透明）规则保留，批量删除仍受选中门控。

**连带**：设计规范 `BRIEF §七.5` 与 `AGENTS #87 ⑤` 的批量条清单需同步删掉「批量发布」；`AGENTS #88 ③` 同。
