# proposal: clickhouse-config-ux-review-fixes

## Why

用户以标准评审简报要求对 ClickHouse 配置模块做体验评审（易用性 / 易理解 / 美观层级 / 安全风险四维 + 状态展示），输出 openspec 需求文档，批准前不动代码。证据链：`ClickHouseConfig.vue` 全文走读、`clickhouse_config.py` / `clickhouse_client.py` 契约核验、`stores/metrics.ts` 消费方核验、主规格 `clickhouse-config-management` 对照、真实页面 Playwright 走查（页面全貌 / 新建弹窗 / 失败 toast / 成功 toast 共 4 张截图）+ API 实测（试连失败文案、重名新建、真实 CH 192.168.100.42 试连成功，实验残留已还原 1/1）。

**模块本质**：单页配置模块（命名连接 CRUD + 激活切换 + 试连），存储于 `backend/clickhouse.yaml`、写盘即免重启生效（缓存版本号失效机制已在）。CRUD / 审计 / 密码加密 / 权限门控均合规；问题集中在**状态诚实性与反馈可追溯**，不在链路。

**关键语义实锤（决定状态展示怎么设计）**：

- 「当前连接」绿点由 `activeConnection` 是否存在驱动（`.status-dot.online`），**与连通性无关**——实测激活连接 127.0.0.1:9000 拒连（toast 报 `Code: 210. Connection refused`）的同时绿点依然亮，同屏自相矛盾（截图 03 实证）。
- `execute_query` 失败返回 `None` → metrics 端点按 2026-06-23 设计返回 `{data: []}`（非 500）→ 前端 `catch` 不触发，指标页渲染**空图表**：「无数据」与「取不到数据」不可分辨，且无任何跨页引导。
- 测试端点按主规格「MUST NOT 落盘」，测试结果只有 3 秒 toast，无任何持久痕迹；`last_test_*` 类状态不存在。
- 开箱即踩坑：随包模板预置 `ck_default`（「默认连接（示例）」→ 127.0.0.1）且**就是激活连接**——全新部署打开本页即呈现「绿点在线 + 实际不可达」（本机运行态即此状态，截图 01 实证）。

## 问题清单

### P1（信任 / 风险感知）

1. **绿点是假状态**：状态卡的 `online` 绿点仅表示「已配置激活连接」，用户普遍读作「ClickHouse 正常」。数据源类产品的核心信任指标失真，且与试连失败 toast 同屏矛盾。
2. **数据源死亡全链路静默**：激活连接不可达时，配置页无感知（绿点照亮）、指标页无感知（空图表）、无跨页引导。真实故障路径：切到死连接 / 服务宕机后，用户先发现「指标怎么没数了」，排查动线断裂。
3. **切换激活无连通性提示**：`POST /activate` 只改指针，不参考目标连接的测试历史（也没有历史可参考）；可一键切到从未测试或已知失败的连接，确认弹窗无任何风险提示。

### P2（易理解 / 易用）

4. **测试结果不可追溯**：行内「测试」与弹窗「测试连接」的结果均为瞬态 toast；列表无「上次测试」列，页面无任何持久化测试状态，关页即归零。
5. **错误文案裸驱动输出**：`连接失败：Code: 210. Connection refused (127.0.0.1:9000)` ——英文 + 驱动错误码直出（截图 03）。高频失败（拒连 / 认证失败 / 库不存在 / 域名解析失败 / 超时）无中文转译、无排查建议。
6. **连接名称可重复**：实测重名新建直接成功（已还原）。重名不破坏功能（按 id 操作），但列表出现两个「生产指标库」无法分辨，激活确认弹窗按名称指代产生歧义。
7. **「新建 → 启用」路径长**：首条连接自动激活，第二条起完整路径 = 新建 → 填表 → 保存 → 找行 → 设为当前 → 确认，六步；换数据源是本页高频操作。
8. **表单校验弱**：仅 name/host 非空两个 toast；host 无格式校验（`192.168. ` 可提交）；端口输 0 或清空被 `Number() || 9000` 静默改写成 9000；越界端口（70000）落到后端 422，toast 显示 pydantic 英文原文（`port: Input should be less than or equal to 65535`，getApiErrorMessage 实测路径）；所有校验错误不定位到字段。
9. **端口语义零提示**：模板注释明确「port 为 native 协议端口（默认 9000；HTTP 8123 不适用）」——这是最高频的真实配置坑，表单却无任何提示。
10. **列表信息缺列**：`password_set` 后端已返回但页面不显示（确认是否配过密码须点开编辑看 placeholder）；连接超时不显示（低价值，可不入列）。

### P3（一致性 / 打磨）

11. **表格解剖不合 #59 标准**：无 `#` 序号列（table-anatomy：首列 `{title:'#', key:'index', width:45}`，全量渲染用 `index+1`）。
12. **空态双层且无 CTA**：列表为空时 a-table 默认「暂无数据」与下方 `.empty-hint` 文字并存；无 `#emptyText` 槽（约定 #57 坑形）；M2 惯例（空态带引导按钮）未落地。
13. **状态卡信息密度低**：整卡仅承载「绿点 + 名称 + 地址」，与表格「当前」列信息重复；最有用的信息（连通性、上次测试、快捷动作）反而没有。
14. **`clickhouse.yaml` 文件头注释过期**：`_write_struct` 与模板注释均写「系统管理 → ClickHouse 配置」，页面已在批 9 迁「监控」组。
15. **禁用 danger 按钮视觉噪声**：激活行的「删除」禁用态仍为红色，看起来像可点的危险操作。
16. **（顺带）后端 create/update/delete 连续两次 `await db.commit()`**：重复代码，行为无害，随批清理。

## Goals

- 状态诚实：页面任何时刻 MUST NOT 展示与实测连通性矛盾的「在线」暗示
- 失败可追溯：测试结果持久可见；切换激活前能看到目标连接的测试历史
- 错误可理解可行动：高频失败中文转译 + 排查建议，原始错误保留可查
- 表单防呆：行内校验定位到字段、端口语义提示、重名拒绝

## Non-goals

- 不改 CRUD / 激活 / 试连的既有 API 契约语义（密码仍不回显；鉴权 / 审计 / 加密 / 免重启失效机制不动）
- 不做后台定时健康探测（页面级进页检测 + 手动检测足够，定时巡检如需另立项）
- 不用 a-form 重构弹窗（维持手写 modal 形态，对齐弹窗三层制约定 #25；行内校验用轻量 error state 实现）
- 不做连接导入导出 / 凭据轮换等增值功能（未在本次评审范围）

## 分批

- **批 1（状态诚实与风险感知，P1-1/2/3）**：状态卡改造为「数据源健康卡」（进页自动检测激活连接 + 重新检测按钮 + 可达 / 不可达 / 检测中 / 未配置四态 + 失败原因摘要 + 「去指标总览」入口）；试连错误中文转译（后端，原始错误保留）；激活确认弹窗展示目标上次测试状态，未测试 / 上次失败给黄色警示
- **批 2（表单与流程，P2-4/6/7/8/9/10）**：测试结果持久化（`last_test_*` 操作元数据 + 「上次测试」列 + 密码列）；「保存后设为当前连接」勾选项；行内校验（必填 / host 格式 / 端口范围）+ 端口 native 语义提示；重名 400 拒绝
- **批 3（一致性与收尾，P3 + 决策点 5）**：`#` 序号列；单层空态带「+ 新建连接」CTA；文件头注释修正；danger 禁用态去红；双 commit 清理；（若决策点 5 选 A）指标页「数据源不可用」横幅

## 需补充（待确认）

- **角色口吻**：`clickhouse_config` 为可授予资源权限（超级管理员直通）。本文档按「平台管理员」口吻撰写、不做角色分支——如该权限实际普遍授予普通运维角色请指出，涉及文案改按一般运维口吻。
- **指标页横幅归属**：见决策点 5，影响批 3 范围与 delta 规格数量。

## 决策点（待用户裁决）

1. **测试结果持久化**：A 落盘 `last_test_ok/last_test_at/last_test_error`（操作元数据，测试端点加 record 语义；「上次测试」列与激活警示依赖它，**推荐**）/ B 不落盘，仅状态卡实时检测 + 行内 toast（批 2 相应瘦身，激活警示降级为「建议先测试」静态提示）
2. **「保存后设为当前连接」**：A 新建弹窗加勾选项、默认不勾（显式选择不惊吓，**推荐**）/ B 保持现状（保存后行内「设为当前」）
3. **错误转译位置**：A 后端转译——`error` 字段即中文主文案 + 排查建议，`error_detail` 保留原始输出（**推荐**：转译逻辑单实现，测试端点三个调用方自动一致）/ B 前端映射表（后端零改动，但映射与驱动版本耦合在两端）
4. **重名处理**：A 后端 400 拒绝（trim 后精确比对，update 排除自身；存量重名不强制处理，**推荐**）/ B 保持允许
5. **指标页「数据源不可用」横幅**（P1-2 的跨页半边）：A 纳入本变更批 3——metrics summary 响应加 `source_ok`，指标总览 / 查询两页顶部横幅 + 跳转配置页链接（delta 新增 `metrics-source-status` 能力；**推荐**：P1-2 只修配置页半边则用户实际踩坑点仍在）/ B 独立立项（本变更严格限于配置模块）
