# Design

## Context

`PublishPreviewModal.vue` 现有呈现：`nodes[]`（逐节点状态/diff_count/behind）+ `matrix.diff_rows/same_rows`（每行 values 为 {节点标签: 值}）。组件测试已具备 mock result 注入模式。当前部署 ≤3 节点/集群（可接受运营现状），本变更为节点数增长的结构性储备。

## Goals / Non-Goals

**Goals:**
- 阈值混合：≤5 节点现矩阵零变化；>5 节点自动分组
- 分组聚合为纯函数（可独立单测），组件仅做呈现分支
- 后端零改动

**Non-Goals:**
- 不做后端分组聚合（响应体积在几百节点规模仅几百 KB）
- 不做组内节点选择器下钻（列为后续增强，非本批）
- 不改对比口径/响应契约

## Decisions

**D1 差异指纹与分组。**
每节点指纹 = 其 diff 条目集合的规范化序列化：`JSON.stringify(sorted(diff_rows 中该节点有贡献的 {path, value} 对))`，外加节点状态（missing/unreachable 单独成组不参与指纹）。指纹相同的节点归组 → 组内差异表 = 该指纹的行集（路径 × 待发布 × 组值），组内值全同由指纹保证。「与待发布一致」= 无任何 diff 贡献且 status 为 ok 的节点。分组顺序：落后/旁路等差异组（按节点数降序）→ 资源缺失 → 不可达 → 与待发布一致（末位）。

**D2 阈值与形态判定复用既有字段。**
阈值常量 `NODE_MATRIX_THRESHOLD = 5`（`nodes.length > 5` 切分组）。组的语义标注复用节点既有 behind/status/behind_reason（组头描述 = 成员节点的 behind_reason/状态文案去重后的并集），不新增响应字段。

**D3 「显示一致字段」开关的分组语义。**
开关开启时，每个差异组在其差异表下追加「组内与候选一致的字段行」（候选叶子集中去除该组 diff 路径，值 = 候选值）；一致组/缺失组/不可达组不展开字段。与矩阵模式行为对齐。

**D4 测试。**
组件测试新增：8 节点 mock（5 一致 + 2 同指纹落后 + 1 旁路）→ 断言分组块数量/组头文案/IP chips/组内差异表行；5 节点 mock → 断言仍为矩阵（回归）；开关在分组模式下追加一致行。聚合纯函数单测：指纹分组边界（全同/全异/混合/缺失/不可达）。

## Risks / Trade-offs

- 阈值 5 为产品判断：当前 ≤3 节点部署完全走旧路径；未来若 5-6 节点集群希望看矩阵，仅需改常量。
- 组头描述由 behind_reason 拼接可能较长——长文案折叠进 chips title（悬浮全量），组头保持一行摘要。
