## Why

统一管理页现有的"导出 Excel"（`cluster_export.py`）是面向人阅读的报表：字段不全（路由 `vars`/`enable_websocket`、四层代理超时与健康检查等大量字段缺失）、值被展示化（targets/插件拼成字符串）、且按安全设计不含证书内容与集群 admin_key。因此它无法作为数据源把集群重新导入系统。运维需要一套**机器可读、字段无损**的集群备份/重建能力。

经调研与评审确认采用方案 A：Excel 保持人读报表定位不变，另建 JSON 全量备份/重建通道。评审中确认两个关键收敛：

1. **只做单一导入模式**（新建集群 + 数据库分配新 ID + 名称映射重建外键）。业务表主键全表唯一而非按集群隔离，"保 ID 的集群级还原"在非空库上必然主键冲突；整库级灾备恢复继续走现有「数据库管理」的整库迁移能力。
2. **内容缺失一律降级 + 警告清单**，不用硬失败卡死用户（源数据自身的历史脏数据同理，自动清理并告警）。

## What Changes

- 新增集群级 **JSON 备份导出** API：导出集群全部业务表的全量字段（含 Excel 未覆盖的表与字段），证书/私钥、静态资源文件本体可选包含；文件自带版本号与 SHA-256 校验和
- 新增 **JSON 导入重建** API（单一模式）：上传备份 → 系统创建新集群 → 忽略平台自增 ID 由数据库分配 → 按"名称 / ip:port"映射重建外键（含 `stream_proxies.ref_node_id`）→ 源数据悬空引用自动清理并计入警告清单 → 返回导入结果与"需补齐清单"（缺内容的证书、缺文件的静态资源）
- 导入后的集群处于**未发布**状态，结果页明确提示需手动发布才生效到 Edge
- 前端统一管理页新增【备份下载】与【从备份恢复】入口
