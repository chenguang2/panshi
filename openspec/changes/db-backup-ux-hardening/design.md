# Design — 备份与容灾页 UX 加固

## Context

评审（des-1，2026-10-01）确认页面骨架专业，但 H1–H6 落在信任要害。后端事实（cod-1 全文直读核查，行号即 ground truth）：

- `POST /db-backup/restore/execute`（`backend/app/api/v1/db_backup.py:606-630`）是**同步 await**，响应返回即恢复完成；下载/校验都在 verify 阶段（下载超时 300s）。execute 无整体内部超时。
- 暂存 TTL = 600s（`db_restore_service.py:36` `STAGE_TTL_SECONDS`）；过期执行返回 409「校验会话已过期或不存在，请重新校验后重试」。
- 备份/恢复共用互斥锁；冲突返回 409「已有备份/恢复任务进行中，请稍后再试」。**注意：并发拒绝时 `drop_staged` 会顺带删除本次 verify_id 的暂存**（`db_restore_service.py:483-485`）——冲突解除后必须重新校验。
- `status.reason` 恰好 3 种取值（`db_backup.py:98-101`）：`None` /「注册表中没有 SQLite 连接，不适用」（功能维度）/「未配置启用的备份位置」（配置维度），两语义共用一字段。
- `POST /db-backup/targets/test` 仅校验 SSH 连通 + 认证 + 可执行命令（单条 `echo`）；**不校验远端目录可写性、不校验磁盘空间**（目录/磁盘问题只在真实备份推送阶段以 runtime_error 暴露）。

约束：本次**不改后端**；遵循 AGENTS.md 约定 #25（弹窗三层制）、#26（格式化只用 utils/format.ts）、#43（mock 必须 URL 感知兜底、形状取自真实响应）、#16（TDD）、#51（验收落在真实页面）。

## Goals / Non-Goals

**Goals:**
- 修复 H1–H6 全部信任要害问题，M1–M13 全部修复，L 批量清理。
- 纯前端实现：状态口径统一、危险操作守卫与透明化、可用性信号、完成闭环。
- 每批 TDD（vitest，URL 感知 mock），`vue-tsc -b` 全绿，真实页面截图验收。

**Non-Goals:**
- 后端 API 变更（含给 `status.reason` 加结构化 kind 字段——前端按已知字符串分类即可，后端结构化留待后续）。
- 恢复执行 SSE 流式化（execute 为本地落位+引擎重载，秒级到数十秒，显式超时 + 防重文案已足够；迁移 SSE 先例不适用于此场景）。
- 历史数据分页/接口重构；页面 Tab 化（方案 B 中期再议）。

## Decisions

### D1 状态单一数据源与编辑态隔离（H1）
状态区（调度徽章、下一轮预计、最近成功、reason）一律只读 `GET /db-backup/config` 响应内的已保存 config + status；编辑区 `form` 不再反向影响状态区。dirty 判定 = `form` 与已保存快照的归一化比较（密码字段留空视为未修改，按后端「留空不修改」语义排除）。**替代方案**（逐字段 watch 标脏）弃——字段集会演化，维护成本高。新增计算属性 `isDirty`，页面显示「有未保存修改」徽标（M12）。

### D2 `status.reason` 前端分类（H1/M6 关联）
前端以两个已知字符串常量映射为 `kind: 'ok' | 'no-sqlite' | 'no-targets'`，未匹配值原样透传展示。避免脆弱的按文案分支扩散：分类函数单点定义在组件内，后端未来加结构化字段时只改一处。

### D3 立即备份守卫（H2 + M9 等待预期）
`runNow` 前置 `isDirty` 检查：弹三选（自定义内联弹窗，约定 #25 视图级）——「保存并备份」（saveConfig 成功后自动 run）/「按已保存配置备份」（提示按旧配置执行）/「取消」。执行期按钮锁定，文案给耗时预期（「打包并推送到 N 个位置，约需 1–2 分钟」，N = 启用位置数）。409 时使用后端 detail 原文（「已有备份/恢复任务进行中，请稍后再试」）。

### D4 恢复执行超时与防重文案（H3）
`executeDbRestore` 显式 `timeout: 600_000`（execute 无下载，正常秒级；600s = 2× 暂存 TTL，保守上限）。失败文案分三类：超时 →「恢复请求超时：后端可能仍在执行恢复（落位与引擎重载进行中），请勿重复发起；请刷新页面并核对当前活动数据库」；409 过期 →「校验会话已过期（暂存有效期 10 分钟），请返回上一步重新校验」；409 冲突 → 使用后端 detail 原文 + 追加「本次校验暂存已失效，冲突解除后需重新校验」（对应 `drop_staged` 附带删除事实）。

### D5 多位置校验来源显式选择（H4）
聚合视图 `present_in.length > 1` 时，校验前弹出位置选择（默认第一项，列表标注各位置），结果区固定显示「本次校验自「位置名」」。单位置时静默沿用（免打扰）。落点仍是既有 verify API 的 target_id 参数，无接口变化。

### D6 位置健康信号（H5）
「最近推送」列从已加载的 history（位置子结果表，含删除位置的名称快照）按位置名聚合派生：状态点（绿=最近成功/红=最近失败/灰=从未）+ tooltip 显示最近推送与最近测试时间。「最近测试」取该位置最近一次测连接结果（前端已有暂存状态）。不新增后端接口。名称快照与现位置名不一致时以现位置名为准显示、快照仅参与聚合。

### D7 恢复完成闭环（H6 + M13）
成功框内容：① 可复制的重启命令（开发 `develop/linux/start.sh`、生产 `sh stop.sh && sh start.sh`，与 deployment 实际一致）；② 「暂存有效期至 {expires_at}（格式化走 utils/format.ts）」；③ 唯一主按钮「已完成，刷新页面」。附带提醒保留既有「来源标识核对 / 位置可达性核对」文案（主 spec 既有要求）。

### D8 轮询策略（M9）
- 执行期轮询维持现状（5s），失败**静默降级**：状态条内联「刷新失败，正在重试」，不弹 toast；连续失败 ≥3 次停止自动重试、保留手动刷新。
- 兜底轮询：`document.visibilityState === 'visible'` 且无执行中任务时，60s 轻刷 status（不刷 history），让定时备份完成自动反映。

### D9 样式令牌化（M4/L 批）
向导校验明细图标按校验值渲染（✓ 通过 / ✗ 失败），颜色与背景改用主题令牌（`var(--success-color)` 等全站既有变量；无对应令牌时用 AntDV CSS 变量），不再硬编码浅绿，兼容暗色模式。文案「integrity ok」→「完整性校验 通过」。

### D10 历史与向导打通（M8）
历史行加「恢复此包」次级动作 → 打开恢复向导并预选该包（以包名定位聚合列表条目；需先有可用位置来源，手动输入路径不支持预选，按钮仅在已配置位置存在时显示）。向导包列表加「仅最新」过滤与时间排序标识（后端已按时间戳倒序，前端补「最新」徽标即可）。

## Risks / Trade-offs

- [1610 行单组件改动面大，回归风险] → 按批次小步提交；每批跑 `vue-tsc -b` + 相关 vitest；模板多语句 handler 一律提取为 script 函数（约定 #25 教训）。
- [前端字符串分类 reason 脆弱] → 分类函数单点 + 未匹配透传兜底；后端结构化字段列为后续非目标。
- [mock 形状失真导致测试假绿] → 全部 mock 数据形状取自真实响应（约定 #43），关键字段（present_in 数组、expires_at、position 子结果）逐一 curl 核对。
- [低频轮询与执行期轮询叠加] → 互斥：有执行中任务时只用执行期轮询，兜底轮询跳过。
- [「保存并备份」链路中 save 成功但 run 失败] → run 失败按 D3 正常错误路径展示（配置已保存的事实不受影响）。

## Migration Plan

纯前端变更，随前端构建发布即可；无数据迁移、无后端部署依赖。回滚 = 回退前端构建产物。
