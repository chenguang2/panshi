# 备份与容灾页 UX 加固（db-backup-ux-hardening）

## Why

2026-10-01 对「备份与容灾」页（`BackupManagement.vue` → `DbBackupCard.vue` / `DbBackupRestoreWizard.vue` / `DbBackupSummaryCard.vue`）的专业 UX 评审发现：页面骨架已达专业后台水准，但存在 **6 个高危问题（H1–H6）**，全部落在备份容灾产品的信任要害上——编辑态与已保存态互相矛盾、未保存配置可直接执行、恢复执行请求无超时覆盖、多位置校验下载来源不透明、备份可用性（远端健康）盲区、恢复完成后指引断裂。另有 13 个中危（M1–M13）与 8 个低危（L1–L8）一致性问题。这些问题共同侵蚀用户对"备份是否真正可用"的信心，需按 H → M → L 顺序系统性修复。

## What Changes

### 高危批次（H，全部修复）

- **H1 状态口径统一**：状态区「下一轮预计」等所有状态展示改为只读单一数据源（已保存配置 + `status` 接口），与编辑中表单解耦；全页增加「有未保存修改」显式标记（dirty 徽标）。
- **H2 立即备份守卫**：存在未保存修改时点击「立即备份」弹三选确认（保存并备份 / 按已保存配置备份 / 取消）；执行期间按钮锁定并显示耗时预期。
- **H3 恢复执行超时覆盖**：`executeDbRestore` 显式设置超时（覆盖 axios 全局 30s，与 verify 同级或更长）；超时/失败文案明确"后端可能仍在执行，请勿重复点击，先刷新查看"，防止对恢复中的库重复发起恢复。
- **H4 校验来源透明**：「全部位置」聚合视图下校验备份包时，多位置副本不再静默取 `present_in[0]`，显式让用户选择校验来源位置；结果展示"本次校验自「位置名」"。
- **H5 备份可用性信号**：位置表格新增「最近推送 / 最近测试」列（状态点 + tooltip，数据从既有 history 位置子结果聚合派生，无需新后端接口）；健康横幅（或状态区）给出"最近可恢复点 + 存在位置数"摘要，异常时给出第一修复动作。
- **H6 恢复完成闭环**：成功框给出可复制的重启命令（开发/生产两种），按钮语义与文案对齐（不再"建议重启"却只给刷新按钮）；展示 verify 暂存有效期（`expires_at`）。

### 中危批次（M，全部修复）

- **M1** 向导步骤 1 标签「临时远端目标」→「选择备份来源」；**M2** 摘要卡与主卡口径对齐（下一轮显示具体时间、补 `in_progress` 态、`running` 徽章中文）；**M3** 向导关闭确认文案改写（消除"丢失 vs 保留"自相矛盾）；**M4** 校验明细图标按校验值渲染（失败不再绿勾）、`integrity ok` 等中文化、硬编码浅绿改为主题令牌（兼容暗色）；**M5** 历史失败原因行内可展开（不再只靠 hover）、增加状态/触发方式筛选；**M6** 「刷新」在有未保存修改时先确认；**M7** 清空来源标识保存时弹风险确认（说明旧 source 历史包将脱离保留清理）；**M8** 历史行加「恢复此包」入口（打开向导并预选该包）；向导包列表加排序/筛选与「最新」标记；**M9** 立即备份同步等待给出进度预期；状态轮询失败静默降级（内联提示，不弹 toast）；Tab 可见时低频兜底轮询；**M10** 位置「启用」改与全站一致的 toggle，停用时弹确认（容灾降级提示）；**M11** 「恢复向导」「灾难恢复」入口降为次级样式，缓解警示疲劳；**M12** 全局配置保存按钮贴近表单并随 dirty 反馈；**M13** verify 暂存有效期展示（与 H6 合并实现）。

### 低危批次（L，顺手批量清理）

- L1 分页计数去重；L2 行级测试结果条与触发行视觉关联；L3 「测试连接」覆盖范围语义 hint；L4 交互元素键盘可达性；L5 间隔上限提示；L6 摘要卡错误态强化；L7 手输模式密码清除选项；L8 测试补强（保存流程 / 位置 CRUD / 向导三步断言，随各批次 TDD 落地）。

## Capabilities

### New Capabilities

（无——全部行为变更归属既有能力的需求修订。）

### Modified Capabilities

- `sqlite-remote-backup`：修订「备份管理页面与导航」需求——状态区以已保存配置为单一数据源（编辑态隔离 + dirty 标记）、立即备份的未保存守卫、位置表格健康信号列（最近推送/最近测试）、位置停用确认、刷新脏守卫、来源标识清空风险确认、历史筛选与失败原因行内展开、历史→恢复打通、危险入口样式降级、摘要卡口径对齐（具体时间 / in_progress / 中文徽章）、全局配置保存按钮布局与 dirty 反馈。
- `sqlite-backup-restore`：修订恢复链路需求——恢复执行请求超时覆盖与防重复执行文案、多位置校验来源显式选择与结果标注、恢复完成指引闭环（可复制重启命令 + 暂存有效期）、向导步骤 1 改名、关闭确认文案、校验明细按值渲染与中文化、包列表排序筛选与「最新」标记、历史行「恢复此包」预选。

## Impact

- **前端（主体，纯前端修复）**：`frontend/src/components/DbBackupCard.vue`（H1/H2/H5/M2 部分/M5/M6/M7/M9/M10/M11/M12）、`frontend/src/components/DbBackupRestoreWizard.vue`（H4/H6/M1/M3/M4/M8/M13）、`frontend/src/components/DbBackupSummaryCard.vue`（M2/M11）、`frontend/src/api/dbBackup.ts`（H3 超时）、`frontend/src/types/dbBackup.ts`（如需）、`frontend/src/views/DatabaseManagement.vue`（M11 摘要卡入口样式）。
- **测试**：`frontend/src/views/__tests__/BackupManagement.test.ts` 扩展（现有 3 条 → 覆盖保存流程、位置 CRUD、向导三步、H 批次守卫行为）。
- **后端**：不改（H5 从既有 history 位置子结果聚合派生；H3 为前端超时覆盖；轮询复用既有 status/history 接口）。
- **验证**：`npx vue-tsc -b` + `npx vitest run`（含新增用例）；涉及页面为用户实际操作路径，验收须在真实页面上核对（AGENTS.md 约定 #51）。
