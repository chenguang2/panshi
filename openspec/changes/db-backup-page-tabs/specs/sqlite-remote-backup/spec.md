## ADDED Requirements

### Requirement: 备份页分区结构与常驻状态层
「备份与容灾」页 SHALL 采用「常驻状态操作层 + 页内 Tab 内容区」结构：状态四格、错误横幅、立即备份、恢复数据主入口、刷新与「有未保存修改」徽标 MUST 位于常驻层（页内任何 Tab 下可见，sticky 化滚动时不离场）；内容区 MUST 以页内 Tab 分为「备份位置」「策略与保留」「备份历史」三页，默认落在「备份位置」；Tab 切换 MUST NOT 销毁非激活 pane（表单内存态保留），「有未保存修改」时切换 Tab MUST NOT 弹窗拦截，未保存状态的可见性由常驻层徽标承担（点击跳回策略 Tab）；恢复向导 MUST 保持 modal 形态与三入口语义，入口文案统一为「恢复数据」系；Tab 选中状态 MUST NOT 进入 URL。

#### Scenario: 常驻层跨 Tab 可见
- **WHEN** 用户停留在「备份历史」Tab
- **THEN** 状态四格、立即备份按钮、「有未保存修改」徽标（若有）仍在页面常驻层可见可点

#### Scenario: 切换不丢表单态
- **WHEN** 用户在「策略与保留」Tab 修改间隔但未保存，切到「备份历史」再切回
- **THEN** 输入保留原值、dirty 徽标仍显示，无任何内容丢失或拦截弹窗

#### Scenario: 未保存徽标跳回
- **WHEN** 存在未保存修改且用户在「备份历史」Tab 点击常驻层徽标
- **THEN** 页面切回「策略与保留」Tab，表单与徽标可见

#### Scenario: 恢复入口统一命名
- **WHEN** 用户查看常驻层主按钮、历史行内动作与数据库管理页摘要卡入口
- **THEN** 三处均为「恢复数据」系命名（行内保留「此包」指向性），语义上可识别为同一功能的三个入口

#### Scenario: 刷新历史不丢选中状态之外的信息
- **WHEN** 用户在「备份历史」Tab 使用筛选并翻页
- **THEN** 常驻层状态不因筛选/翻页变化，历史 Tab 内容独立响应筛选
