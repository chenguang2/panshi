# 备份页 Tab 化改版（db-backup-page-tabs）

## Why

用户反馈「备份与容灾」页界面比较乱。结构评估（des-1，2026-10-01，实测定位）诊断出三个根因：① 历史区已长成约 600px 的半独立功能块（占整卡 45%+）却被塞在大卡尾部（错放）；② 全局配置表单与位置表是视觉等权的「标题行+按钮」同构单元连排，但语义完全不同（策略参数 vs 资产清单）；③ 状态四格被压到 y=254，运维第一诉求「看状态」要先扫过双重标题，重状态时整页约 2.5 屏长滚动、状态离场。用户已在三个备选中确认选择**方案 B：常驻状态操作层 + a-tabs 三内容页**。

## What Changes

- **常驻状态操作层**（Tabs 组件外侧，任何 Tab 可见，sticky 化）：状态四格、错误横幅、立即备份、恢复数据主入口、刷新、「有未保存修改」徽标（上提至此，点击跳回策略 Tab）。
- **页内 a-tabs 三内容页**：备份位置（默认 Tab）/ 策略与保留 / 备份历史。历史区获得完整纵向空间，配置与位置的语义边界由 Tab 天然分离。
- **不做切 Tab 拦截**：利用 a-tabs 默认不销毁非激活 pane 的特性（v-show 语义）保留表单内存态；dirty 可见性靠徽标上提解决，不做离开确认弹窗。
- **恢复向导保持 modal**：低频高危操作的阻断感是需求；三入口语义不变，文案统一为「恢复数据」系（常驻层主按钮「恢复数据…」/ 历史行内「恢复此包」/ 摘要卡「灾难恢复」→ 同系命名）。
- **不做**：keep-alive、pinia 状态上提、总览 Tab（内容太薄且割裂状态前情）、Tab 状态进 URL、恢复 Tab 化、切 Tab 拦截弹窗。
- 逻辑层零迁移：H1 单一数据源 / dirty 计算 / 轮询 / 健康聚合 / 三选守卫全部留在组件状态层，只挪模板位置。

## Capabilities

### New Capabilities

（无。）

### Modified Capabilities

- `sqlite-remote-backup`：新增「备份页分区结构与常驻状态层」需求——常驻层跨 Tab 可见性（状态/主操作/未保存徽标）、Tab 切换不销毁表单态、默认 Tab、恢复入口统一命名、Tab 状态不进 URL。

## Impact

- **前端**：`frontend/src/components/DbBackupCard.vue`（模板重组 + a-tabs 引入 + 常驻层抽离，逻辑不动）；`frontend/src/components/DbBackupSummaryCard.vue` 与向导相关文案（恢复入口统一命名）。
- **测试**：DbBackupCard 三套共 51 用例逐组回归（预估 5–10 处「跨区可见性」DOM 断言适配）；新增「切走再切回表单保留」回归用例；SummaryCard 深链 `?wizard=1` 回归。
- **后端**：不改。
- **验证**：`vue-tsc -b` + 相关 vitest 全绿 + 真实页面截图验收（Tab 结构/常驻层/切换保态/恢复 modal）。
