# 提案：新增「从零搭建」用户操作手册（docs/new）

## Why

现有 `docs/user-manual.md`（v1.19.0）是按功能模块罗列的参考型手册，存在两个不足：

1. **缺少端到端主线**：新用户面对空系统时，不知道应该先建什么后建什么。网关后台的正确上手顺序（集群 → 节点 → edge.env → 全局规则 → 插件元数据 → 插件组 → 上游 → 路由 → 证书 → 四层代理 → DNS 代理 → 域名验证）散落在各章节中，没有一条完整的实操路径。
2. **缺少选项级解释**：表单中每个字段"是什么、为什么填、填错会怎样"没有系统讲解，用户只能靠猜测。

需要一本以"从一个空系统开始，完整搭建一套可用网关"为主线的场景式操作手册，参考主流网关管理台（APISIX Dashboard / Kong Manager）的 Quickstart + 场景指南风格，让用户照着做即可得到一套能跑通 HTTP(HTTPS)/TCP/UDP/DNS 的演示系统。

## What Changes

- 新增 `docs/new/` 文档目录，存放新版操作手册（Markdown，含截图占位）
- 手册以**演示环境**贯穿全程：
  - 起点为干净的本地 SQLite 空库（通过数据库管理切换到空文件，重启后端生效）
  - 访问地址 `http://localhost:12345/`，默认账号 admin / panshi123
  - 3 个预装节点：192.168.0.13 / 14 / 15，OpenResty 路径 `/work/jboss/uapm/openresty`，Edge 路径 `/work/jboss/uapm/uap-edge`
- 章节顺序（每章统一结构：**本步骤的作用 → 入口 → 字段/选项逐项解释 → 操作步骤 → 发布 → 预期结果与验证方法**）：

| 章 | 内容 | 关键演示点 |
|---|---|---|
| 0 | 登录与界面导览、准备干净 SQLite 环境 | 数据库管理切换空库 |
| 1 | 建立集群 | 集群概念、Edge 管理地址/密钥、连接测试 |
| 2 | 建立节点（192.168.0.13-15） | 服务端口/管理端口/SSH 端口、双路径含义、状态检测 |
| 3 | 修改 edge.env：新增 HTTP 5000(HTTPS)、TCP 8880、UDP 53 | edge.env 与监听端口的关系、https 开关 |
| 4 | 建立全局规则 | 全局规则 vs 路由级插件的区别、执行阶段 |
| 5 | 设置插件元数据 | 元数据 vs 插件配置的区别、schema 校验 |
| 6 | 建立插件组（内置日志插件 log-process 等） | 插件组复用机制、内置插件清单 |
| 7 | 建立上游 | 负载均衡算法、健康检查、目标节点权重 |
| 8 | 建立路由（含高级匹配绑定端口 5000） | URI/Host/Method/vars 高级匹配、绑定端口、优先级 |
| 9 | 根证书与证书：建立根 CA → 生成证书 → 发布 | 国密/Tongsuo、证书与域名绑定 |
| 10 | TCP 四层代理 8880 | 四层 vs 七层、stream 路由 |
| 11 | DNS 代理（UDP 53） | DNS 代理[UDP] 页面、上游 DNS 转发 |
| 12 | 绑定域名并测试访问 | hosts/域名解析、curl 验证 HTTPS/TCP/UDP 全链路 |

- 截图策略：编写时用 Playwright 对可自动到达的页面截图存入 `docs/new/images/`；无法自动化到达的弹窗/中间态用「📷 截图占位：文字描述画面内容」标注，由用户后续补图
- 以上每一步创建后都执行**发布**，并说明发布结果如何确认

## Capabilities

### New Capabilities
- `operation-manual`: 从零搭建场景式用户操作手册，位于 `docs/new/`，覆盖登录、12 个功能章节与全链路验证

### Modified Capabilities
- （无——纯文档变更，不改任何代码行为）

## Impact

- **新增文件**：`docs/new/` 下若干 `.md` + `docs/new/images/` 截图
- **代码影响**：无（不修改前后端代码）
- **环境操作**：编写过程中需将后端切到空 SQLite 文件（如 `data/manual-demo.db`）截图，完成后恢复原数据库配置
- **旧文档**：`docs/user-manual.md` 本次不动；手册稳定后再决定是否替换或归档
- **风险**：低。唯一注意点是演示库切换/恢复期间不要污染现有开发数据
