## ADDED Requirements

### Requirement: 手册位置与格式
操作手册 SHALL 位于 `docs/new/` 目录，使用 Markdown 格式，图片存放于 `docs/new/images/`。

#### Scenario: 目录结构
- **WHEN** 查看仓库 docs/new 目录
- **THEN** 存在手册主入口文件（README 或 index）
- **AND** 各章节为独立 .md 文件或单文件分章结构，均可从目录导航跳转

### Requirement: 从零搭建主线
手册 SHALL 以一个空系统为起点，按固定顺序完整演示搭建一套可用网关：登录准备 → 集群 → 节点 → edge.env → 全局规则 → 插件元数据 → 插件组 → 上游 → 路由（含高级匹配绑定端口）→ 根证书与证书发布 → TCP 四层代理 → DNS 代理 → 域名绑定与全链路验证。

#### Scenario: 章节顺序覆盖
- **WHEN** 阅读手册目录
- **THEN** 覆盖上述全部 13 个阶段（0-12 章），顺序与提案一致
- **AND** 每个资源创建后都有对应的「发布」操作说明

#### Scenario: 全链路验证闭环
- **WHEN** 用户完成第 12 章
- **THEN** 能够通过域名以 HTTPS 访问第 8 章创建的路由
- **AND** 能够验证 TCP 8880 与 UDP 53 的四层/DNS 代理连通性

#### Scenario: 本机操作与平台操作区分
- **WHEN** 章节涉及读者本机的操作（如第 12 章修改 hosts 把 demo.panshi.local 指向节点 IP）
- **THEN** 明确标注该操作发生在读者电脑而非平台界面
- **AND** 给出 Windows 与 Linux/macOS 两种 hosts 修改方法

### Requirement: 每章统一结构
每个功能章节 SHALL 遵循统一结构：本步骤的作用 → 页面入口 → 字段/选项逐项解释 → 操作步骤 → 发布 → 预期结果与验证。

#### Scenario: 选项级解释
- **WHEN** 某章节介绍一个含表单的创建操作
- **THEN** 表单中每个字段都有名称、含义、演示值、填写注意事项
- **AND** 高风险操作（如清空目标库、删除）有明确警告说明

### Requirement: 截图规范
手册 SHALL 在关键界面处配截图；无法自动截取的画面 SHALL 使用带文字描述的占位标注，便于后续人工补图。

#### Scenario: 截图存在性
- **WHEN** 章节涉及页面操作
- **THEN** 使用相对路径引用 docs/new/images/ 下的截图
- **AND** 未补图的位置使用「📷 截图待补充：<画面描述>」格式占位

### Requirement: 演示环境一致性
手册中的示例值 SHALL 与演示环境一致：节点 192.168.0.13-15、OpenResty 路径 /work/jboss/uapm/openresty、Edge 路径 /work/jboss/uapm/uap-edge、HTTP 5000(HTTPS)、TCP 8880、UDP 53。

#### Scenario: 示例值可复现
- **WHEN** 用户按手册示例值逐章操作
- **THEN** 各章产物之间能够相互引用（路由引用上游/插件组/证书等）
- **AND** 第 12 章验证命令可直接复制执行

#### Scenario: 软件预装与平台记录分离
- **WHEN** 手册描述演示节点 192.168.0.13-15
- **THEN** 明确说明节点机器上已预装 OpenResty/Edge 软件（系统级前提，非平台操作）
- **AND** 空库起点下平台内无任何节点记录，需按第 2 章重新录入

### Requirement: 环境前置与功能门控核对
手册 SHALL 在第 0 章提供「功能开关前置检查」，集中列出受 feature 门控的菜单项及对应的 features.yaml 开关名。

#### Scenario: 门控菜单核对
- **WHEN** 某章节对应的菜单项在侧边栏不可见
- **THEN** 读者可在第 0 章「功能开关前置检查」总表中查到该菜单项对应的 features.yaml 开关名与开启方法
- **AND** 总表覆盖全部受门控入口（如 SSL 证书、DNS代理[HTTP]、数据库管理等）

### Requirement: 发布失败的统一排错指引
搭建篇 SHALL 在第 1 章（首次执行发布处）提供「发布失败排查」小节，后续章节的发布失败说明 SHALL 引用该小节而非重复展开。

#### Scenario: 排错入口唯一
- **WHEN** 任一章节的发布操作失败（如节点不可达、管理密钥错误、服务异常）
- **THEN** 该章节给出简短失败说明并引用第 1 章的排查清单
- **AND** 排查清单覆盖网络连通性、管理密钥、Edge/OpenResty 服务状态三类常见原因

### Requirement: 进阶与运维篇覆盖剩余菜单项
手册 SHALL 包含进阶与运维篇（第 13-22 章），覆盖左侧菜单中从零搭建主线（0-12 章）未涉及的其余全部入口：概览、静态资源、DNS 代理[HTTP]、统一管理、指标查询、指标总览、插件开关、用户管理、数据库管理（完整功能）、Edge 直连、数据导入、工具箱、自启动管理、节点任务。

#### Scenario: 菜单项全覆盖
- **WHEN** 对照侧边栏五个分组（核心功能/边缘网络/综合/系统管理/运维管理）核对手册目录
- **THEN** 每个菜单项都能映射到至少一个章节（0-22 章）
- **AND** 第 13-22 章与菜单项的对应关系为：13 概览、14 静态资源、15 DNS代理[HTTP]、16 指标总览+指标查询、17 统一管理、18 插件开关、19 用户管理、20 数据库管理、21 Edge直连+数据导入、22 工具箱+自启动管理+节点任务

#### Scenario: 运维篇结构一致
- **WHEN** 阅读第 13-22 章任一章节
- **THEN** 遵循与搭建篇相同的统一结构（作用 → 入口 → 字段解释 → 操作 → 发布/生效 → 验证）
- **AND** 高风险操作（数据库迁移清空目标库、自启动 root 凭据、删除连接等）有明确警告说明

#### Scenario: 与演示环境衔接
- **WHEN** 进阶与运维篇涉及资源对象（静态资源、DNS 查询规则等）
- **THEN** 示例值沿用演示环境的节点与域名约定，可复用第 1-12 章产物
- **AND** 仅查看型页面（概览、指标总览）说明数据来源与刷新机制，不要求构造前置数据

#### Scenario: 数据导入隔离练习
- **WHEN** 第 21 章演示数据导入
- **THEN** 章节开头警告应使用独立空库练习（切库步骤引用第 20 章），避免污染手工搭建的演示库
- **AND** 讲解冲突检测机制（uuid 冲突提示「已存在」时的跳过/处理方式）

#### Scenario: 看板分工边界
- **WHEN** 阅读第 13 章（概览）与第 16 章（指标总览/查询）
- **THEN** 第 13 章定位为健康速览（集群/节点状态、快捷入口，运维视角），第 16 章定位为流量指标分析（性能视角）
- **AND** 两章开头互相引用对方并说明分工

#### Scenario: DNS[HTTP] 前置依赖
- **WHEN** 第 15 章演示 DoH 查询规则
- **THEN** 标注前置依赖：需先完成第 8 章路由与第 9 章证书
- **AND** 使用 demo.panshi.local 域名发起 DoH 请求验证，复用主线产物

#### Scenario: 指标数据前提
- **WHEN** 第 16 章展示指标页面
- **THEN** 开头「数据前提」小节说明指标来自 Edge 采集器上报 ClickHouse，需节点在线且采集正常
- **AND** 无数据时给出排查清单（节点状态 → 采集器 → ClickHouse）

#### Scenario: root 凭据安全表述
- **WHEN** 第 22 章演示自启动管理
- **THEN** root 密码使用占位符 <root-password> 表示，不出现真实凭据
- **AND** 说明凭据仅本次使用、不保存的机制
