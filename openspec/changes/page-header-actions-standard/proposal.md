# Proposal

## Why

各页面页头右侧的动作区（`.page-header-actions`）是全站被反复复制、但从未被规范化的地方。`proposal-c` 的 20 张设计页里 14 张带页头动作区，实现侧 22 个页面有动作区，两侧在四件事上已经漂移：

1. **图标**：设计页的「新建/添加/导入/生成」类按钮全部带 13px 线性图标，实现侧只有「节点管理 · 批量导入」一处带图标（统一管理/集群管理已于 central-management-parity r1 补齐），其余仍是纯文字。
2. **文案前缀**：实现侧同一语义出现三种写法——`+ 添加节点`、`＋ 创建 CA 根证书`、`生成证书`（无前缀）。
3. **布局**：`ServerCertList.vue` 用按钮 inline `margin-left: 8px` 制造间距，而容器本身已有 `gap`。
4. **按钮集**：设计页与实现的动作集在 3 个页面互不一致（静态资源/插件元数据：实现有「批量管理」设计页没有；插件元数据：设计页有「插件开关」实现没有；CA 证书：设计页有「查看安装指引」实现改成了页内折叠面板；服务器证书：设计页三颗、实现一颗，另两颗在页面横幅里）。

结果是：设计页不能当完整基线用（parity 每轮都会被这些差异反复打扰），实现侧同类按钮观感也不统一。

## What Changes

- **定一份页头动作区规范**（本变更 design.md D1–D9）：范围、数量与主次、文案、图标白名单、顺序、布局、权限、窄屏、设计页与实现的一致性约束。
- **按规范收口实现侧 12 个页面的页头动作区**（见 tasks 的逐页清单）：补图标、去 `+`/`＋` 前缀、去 inline margin；按钮集冲突按裁决表处理。
- **回填设计页**：把实现的「批量管理」「刷新」等设计页缺的元素补进对应 HTML，把设计页有、但实现已另置（如「前往 CA 根证书下载」在横幅、CA 安装指引在页内折叠面板）的条目按裁决处理，使两侧一一对应。
- **加两道守卫**：实现侧源码守卫（无 `+`/`＋` 前缀、每页 primary ≤ 1、页头按钮禁 inline margin、按钮必须带白名单图标）+ parity 脚本核对设计页与实现按钮集一致。

## Capabilities

### New Capabilities

- `page-header-actions`：页面级动作区的唯一形态规范——它承载什么、放几颗、谁主谁次、怎么配图标、按什么顺序、设计页与实现如何保持一一对应。

## Impact

- 前端：`components/PageHeader.vue`（如需追加动作区容器规则）、`components/StrokeIcon.vue`（如需补图标）、12 个页面视图的 `#actions` 模板、`style.css`（若需页头动作区级规则）。
- 设计页：`docs/ui/Live-Artifact-5/proposal-c/` 下 12 张 HTML 的 `<div class="page-header-actions">`。
- 测试：新增源码守卫用例；既有页面测试中凡断言按钮文案（含 `+ ` 前缀）者需反转（#217）。
- 后端：零改动。
