## 一、节点管理

### 1.1 用户项①：选中行颜色比设计页浅

| 量测（1600×1000，同浏览器） | 设计 | 实现 |
|---|---|---|
| 选中行 `td` 背景 | `oklch(0.56 0.16 210 / 0.08)` | `oklch(0.56 0.16 210 / 0.08)` |
| 令牌 `--accent` | `oklch(56% 0.16 210)` | `oklch(56% 0.16 210)`（`theme.css` 两侧逐字相同） |
| 卡片底 `--surface` | `oklch(100% 0 0)` | 同 |

→ **本机实测完全一致**（同色值、同透明度、同底色 → 合成结果相同），不可复现「更浅」。

### 1.2 用户项②：行 hover 颜色比设计页浅

| 量测 | 设计 | 实现 |
|---|---|---|
| hover 行 `td` 背景 | `oklch(0.56 0.16 210 / 0.04)` | `oklch(0.56 0.16 210 / 0.04)` |
| 选中行 hover 时 | 选中态优先（8%） | 选中态优先（8%，选择器多一个类） |

→ 同样**逐值一致**。

### 1.3 可能原因（需你确认）

三个可能，按概率排序：
1. **页面是改动前的旧渲染**（硬刷新可排除；前两轮也出现过同类误报——胶囊、上游滚动条）。
2. **浏览器缩放不同**：应用页若被缩到 90%（看列多时常见），半透明叠色在非整数像素下会显得更淡；设计 HTML 在新标签页通常 100%。自查：`Ctrl/Cmd+0` 复位后对比。
3. **对比的是不同行/不同状态**：设计页第 1–2 行是「选中 + 已勾选」，且设计页 `tbody tr:hover td` 与 `tr.row-selected td` 两条规则叠在同一行时，选中优先——与实现一致。

**若你确认「同条件、100% 缩放、硬刷新后仍更浅」**：那就不是还原偏差，而是基准要加深（选中 8% → 12%、hover 4% → 6%，三份设计页同步改）。**需你裁决，默认不做。**

## 二、上游管理

### 2.1 用户项①：目标节点与健康列要按设计页重建（真实缺陷）

**现状**（`UpstreamList.vue:130-137`）：一行一个 chip，仅 `ip:port` + 「· 权重 100」，无状态点、无权重条、无占比、无汇总。
**设计**（`upstreams.html` `.tg-list`）：

| 元素 | 设计解剖 |
|---|---|
| 列表 | `.tg-list`：纵向 flex、`gap 4px`、`align-items:flex-start` |
| 目标胶囊 | `.tg-chip`：inline-flex、`gap 6px`、`padding 2px 8px`、圆角 999、底 `var(--bg)`、边框 1px `var(--border)`、**mono 11px** |
| 状态点 | 6px 圆点：`.d-ok` success / `.d-warn` warning / `.d-off` danger |
| 权重条 | `.tg-bar` 44×4、圆角 2、底 `oklch(50% .018 240/15%)`，内条 `i` = accent、宽度 = 占比 |
| 权重文案 | `.tg-w`「`权重 · 占比%`」、muted（例：`80 · 44%`） |
| 汇总行 | `.tg-sum`：11px muted、「`N 目标 · 全部健康`」（数字/结论 600）；异常时「`1 项待验证`」用 warning 600 |

**阻塞点（必须先裁决）**：**平台没有目标级健康数据**。后端 `UpstreamTarget` 只有 `{target, weight}`（实测 `GET /clusters/1/upstreams` 返回 `targets:[{target,weight}]`，无健康字段），Edge 侧健康需另行拉取。因此「点颜色 + 剔除不健康再算占比 + 全部健康」**无法如实实现**。三个方案：

| 方案 | 做法 | 健康来源 | 占比口径 | 代价 |
|---|---|---|---|---|
| **A（推荐本轮）** | 视觉完全照设计：点 / 条 / 占比 / 汇总都在；**健康用上游发布态近似**——已发布且上次发布成功 = 绿点「全部健康」；待发布 / 未发布 / 部分失败 = 警示点 + 「N 项待验证」 | 上游发布态（现成） | 全部目标权重（无目标级健康可剔除） | 前端 1 处模板+计算，零后端 |
| **B（若你要真实的逐目标健康）** | 后端新增「查询上游目标健康」端点（Edge healthcheck，经 `EdgeClient` + 中继感知），前端按真实健康上色、**占比只算健康目标** | Edge 实时 | 剔除不健康 | 后端新端点 + 缓存/超时 + 权限/审计 + 测试；另立变更 |
| C | 全部按「未采集」呈现：中性灰点 + 汇总「N 目标 · 健康未采集」 | 无 | 全部目标 | 最小，但达不到你要的「全部健康」观感 |

**占比算法（A/B 通用）**：`pct = round(weight / 有效权重和 × 100)`，条宽 = pct%；A 方案有效 = 全部目标，B 方案有效 = 健康目标（不健康目标条宽 0、占比显示「—」）。

### 2.2 用户项②：重置列宽后横向滚动条 + 提示行图标

| 子项 | 实测（r6 已改） | 结论 |
|---|---|---|
| 三页表格宽度自适应 | 1600 / 1536 / 1440 / 1366 四档：表格 = 卡片宽、**溢出 0**；1440 实点「重置列宽」后仍 0 | 已在 r6 修复 |
| 提示行图标 | 三页均为 `.pop-hint-line` + 13px 双向箭头图标（`StrokeIcon resizeH`） | 已在 r6 补上 |
| ≤1280 视口 | 上游卡片 990 < 最小总宽 1054 → 仍溢出 64px（节点 86 / 路由 46） | 若你的窗口 ≈1280，这就是你看到的那条滚动条 |

**可选加固（建议做）**：把「最小总宽」从设计值（1076/1054/1036）下探为**列内容下限之和**（≈600 + 选择列 40），即只要窗口 ≥ 约 1000px 就**永不出现横向滚动**；低于此值才滚动。代价：窄窗下安装路径列更早出现省略号。
