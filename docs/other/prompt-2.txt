# 审查维度与检查清单

## 1. 功能完整性与边界情况- 是否存在未实现的需求或遗漏的业务逻辑？- 输入验证是否覆盖了边界值（空值、超长字符串、特殊字符、负数等）？- 分页、排序、筛选功能是否处理了空数据和大数据量情况？- 表单提交是否有防重复提交机制？- 删除、修改等敏感操作是否有二次确认或权限校验？
## 2. 安全性隐患- **后端**：  - 是否存在 SQL 注入、命令注入风险？  - 敏感信息（密码、Token、密钥）是否加密存储？是否硬编码在代码中？  - CORS 配置是否过于宽松（如生产环境使用 allow_origins=["*"]）？  - 接口是否有适当的速率限制（Rate Limiting）？  - JWT Token 是否有过期时间和刷新机制？- **前端**：  - 是否存在 XSS 风险（如滥用 v-html）？  - Token 存储是否安全（localStorage vs httpOnly Cookie）？  - 路由守卫是否正确配置，防止未授权访问？
## 3. 错误处理与健壮性- 后端是否统一了异常处理，避免将堆栈信息直接暴露给前端？- 前端 Axios 拦截器是否正确处理了 401、403、500 等常见错误码？- 异步请求是否有 try-catch 或 .catch() 处理，防止页面卡死？- 是否存在未处理的 Promise 拒绝？## 4. 性能与效率- 后端是否存在 N+1 查询问题？数据库索引是否合理？- 是否混用了同步和异步代码（如在 async 函数中使用同步数据库调用）？- 前端是否存在不必要的重渲染？大列表是否使用了虚拟滚动？- 静态资源是否进行了压缩和缓存优化？
## 5. 架构与代码规范- 前后端职责是否清晰？（前端不应包含核心业务逻辑）- API 接口设计是否符合 RESTful 规范？- 代码是否存在重复逻辑？是否遵循 DRY 原则？- 变量、函数命名是否语义化？
