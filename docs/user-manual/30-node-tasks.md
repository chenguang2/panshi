# 30. 节点任务

> 面向多集群的节点级运维任务中心：安装、升级、启停、状态查询、软件查询、命令执行、文件分发，全部在一个台账里可筛选、可追踪、可取消、可重试。

## 30.1 页面入口

左侧侧边栏：【运维管理】→【节点任务】。

> 若菜单不可见：回[第 1 章 功能开关前置检查](01-login.md)核对 `task_center` 开关；同时确认当前账号拥有「节点任务」权限。

## 30.2 任务列表

![任务列表](images/30-01-task-list.png)

### 30.2.1 列表各列

| 列 | 说明 |
| --- | --- |
| # | 行序号（跨页连续，与分页联动） |
| 任务类型 | 安装 OpenResty / 安装 Edge / 启动 / 停止 / Reload / 状态查询 / 软件查询 / 命令执行 / 分发文件等 |
| 集群 | 任务所属集群。集群已删除时显示 `—` |
| 结果 | 任务结论区：状态标签 + 成功/失败计数 + 进度条 + 失败原因摘要 |
| 时间 | 结束时间与耗时；未结束的任务显示「进行中 · 已用时 x」 |
| 操作 | 【详情】直达任务详情页；【⋯】含取消 / 重试 / 删除 |

> 💡 鼠标悬停「任务类型」可看到任务编号与发起人；悬停「时间」可看到创建时间。

### 30.2.2 「结果」列怎么读

「结果」列把一个任务的三件事放在一起，自上而下是：**状态 → 规模 → 原因**。

| 元素 | 含义 |
| --- | --- |
| 状态标签 | 待执行 / 执行中 / 取消中 / 成功 / 部分成功 / 失败 / 已取消 |
| 计数 | 成功 x · 失败 y（有跳过/取消时追加「跳过 z」「取消 w」） |
| 进度条 | 分段显示构成：<br>绿 = 成功段，红 = 失败段，灰 = 跳过/取消段，蓝条纹 = 仍在执行 |
| 原因摘要 | 仅失败/取消任务出现，如「3 台节点不在 Ansible 主机清单中」 |

> 💡 **失败任务一定有红段**。如果一条任务显示失败却看不到红段，说明该页数据未刷新，点【刷新】即可。
>
> 💡 「部分成功」为琥珀色，与「失败」的饱和红 + 细红框在颜色与形状上都不同，不必靠颜色深浅去猜。

### 30.2.3 筛选与搜索

筛选条从左到右：

| 控件 | 说明 |
| --- | --- |
| 搜索框 | 支持**任务编号**、**节点 IP**、**命令关键字**。输入后按回车生效 |
| 全部集群 | 按集群过滤（跨集群统一视图） |
| 全部状态 | 待执行/执行中/成功/部分成功/失败/已取消/跳过 |
| 全部类型 | 按任务类型过滤 |
| 全部时间 | 全部时间 / 近 24 小时 / 近 7 天 / 近 30 天（按创建时间） |
| 刷新 | 手动刷新列表 |

### 30.2.4 批量操作与空态

- 勾选任意行后，筛选条下方出现批量工具条：`已选 N 项`、【批量删除】、【取消选择】。
- **执行中/待执行的任务不可勾选**（勾选框置灰），避免误删。
- 空态分两种：没有任何任务时提示「还没有节点任务」并提供【新建任务】；筛选后无结果时提示「没有符合条件的任务」并提供【清空筛选】。

> 💡 列表在存在执行中/待执行任务时每 3 秒自动刷新；筛选条件在刷新与翻页后保持。

## 30.3 新建任务

点击页头右上角【＋ 新建任务】。

### 30.3.1 必填与校验

![新建任务的必填与就地校验](images/30-02-create-empty.png)

- 带红色 `*` 的字段为必填。
- 字段失焦即校验，错误直接显示在字段下方并给输入框红框，不需要提交才发现。
- 底部会实时提示还缺什么（如「还需选择集群、选择任务类型」）。
- 必填项未补齐时【创建】按钮为灰色不可点，鼠标悬停会提示还缺哪些内容。

### 30.3.2 选择集群与节点

1. **集群**：从下拉框选择目标集群。
2. **节点**：选定集群后列表加载该集群全部节点。
   - 顶部搜索框可按 IP / 名称过滤，节点多时用它找人。
   - **离线节点不可勾选**（置灰并标注「离线」），避免把任务投给连不上的机器。
   - 支持【全选】（自动跳过离线节点）与【取消全选】；右侧显示 `已选 x 个（共 y）`。

> 💡 选中集群或切换集群后，安装包/版本包等下拉会自动按新集群重新加载，无需切换任务类型。

### 30.3.3 选择任务类型

| 类型 | 说明 | 额外必填 |
| --- | --- | --- |
| 安装 OpenResty | 安装 OpenResty 运行环境（两阶段执行） | 安装包 |
| 安装 Edge | 安装 Edge 服务 | — |
| 关联新 OpenResty | 将 Edge 重新关联到新的 OpenResty 实例 | — |
| 升级 Edge(传包) | 上传版本包升级 | Edge 版本包 |
| 升级 Edge(切版本) | 切换到已上传的某个版本 | 目标版本 |
| 启动 / 停止 / Reload | 启停或重载 Edge 服务 | — |
| 状态查询 | 查询 Edge 服务运行状态 | — |
| 软件查询 | 查询节点上指定软件是否安装及版本 | 软件列表 |
| 命令执行 | 在节点执行自定义命令或脚本 | 命令/脚本、执行策略 |
| 分发文件 | 把文件分发到节点指定目录 | 源文件、目标目录 |

每个类型下方都有一行说明该类型的行为，例如命令执行会提示「命令将以清单中的用户身份在各节点执行；执行明细见任务详情」。

### 30.3.4 命令执行

![命令执行表单](images/30-03-create-cmd.png)

支持两种模式，切换按钮在任务类型下方：

**命令模式**

| 字段 | 说明 |
| --- | --- |
| 命令 | 要执行的 shell 命令，右侧【复制命令】可复制当前内容 |
| 执行策略 | 黑名单：拦截危险命令（默认）<br>白名单：只允许预置只读命令 + 本任务添加的命令<br>不限制：不做校验 |
| 超时 | 命令超时时间，默认 30 秒 |

**脚本模式**

| 字段 | 说明 |
| --- | --- |
| 脚本文件 | 支持 `.sh` / `.bash`，最大 512KB；可直接上传，或从【暂存文件】中选择 |
| 脚本内容 | 上传后自动载入编辑区，可在线修改；**执行的就是编辑区内容** |
| 执行策略 / 超时 | 同命令模式 |

> 💡 脚本通过 SSH 以 base64 管道传输到节点执行，不经落地文件中转。
>
> 💡 脚本模式下的【转换为命令】会生成等价的 `echo '<base64>' | bash` 命令并复制到剪贴板，便于在别处复现。

### 30.3.5 分发文件

| 字段 | 说明 |
| --- | --- |
| 选择文件 | 任意类型，最大 10MB；可直接上传或从【暂存文件】中选择 |
| 目标目录路径 | 节点上的目录，如 `/etc/nginx/conf.d/` |
| 超时时间 | 默认 10 分钟 |

> 💡 节点上落地文件名 = 目标目录 + 原始文件名。分发进度与逐节点结果在任务详情中查看。

### 30.3.6 软件查询

可勾选预置软件（默认全选），也可手动输入自定义软件名；至少选择一项。任务完成后在详情页以「软件 × 节点」矩阵展示结果。

### 30.3.7 创建

点击【创建】后任务立即进入执行队列，页面会**直接跳转到该任务详情页**，在那里看进度与日志。

## 30.4 任务详情页

在列表点击【详情】或整行任意位置，进入独立详情页（地址形如 `/node-tasks/12`，可收藏、可刷新、可分享给同事）。

![任务详情](images/30-04-detail.png)

### 30.4.1 结论区（先看这里）

页面最上方回答三个问题：

1. **成没成**：状态标签 + 成功/失败计数 + 分段进度条。
2. **为什么**：失败原因摘要，如「1 台节点不在 Ansible 主机清单中」。
3. **下一步**：一行处理建议，如「建议：确认节点已加入 Ansible 主机清单后重试」。

> 💡 建议只在有失败/取消时出现；全部成功时不占位。

### 30.4.2 上下文行

集群、发起人、创建时间、开始时间、结束时间、耗时；任务被取消过时额外显示取消请求时间。

### 30.4.3 节点结果

| 列 | 说明 |
| --- | --- |
| 节点 | IP 与节点上的路径标识 |
| 状态 | 该节点的执行状态（成功/失败/取消中/已取消…） |
| 返回码 / 原因 | 有归因时显示中文原因（悬停看全文），没有时显示返回码（0 = 成功） |
| 耗时 | 该节点耗时 |
| 操作 | 【查看日志】打开日志抽屉 |

重试过的节点会标注「已重试 N 次」。

### 30.4.4 任务参数

先给关键参数的 key-value 摘要（命令、执行策略、超时、目标目录、安装包等），下方【原始参数】可展开完整 JSON 并一键复制。

### 30.4.5 日志抽屉

![日志抽屉](images/30-05-detail-log.png)

点击节点行的【查看日志】，右侧打开抽屉：

| 元素 | 说明 |
| --- | --- |
| 页签 | stdout / stderr / 命令 / 实时日志 |
| 拖拽把手 | 抽屉左缘可拖动调宽（420px ~ 视口宽度） |
| 下载本次日志 | 下载该节点本次执行的日志文件 |
| 查看历史尝试 | 该节点重试过时出现，可回看第 1 次、第 2 次……的日志 |
| 实时徽章 | 任务仍在执行时显示，日志随执行滚动 |

> 💡 执行中的任务日志自动追加，无需刷新；日志过长时文件会保留前 5000 行并在末尾标注「已截断」。
>
> 💡 历史任务或该节点确实没有输出时，显示「该任务没有执行日志（历史任务或未产生输出）」。

### 30.4.6 页头操作

| 按钮 | 出现条件 | 行为 |
| --- | --- | --- |
| 返回列表 | 始终 | 回到列表，**筛选条件与页码保持不变** |
| 导出日志 | 始终 | 打包下载本任务所有节点的日志（zip，按 IP 分目录） |
| 取消 | 待执行/执行中 | 中断任务，详见 30.5.1 |
| 重试失败节点 | 失败/部分成功/已取消 | 只重跑失败/取消的节点 |
| ⋯ → 删除任务 | 始终 | 删除任务记录与日志（不可恢复） |

## 30.5 任务操作

### 30.5.1 取消

对**待执行**或**执行中**的任务点击【取消】：

1. 任务立即进入「取消中」，并记录取消请求时间。
2. 系统会终止正在运行的执行进程（含 Ansible 播放与脚本 SSH 进程），节点上的命令随之被中断，不会「界面已取消、机器还在跑」。
3. 已执行完成的节点保持「成功」不变，被中断的节点记为「已取消」并注明「任务已被取消，执行已中断」。
4. 全部未完成时任务状态为「已取消」；部分已完成时为「部分成功」。

> ⚠️ **取消不是回滚**：对于安装、升级、启停这类改动型任务，取消只能让执行停下来，**节点上已经发生的改动不会自动恢复**。取消后请查看节点结果与日志，确认是否需要手工修复或重新执行。

> 💡 已结束的任务点【取消】不会有任何副作用（不会出现「取消中」假象）。

### 30.5.2 重试

对失败/部分成功/已取消的任务点【重试】：

- 只重新执行失败与被取消的节点，已成功的节点不会重复执行。
- 重试前会二次确认，提示将重跑的失败/取消节点数量。
- **上一次的日志不会被删除**：它会被归档为该节点的「第 N 次尝试」，在日志抽屉的【查看历史尝试】里可回看；当前日志从头开始记录。

> ⚠️ 只有终态任务可重试。任务仍在执行时点重试会被拒绝（提示「任务仍在执行中，请先取消或等待结束」）。

### 30.5.3 删除

对已完成的任务点【⋯】→【删除任务】，确认后删除任务记录与日志文件（不可恢复）。

支持批量删除：勾选多行后点【批量删除】。执行中/待执行的任务会被自动跳过，并在结果提示中告诉你跳过了几个。

## 30.6 文件管理

### 30.6.1 暂存文件

筛选条右端的【暂存文件】打开弹窗，管理「已上传但尚未用于任务」的临时文件：

- 脚本文件（`.sh` / `.bash`）：供命令执行的脚本模式选用
- 分发文件（任意类型）：供分发文件任务选用
- 创建任务时会自动迁入该任务目录，并从此处消失；也可手动删除不再需要的文件

![暂存文件](images/30-06-staged-files.png)

> 💡 创建任务时也可以直接上传，无须事先到【暂存文件】。

### 30.6.2 任务源文件

筛选条右端的【任务源文件】打开弹窗，展示各任务创建时迁入任务目录的**控制端副本**：

- 只包含控制端副本，**不包括**已分发到节点上的文件
- 可按任务与文件名查看、删除
- 删除只清除控制端副本，不影响任务记录，也不影响节点上的文件

![任务源文件](images/30-07-task-files.png)

## 30.7 失败归因速查

任务失败时系统会自动给出中文原因，常见几类与处理方式：

| 归因文案 | 含义 | 处理 |
| --- | --- | --- |
| 节点 x.x.x.x 不在 Ansible 主机清单中 | 该节点未写入 `inventory/host` | 在【Ansible 主机清单】中补充该节点 SSH 连接信息 |
| 节点 x.x.x.x 无法连接 | 网络不通或 SSH 端口被拦 | 检查节点网络、SSH 服务与端口 |
| 节点 x.x.x.x SSH 认证失败 | 用户名/密码/密钥不对 | 检查清单中的账号密码或免密配置 |
| 节点 x.x.x.x 执行超时 | 命令超过设定时限 | 调大超时或优化命令 |
| 命令含黑名单/不在白名单 | 执行策略拦截 | 改用合规命令，或在白名单中补充命令 |
| 节点 x.x.x.x 权限不足 | 目标操作需要更高权限 | 确认执行用户权限 |
| 任务已被取消，执行已中断 | 用户主动取消 | 见 30.5.1 |

> 💡 归因只是结论，具体现场看该节点日志（详情页【查看日志】）。

## 30.8 常见问题

| 现象 | 处理 |
| --- | --- |
| 任务一直「待执行」 | 确认后端服务正常；并发执行有上限（默认同时 5 个 playbook），排队属正常 |
| 状态查询返回权限不足 | 检查清单中该节点的 SSH 用户权限 |
| 重试按钮不可点 | 只有失败/部分成功/已取消的终态任务可重试 |
| 点了取消，状态还是「取消中」 | 执行进程正在收尾（通常几十毫秒到数秒），刷新后应转为「已取消」 |
| 取消后节点状态异常 | 取消不回滚已发生的改动，按 30.5.1 的提示检查并重新执行 |
| 批量删除提示「跳过 N 个」 | 执行中/待执行任务不可删除，属预期 |
| 脚本上传失败 | 检查扩展名（仅 `.sh`/`.bash`）与大小（≤512KB） |
| 日志只显示到某一行就断了 | 单节点日志保留前 5000 行并标注截断；完整内容以节点现场为准 |
| 找不到某条历史任务 | 用搜索框按任务号/IP/命令关键字找；时间范围默认「全部时间」 |

## 30.9 本章小结

- 节点任务是运维操作的统一台账：列表 6 列，先看「结果」列——状态、规模、原因一眼读完。
- 新建任务按「集群 → 节点 → 类型 → 参数」填写，必填有 `*`、错误就地提示、缺什么一眼可见。
- 详情是独立页面：结论区先回答「成没成 / 为什么 / 下一步」，日志在可拖拽抽屉里读，不再挤在弹窗中。
- 取消会真正终止执行进程，但**不回滚已发生的改动**；重试只补失败节点，并保留上一次日志。
- 文件分两层：暂存文件（尚未用于任务）与任务源文件（控制端副本），都只影响控制端。
- 失败优先看归因摘要，再点进节点日志定位现场。
- 升级类任务建议逐台执行并观察，避免全量同时升级。
