# 附录 E　集群配置漂移检测

> 附录 E（需更新截图：集群卡片漂移检测入口 / 结果抽屉三态 / 字段级差异展开）
>
> 适用场景：怀疑有人在平台之外直接改了 Edge 网关的配置（运维 curl/脚本、其他系统），想知道「线上跑的」和「平台发布的」是否还一致。漂移检测回答三个问题：**哪些资源一致、哪些被改过（改了什么）、哪些无法判断（为什么）**。

## E.1 它是什么与三态结论

漂移检测 = 「**平台最后一次真正发到 Edge 的配置**（发布快照基线）」与「**Edge 当前运行态**」的逐字段对比。每次发布成功时，平台会把实际发给 Edge 的载荷随版本快照留痕；检测即以这份不可变基线为准，只读对比，不改任何数据。

逐资源给出三态结论：

| 结论 | 含义 |
| --- | --- |
| **一致** | Edge 运行态与基线逐字段等价 |
| **漂移** | Edge 与基线不一致——字段被改（含字段级差异表）、资源在 Edge 被删、或 Edge 多出平台无记录的旁路资源 |
| **无法评估** | 该资源没有可比对的基线或读不到 Edge（原因见 A.2） |

> 💡 检测为**纯只读**：不写库、不写 Edge，随时可点，不影响发布与流量。

## E.2 前置条件与「无法评估」的原因

| 原因 | 含义 | 怎么消除 |
| --- | --- | --- |
| 未发布过（无版本快照） | 资源从未经平台发布过 | 发布一次即建立基线 |
| 基线缺失：该快照不含实发载荷（旧版本） | 最后一次发布发生在「实发载荷留痕」功能上线之前 | 对该资源**重新发布一次**即建立基线 |
| Edge 读取失败 | 节点不可达 / 连接失败 / 中继白名单未下发 | 修复连通性（经中继场景与发布同通道）；仅该资源降级，不影响其余资源 |

> ⚠️ 「无法评估」**不是「一致」**——平台宁可说无法判断，也不把真漂移藏起来。

## E.3 操作步骤

前置条件：目标集群有至少 1 个活跃节点；待检测资源已在平台发布过（有基线）。

1. 进入集群卡片所在页（【集群管理】或【统一管理】）；
2. 点击卡片操作区的【**漂移检测**】按钮（【连接测试】与【编辑】之间）；
3. 等待检测完成（抽屉顶部显示汇总计数：一致 / 漂移 / 无法评估 + 检测时间）；
4. 结果按资源类型分组列出（路由 / 上游 / 插件组 / 全局规则 / 插件元数据 / SSL 证书 / 四层·DNS 代理）；
5. 漂移项点击【展开差异】，查看字段级三列表：**字段路径 / 基线（发布值）/ Edge 运行态值**；「（Edge 已无此字段）」表示基线有、Edge 被删；
6. 需要复核时点【重新检测】（每次都实时读取 Edge，不缓存旧结论）。

**结果反馈示例**：

- 漂移 · 节点 `192.168.0.14` 与基线不一致（`192.168.0.15` 一致）——差异表 `plugins.data_center: {} → {"a":"a"}`；
- 漂移 · Edge 已删除该资源；
- 漂移 · Edge 多出的旁路资源（平台无此发布记录）；
- 一致；无法评估 · 基线缺失：请重新发布以建立基线。

**让漂移回到一致**：在平台把该资源重新发布一次（平台版本会覆盖 Edge 上的旁路修改）。

## E.4 多节点归因语义

集群有多个活跃节点时，检测采集**全部活跃节点**并做路径级对照：

| 现象 | 结论 |
| --- | --- |
| 差异只在部分节点出现 | **真旁路修改**——结论「漂移」并归因节点（如「节点 192.168.0.14 与基线不一致（192.168.0.15 一致）」） |
| 所有节点呈现完全相同的差异 | **Edge 确定性展开**（如空插件被 Edge 端自动补默认值）——不报漂移 |
| 资源在部分节点整个消失 | 「Edge 已删除该资源」并注明节点 |
| 单节点集群 | 无对照，如实上报全部差异 |

## E.5 常见问题

| 问题 | 答案 |
| --- | --- |
| 我改的插件参数是个空对象里加的值，为什么以前漏报？ | 早期版本对「空容器基线」存在对比盲区（空对象没有键可逐字段比对），已修复：空基线 + Edge 非空一律报漂移 |
| 差异里 SSL 私钥会显示吗？ | 不会——敏感字段（私钥等）在差异表中以 `******` 占位，不回显原文 |
| 静态资源、节点会检测吗？ | 不会。只覆盖经统一发布编排的资源；结果底部明示「未纳入检测：static_resource、node」 |
| 检测会经中继吗？ | 会——与发布同通道，区域挂接集群自动经区域网关读取 |
| 旧发布记录为什么显示无法评估？ | 该次发布早于实发载荷留痕功能，重新发布一次即建立基线 |

## E.6 范围边界

- 基线是「**最新一次发布**」：历史版本不做对比；平台改了配置但**未发布**的改动不计入漂移（那是「待发布」，看发布状态标签）；
- 逐节点全量对账不做：多节点以路径级对照回答「有无旁路」；节点间短暂不一致属发布最终一致性的正常窗口；
- 不提供自动修复：发现漂移后在平台重新发布即可覆盖，一键回写属后续规划。
