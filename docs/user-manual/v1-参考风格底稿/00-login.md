# 第 0 章　登录与准备

本章作用：完成两件事——① 认识磐石 Admin 的界面结构；② 把系统切到一个**干净的空数据库**上，保证后续章节从零开始、每一步结果都清晰可见。如果你是在已有数据的生产系统上学习，可跳过 0.3，但阅读时请忽略页面上已有的数据。

---

## 0.1 登录

1. 浏览器打开 `http://localhost:12345/`，未登录时会自动跳转到登录页。
2. 输入账号密码：

| 字段 | 说明 |
|---|---|
| 用户名 | 首次部署默认 `admin`（超级管理员，拥有全部权限） |
| 密码 | 默认 `panshi123`，**上线前务必在「用户管理」中修改** |

![登录页](images/00-01-login.png)

3. 点击「登 录」，进入概览页。

> 💡 登录态由 JWT 维持；切换数据库后已登录会话仍然有效，但新库中只有 admin 账号，其他用户需重新创建。

---

## 0.2 界面导览

登录后进入「概览」页。整个界面分三块：

![空系统概览](images/00-02-dashboard-empty.png)

| 区域 | 位置 | 内容 |
|---|---|---|
| **侧边栏导航** | 左侧 | 按分组排列的功能入口：核心功能 / 边缘网络 / 综合 / 系统管理 |
| **顶栏** | 上方 | 左侧为面包屑（当前页面位置）；右侧为用户菜单（退出登录） |
| **内容区** | 中间 | 当前页面主体 |

侧边栏分组速览：

| 分组 | 菜单项 | 用途 |
|---|---|---|
| 核心功能 | 概览、集群管理、节点管理、上游管理、路由管理、插件组、插件元数据、全局规则、静态资源、SSL 证书 | 网关配置主线（本手册第 1-9 章） |
| 边缘网络 | edge.env 配置、四层代理、DNS代理[UDP]、DNS代理[HTTP] | Edge 节点网络能力（第 3、10、11 章） |
| 综合 | 统一管理、指标查询、指标总览 | 跨集群运维与监控 |
| 系统管理 | 插件开关、数据库管理、用户管理 | 平台自身管理 |

概览页的数字卡片显示各类资源的数量。空系统中除"用户=1"外全部为 0——这正是我们想要的起点。

## 0.3 准备干净的演示数据库

本手册使用一个独立的 SQLite 空文件作为演示库，与开发数据完全隔离。

### 背景：数据库存在哪里？

系统的连接配置（有哪些库、当前用哪个）保存在后端目录下的 `db_config.json` 文件中，与业务数据分离。切换数据库 = 修改配置 + 重启后端进程。

### 操作步骤

1. 侧边栏进入「系统管理 → 数据库管理」。

![数据库管理页](images/00-03-db-management.png)

2. 在「连接列表」卡片点击「+ 添加连接」：
   - **类型**：选 `SQLite`
   - **名称**：`手册演示库`
   - **数据库文件路径**：`./data/manual-demo.db`（文件不存在没关系，保存并重启后会自动创建）

   📷 截图待补充：（添加连接弹窗，SQLite 类型，填入路径）

3. 点击「测试连接」确认可用，然后「保存」。
4. 在列表中找到「手册演示库」一行，点击「设为当前」。
5. 弹窗提示需要重启后端服务，点击「确认切换」：

   > ⚠️ 切换只写配置，**必须手动重启后端才生效**：
   > - 开发环境：重新执行 `develop/linux/start.sh`
   > - 生产环境：`systemctl restart panshi-backend`

6. 重启完成后刷新页面，「当前数据库」卡片应显示 `SQLite · ./data/manual-demo.db`。

✅ **验证**：回到「概览」页，所有资源计数应为 0（用户除外）；「集群管理」列表为空。

## 本章小结

- 界面 = 侧边栏 + 顶栏 + 内容区
- 数据库连接配置在 `db_config.json`，切换后需重启后端
