# 29. 审计日志

> 本章场景：谁在什么时候改了什么？【审计日志】集中记录平台全部增删改操作（集群/路由/上游/节点/用户/数据库管理等），供管理员追溯与合规检查。

## 29.1 页面入口

点击左侧侧边栏：【系统管理】→【审计日志】。

> - 仅授权用户可见：管理员默认可见；普通用户可在【用户管理】中授予「审计日志」权限。
> - 若菜单不可见：回[第 1 章 功能开关前置检查](01-login.md)核对 `audit_log` 开关。

![审计日志列表页](images/29-01.png)

## 29.2 列表与筛选

列表默认按时间倒序展示最近 20 条，每行包含：**时间、用户、操作、资源、资源ID、详情、IP**。

筛选条件（下拉选项自动从历史数据加载）：

| 筛选项 | 说明 |
| --- | --- |
| 用户 | 按操作人过滤 |
| 操作 | 按动作过滤，下拉显示「中文 + 英文标识」，如「路由 创建（route_create）」「数据库迁移 迁移（db_migration_migrate）」 |
| 资源 | 按资源类型过滤，下拉显示中文名，如 路由 / 集群 / 用户 / 审计日志 |
| 时间范围 | 默认最近 7 天；多条件之间为「且」关系 |

操作标识命名规则为 `{资源}_{动作}`（如 `route_create`、`upstream_update`、`route_batch_delete`）；页面上均以中文展示，对应关系为「资源中文 动作中文」，如 `route_create` → 「路由 创建」、`upstream_update` → 「上游 更新」、`route_batch_delete` → 「路由 批量删除」。归档清理操作显示为「归档清理（archive）」。

筛选条右侧展示**库内统计**：`共 N 条记录 · 库内累计 M 条（最早 时间）`。「共 N 条」为当前筛选结果数，「库内累计」为数据库全部记录数。当库内累计超过 50,000 条时，会显示红色提示「记录量较大，建议归档历史数据」。

## 29.3 详情抽屉

点击「资源」列可跳转对应页面；点击行打开详情抽屉：

- 完整 detail 内容，长内容支持滚动；
- 【复制】按钮一键复制详情文本。

路由更新的 detail 包含**变更前后对比**，例如：`更新路由 r14: uri 从 '/old' 变更为 '/new'`；其他资源的更新记录业务对象名称，例如：`更新上游 api-server`。

创建/更新/删除等常规操作均记录**业务对象名称**，例如：`创建上游 api-server`、`删除上游 legacy-pool`、`删除节点 10.0.0.5:8080`；批量删除会汇总名单，例如：`批量删除上游 3 个：a、b、c`。早期历史记录的详情仅为资源+ID 模板，列表中以「—」显示，可通过资源 ID 与时间定位。

![详情抽屉](images/29-02.png)

## 29.4 导出

页面右上角操作区：【导出 CSV】/【导出 Excel】导出当前筛选结果；大数据量（超过 5000 行）由后端生成文件后下载。

- CSV 为 UTF-8（带 BOM）编码，Excel 双击打开中文不乱码；
- Excel 为真正的 .xlsx 工作簿（openpyxl 生成）；
- 两种格式数据内容完全一致，仅文件格式不同。

## 29.5 归档清理

审计记录只增不删是常态，但日积月累会影响数据库迁移与备份体积。【归档清理】（操作区红色描边按钮，与导出按钮以分隔线隔开）用于**先把旧记录导出存档、再从库中删除**：

1. 点击【归档清理】，在弹窗中选择**截止日期**；
2. 系统实时预览：该日期之前（不含当日）共有多少条记录、时间范围；
3. 点击【确认归档】：系统先将到期记录生成 CSV 存档（服务端留存于 `backend/data/archives/`，并自动开始下载），随后从库中删除；
4. 删除后自动写入一条**归档审计记录**（操作为「归档清理」），说明清理了多少条、时间范围、存档文件名——清理动作本身可追溯。

![归档清理](images/29-03.png)

注意事项：

- 删除**不可撤销**，请确认存档文件已妥善保存后再执行；
- 无可归档记录时按钮不可用（预览为 0 条）；
- 该功能仅对具有「审计日志」权限的用户开放；
- 服务端留存副本位于 `backend/data/archives/audit_archive_*.csv`，随数据库数据一并纳入常规备份。

## 29.6 常见问题

| 现象 | 处理 |
| --- | --- |
| 菜单不可见 | 核对 `audit_log` 开关（第 1 章）与用户「审计日志」权限 |
| 失败的操作没有记录 | 设计如此：失败的请求（未提交）不产生审计记录 |
| 批量操作只有一条记录 | 设计如此：批量操作合并为一条汇总，detail 中含全部 ID |
| 老记录的详情显示「—」 | 历史记录的详情仅为资源+ID 模板（与左侧列重复故折叠显示）；新记录均带业务对象名称 |
| 归档清理后记录去哪了 | 已导出为 CSV：页面自动下载一份，服务端留存于 `backend/data/archives/`；库中保留一条「归档清理」审计记录 |
| 下载的 CSV/Excel 打不开或乱码 | 重新导出。若仍异常，检查下载是否被浏览器拦截（下载需登录态） |
