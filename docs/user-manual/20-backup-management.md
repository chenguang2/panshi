# 20. 备份与容灾

> 本章场景：平台数据要定期备份到异机、服务器要搬迁或灾难后要在新机上快速拉起。【备份与容灾】为**SQLite 源库**提供「定时打包 + 推送多个远端位置」的备份流水线，以及一套三步「容灾恢复向导」：选来源 → 选包校验 → 确认执行，恢复后只需重启后端。备份包自带 JWT 密钥、连接注册表与关键配置，换机恢复后登录即用。

## 20.1 页面入口

三种方式进入：

1. 左侧侧边栏：【系统管理】→【备份与容灾】；
2. 从[第 18 章 数据库管理](18-database-management.md)页面底部摘要卡点【进入备份管理】；
3. 摘要卡点【恢复数据】——直达本页并自动弹出**容灾恢复向导**。

![备份与容灾页](images/20-backup-01.png)

> 若菜单不可见：回[第 1 章 功能开关前置检查](01-login.md)核对 `db_backup` 开关，并确认账号具有 `db_backup` 权限。
>
> ⚠️ 备份功能**仅 SQLite 源库适用**：连接注册表中没有 SQLite 连接时，页面统计条直接显示「不适用」（PostgreSQL 源请用数据库自带的备份机制）。

## 20.2 状态总览条

页面顶部是常驻统计条，四格信息：

| 格 | 内容 |
| --- | --- |
| 最近成功备份 | 上次成功完成的时间；从未成功过只显示「从未备份」，行动建议显示在统计条下方的提示行（见下） |
| 下一轮预计执行 | 定时备份启用时显示下次调度时间；未启用显示「—」 |
| 最近一次状态 | 上次执行结果（成功 / 部分成功 / 失败），执行中显示旋转的「备份进行中」徽标；未执行过显示「尚未运行」 |
| 定时调度 | 已启用（绿）/ 未启用（灰）；**数据库迁移进行中时染黄显示「数据库迁移进行中，定时备份暂停」**，迁移完成后自动恢复 |

统计条右侧操作区：

| 按钮 | 说明 |
| --- | --- |
| 【刷新】 | 重新拉取配置、状态与历史；有未保存修改时先弹确认（丢弃并刷新） |
| 【立即备份】 | 手动触发一次完整备份，**不依赖定时开关**；执行中显示「备份中…」。**尚未配置启用位置时按钮禁用**，旁注提示「请先添加并启用备份位置」 |
| 【恢复数据…】 | 打开容灾恢复向导（见 20.6） |

「策略与保留」页签的修改用页签标题行的【保存全局配置】保存；有未保存修改时统计条出现**「有未保存修改」**徽标（点击直达该页签）。

> 💡 「立即备份」时若有未保存的策略修改，会先弹出三选确认：**保存并备份** / **按已保存配置备份** / 取消。同样地，**有未保存修改时切换到其他页面**会弹「离开将丢弃未保存修改」确认：确认才离开，取消留在本页。
>
> ⚠️ 备份结束一律弹出**结果窗口**（不再以「失败弹错误框」呈现）：成功 / 部分成功 / 失败三态 + 逐位置推送结果。**409 冲突提示（「已有备份/恢复任务进行中」）只在任务冲突时出现**，推送失败不再是报错弹窗，而是结果窗口里的结构化信息。

### 20.2.1 失败错误怎么看（中文归因）

结果窗口与历史展开里，每个失败位置的错误首句是**中文归因 + 可操作建议**，原始错误串保留在「原始错误：」之后供排查：

| 归因首句（节选） | 常见原因 |
| --- | --- |
| 连接备份位置失败：无法建立到 `主机:端口` 的 SSH 连接（连接被拒绝），请检查 IP、端口与防火墙设置 | 目标机器 SSH 未监听该端口 / 防火墙拦截 |
| 备份位置认证失败：`主机:端口` 拒绝了提供的凭据，请检查用户名与密码/私钥是否正确 | 账号或密码/私钥不对 |
| 无法解析备份位置主机 / 连接超时 | 主机名写错、网络不通 |
| 远端目录不存在 / 磁盘空间不足 | 远端目录路径错、远端盘满 |
| 无法使用密码认证：平台后端服务器未安装 sshpass 组件 | 见下方处理 |

> ⚠️ **sshpass 装在哪台机器**：密码认证依赖的 `sshpass` 组件装在**运行本平台的后端服务器**上（不是你当前操作的电脑）。按错误提示在后端服务器执行 `sudo apt-get install sshpass` 安装；不方便安装时，把备份位置的认证方式改为「密钥」并填写私钥路径即可绕开。

## 20.3 备份位置

「备份位置」页签管理备份包要推送到的**远端 SSH 目录**，支持多个位置同时推送：

| 列 | 说明 |
| --- | --- |
| 名称 | 位置显示名 |
| 启用 | 开关：停用前会弹确认（停用 = 容灾能力降级）；停用位置保留配置、不参与推送 |
| 地址 : 端口 | SSH 地址，端口默认 22 |
| 远端目录 | 备份包存放的绝对路径（需预先创建并授权） |
| 最近推送 | 健康点 + 相对时间：绿点 = 最近推送成功、红点 = 失败、灰点 = 暂无记录；悬停显示最近推送时间与结果。行内【测试】的即时结果在**行下展开条**显示，不混入本列 |
| 保留份数 | 该位置保留最近 N 份备份包（默认 7），超出自动清理 |
| 操作 | 【编辑】；【测试】仅校验 SSH 连通与凭据；【删除】（有确认弹窗） |

点【＋ 新增位置】打开右侧抽屉：

![新增备份位置](images/20-backup-04.png)

| 字段 | 说明 |
| --- | --- |
| 名称 | 必填，显示名（如 `局内DR`，允许中文） |
| 地址 / 端口 / 用户名 | SSH 连接参数；端口默认 22，用户名默认 `root`（建议改用专用备份账号，仅授予目标目录写权限） |
| 认证方式 | 密码：填写密码；私钥：填写私钥文件路径（如 `~/.ssh/id_ed25519`） |
| 远端目录 | 绝对路径，不存在时测试会报错 |
| 备份保留份数 | 该位置的保留策略，默认 7；仅清理本来源标识的备份包 |
| 启用 | 默认开启；关闭后保留配置、不参与推送 |

> 💡 抽屉底部【测试连接】按**当前表单参数**即时验证（无需先保存），验证通过再【保存位置】。尚无任何位置时，列表显示空态引导，与顶部「尚未配置备份位置」提示一致。

## 20.4 策略与保留

「策略与保留」页签配置全局备份策略：

![策略与保留](images/20-backup-02.png)

| 字段 | 说明 |
| --- | --- |
| 启用定时备份 | 总开关；「立即备份」不依赖此开关 |
| 备份间隔（分钟） | 建议 5–1440，上限 10080（7 天）；启用后约 30 秒内执行首次备份 |
| 来源标识 | 写入备份包名与远端子目录，用于多机互备时区分来源（如 `panshi-a`、`panshi-b`） |
| 包含静态资源 | 默认不勾选；勾选后把平台静态资源目录一并打包 |
| 包含任务脚本 | 默认不勾选；勾选后包含节点任务上传的脚本存档 |
| 包含任务日志 | 默认不勾选；勾选后包含节点任务执行日志 |

修改后点「策略与保留」页签标题行的【保存全局配置】生效；不保存而直接「立即备份」时，按服务端**已保存**配置执行。

> ⚠️ 附加数据段（静态资源 / 任务脚本 / 任务日志）默认不勾选：它们体积大、且属于「数据库行引用的运行时数据」。勾选越多包越大、推送越慢，按容灾要求取舍。核心数据（SQLite 库文件、JWT 密钥、连接注册表、功能开关、ClickHouse 配置、SSH 主机清单）**始终打包**，无需勾选。

## 20.5 备份历史

「备份历史」页签展示每次备份的执行记录。**最近一次备份失败且尚未查看原因时，页签名会带红点角标**——展开任一失败行查看原因后红点消失（下次备份成功也会自动消失；再次失败会重新点亮）：

![备份历史](images/20-backup-03.png)

工具行支持按**状态**（成功 / 部分成功 / 失败）与**触发方式**（定时 / 手动）筛选，分页浏览；筛选仅作用于**最近 200 条**记录（工具行有常驻提示）。

| 列 | 说明 |
| --- | --- |
| 开始时间 | 触发时刻 |
| 触发 | 定时 / 手动 |
| 状态 | ✓ 成功（所有启用位置推送成功）/ ⚠ 部分成功 / ✗ 失败；右侧 `N/M 目标` 为逐位置成功计数 |
| 包名 / 大小 / 耗时 | 备份包名（`panshi_backup_<来源标识>_<时间戳>.tar.gz`）、包体积与执行时长 |
| 操作 | 【恢复此包】——仅当该记录**至少一个位置推送成功**时出现（见下） |

- **展开任意一行**可看失败原因与**分位置结果**：每个启用位置的推送结果（✓ 推送成功含耗时 / ✗ 推送失败含中文归因，见 20.2.1）；
- **全败或构建失败的记录不显示【恢复此包】**，改以灰色说明标注原因（「未成功推送到任何备份位置，无法在线恢复」/「本次备份构建失败，未生成备份包」）——在线恢复要求包至少存在于一个位置；
- 成功记录点【恢复此包】直达恢复向导：自动定位该包所在位置、列包、**自动发起校验**（与手动校验同一路径，来源标注为该位置名），停在第二步等你确认——**仍需手动确认后才执行恢复，安全闸不减**。

**【清理历史】**（工具行按钮）：备份记录长期累积后可在此清理。弹窗内二选一——**保留最近 N 条**（默认 50）或**清空全部**，实时显示「本次将删除 X 条记录」：

> ⚠️ 清理是**物理删除、不可恢复**，且**只删操作历史**（主记录 + 逐位置子结果），**远端备份包本体不受影响**——清理后仍可在恢复向导里按远端实际存在的包恢复。

## 20.6 容灾恢复向导

【恢复数据…】（或备份历史【恢复此包】、摘要卡【恢复数据】）打开三步向导：

### 20.6.1 第一步：选择备份来源

![选择备份来源](images/20-backup-05.png)

- **已配置备份位置**：从备份位置下拉选择（或「全部位置」并列扫描）——常规场景用这档；
- **手工录入**：直接填主机 / 端口 / 用户名 / 认证方式 / 密码或私钥路径 / 远端目录——**平台宕机后在新环境拉起时用这档**，手工信息仅本次使用，不会保存。

### 20.6.2 第二步：选择并校验备份包

![选择并校验备份包](images/20-backup-06.png)

列出远端目录中所有 `panshi_backup_*.tar.gz`，每张包卡片显示：文件名、大小、来源标识、**存在位置**（多个位置含同一包时可择一复制）、备份时间、平台版本与提交号，以及标签（如「元数据不可读」「未含静态资源」「跳过库」「包含库」）。支持「仅看每个来源的最新包」过滤。

![校验此包](images/20-backup-07.png)

> ⚠️ **必须先校验再恢复**：选中包后点【校验此包】，系统核对 SHA256、tar 完整性、关键表与逐库完整性；未校验的包不能进入下一步。多位置同包时，校验与恢复将使用你选定的那个位置。从备份历史【恢复此包】进入时，第一步与校验会**自动完成**（用的就是该包所在的那个位置），但执行恢复仍需你手动确认。

### 20.6.3 第三步：确认并执行恢复

![执行恢复](images/20-backup-08.png)

- 红色危险提示：恢复将**覆盖本机数据库文件与关键配置**；原活动库自动改名为 `*.pre-restore-<时间戳>` 保留（回退用）；
- 摘要确认：备份包、来源位置、包大小、包含数据段、将写入的目标连接等；
- 勾选「我已知晓风险并确认执行恢复」后点【执行恢复】；
- 成功后显示：恢复后的活动连接 ID、**重启命令**（开发 `develop/linux/start.sh`；生产 `sh stop.sh && sh start.sh`，带一键复制）、暂存有效期 10 分钟内完成落位等提示，点「已完成，刷新页面」收尾。

> ⚠️ 三点务必知晓：
> - **必须重启后端**恢复才生效（JWT 密钥链切换到恢复包内的密钥，旧会话全部失效，需用**备份时点**的账号密码重新登录）；
> - 恢复会继承包内的**来源标识**：多台机器先后用同一个包恢复会互相覆盖远端备份，恢复完成后建议在本机改一个新的来源标识；
> - 暂存区有效期 10 分钟（600 秒），超时未执行需重新校验。

## 20.7 备份包命名与保留策略

- **命名双格式**：新格式 `panshi_backup_{来源标识}_{YYYYMMDD_HHMMSS}.tar.gz`（主格式，时间戳为 Asia/Shanghai）；无来源标识的旧格式 `panshi_backup_{YYYYMMDD_HHMMSS}.tar.gz` 仍可识别与恢复；
- **按位置独立保留**：每个备份位置按包时间戳倒序保留各自「保留份数」；清理只针对**本机来源标识**的新格式包与旧格式包，**绝不删除其他来源标识的包**（多机互备安全）；
- 备份包目录结构：核心数据（`databases/`、密钥、`db_config.json`、`features.yaml`、`clickhouse.yaml`、SSH 主机清单）+ 按开关附加的运行时数据段 + `meta.json`（连接映射、活动连接 ID、版本信息）。

## 20.8 常见问题

| 现象 | 处理 |
| --- | --- |
| 统计条显示「不适用」 | 连接注册表中没有 SQLite 连接——备份仅 SQLite 源适用（原因会原文显示，如「注册表中没有 SQLite 连接，不适用」） |
| 【立即备份】灰色点不动 | 尚无启用的备份位置——旁注提示「请先添加并启用备份位置」；到「备份位置」页签新增或启用 |
| 定时调度格显示黄色「数据库迁移进行中，定时备份暂停」 | 正常的保护行为：迁移期间定时备份暂停，迁移完成后自动恢复；期间仍可手动【立即备份】 |
| 备份失败提示「未安装 sshpass」 | 该组件装在**平台后端服务器**上（见 20.2.1）：在后端服务器 `sudo apt-get install sshpass`，或把位置改用密钥认证 |
| 历史行没有【恢复此包】按钮 | 该记录所有位置都推送失败（或构建失败未生成包），无法在线恢复；确认远端确有包时用【恢复数据…】手输目标走向导 |
| 定时没到点就备份了 | 正常——启用定时后约 30 秒内会执行首次备份 |
| 校验报「元数据不可读」 | 包内 `meta.json` 缺失或损坏（如手工改名/截断）；关键表校验通过仍可恢复，但连接映射等需人工核对 |
| 恢复后登录不上 | 用**备份时点**的账号密码登录（恢复包内含当时的用户表与 JWT 密钥）；仍不行检查是否已重启后端 |
| 想回退恢复 | 停平台 → 把 `db_config.json` 中 SQLite 连接 path 改回旧库（`*.pre-restore-*` 前改名保留）→ 重启 |
| 只想把库迁去 PostgreSQL | 备份恢复不是干这个的——用[第 19 章 数据迁移](19-db-migration.md) |
| 立即备份按的哪份配置 | 有未保存修改时会弹三选确认；「按已保存配置备份」按服务端已保存配置执行，屏幕上的未保存修改不生效 |
| 备份历史想清掉重计 | 「备份历史」页签【清理历史】：保留最近 N 条或清空全部；物理删除仅影响操作历史，**远端备份包不受影响** |
| 离开页面弹「离开将丢弃未保存修改」 | 「策略与保留」有未保存修改时的保护确认：确认离开修改丢弃，取消留在本页先保存 |

## 20.9 本章小结

- 备份 = 核心数据必打包 + 三个附加段按需勾选，推送到多个远端 SSH 位置，按位置独立保留 N 份
- 定时与手动独立：不开定时也能【立即备份】（无启用位置时禁用并提示）；失败一律以**结果窗口**呈现（三态 + 逐位置中文归因），409 只表达任务冲突
- 恢复 = 三步向导（来源 → 选包**强制校验** → 确认执行）；从历史【恢复此包】进入会自动列包并校验，但执行仍需手动确认；完成后**必须重启后端**
- 原活动库自动改名保留，可回退；恢复继承来源标识，多机同包恢复后记得改标识
- 历史页签：失败未读有**红点角标**；【清理历史】保留最近 N 条或清空全部（只删操作历史，不动远端备份包）；筛选仅覆盖最近 200 条
- 仅 SQLite 源适用；PostgreSQL 迁移/同步走[第 19 章](19-db-migration.md)
