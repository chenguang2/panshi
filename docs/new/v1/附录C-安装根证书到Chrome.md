# 附录 C：下载根证书并安装到 Chrome 受信任的根证书颁发机构

> 适用场景：使用平台本地生成、由自建 CA（如演示环境的"演示根证书"）签发的 HTTPS 证书时，
> 浏览器默认不信任该 CA，访问网关会提示"您的连接不是私密连接"。将根证书安装到系统
> **受信任的根证书颁发机构**后，由它签发的所有服务器证书都会被信任，告警消失。
>
> 演示环境约定：管理平台 `http://localhost:12345/`，网关 `https://test.com:50000/`（域名解析参见附录 A / B）。

### 第一步：下载根证书

1. 登录磐石 Admin 管理平台，进入左侧菜单"**SSL 证书**"页面。
2. 找到作为签发根的 CA 证书卡片（演示环境中为"**演示根证书**"，卡片带"CA"标识）。
3. 点击卡片上的【**下载证书**】按钮，浏览器会将证书保存为 `.pem` 文件（如 `演示根证书.pem`）。

> 💡 `.pem` 与 `.crt` 内容格式相同。如果双击 `.pem` 无法打开，可将其重命名为 `.crt` 后再操作。

> ⚠️ 注意区分：要安装的是 **CA 根证书**（如"演示根证书"），不是 `test.com` 这类服务器证书。
> 安装服务器证书本身不会让浏览器信任整个链条。

### 第二步：安装到"受信任的根证书颁发机构"

**方法 1：双击证书文件安装（推荐）**

1. 双击下载的证书文件，打开证书信息窗口，点击【**安装证书**】。
2. 存储位置选择"**本地计算机**"（需要管理员权限，在 UAC 提示中点击"是"），点击"下一步"。
3. 选择"**将所有的证书都放入下列存储**"，点击【浏览】：
4. 在证书存储列表中展开"**受信任的根证书颁发机构**"，选中它，点击"确定" -> "下一步"。
5. 点击"完成"。弹出安全警告时点击"**是**"。

**方法 2：通过 Chrome 设置进入证书管理器**

1. 打开 Chrome，地址栏输入 `chrome://settings/certificates` 并回车。
2. 切换到"**受信任的根证书颁发机构**"选项卡，点击【**导入**】。
3. 在弹出的 Windows 证书导入向导中按方法 1 的第 2-5 步操作（Windows 版 Chrome 使用系统证书存储）。

> 💡 Linux / macOS 用户：Chrome 在这两个系统上使用独立的证书库，直接在
> `chrome://settings/certificates` 界面中导入即可；Linux 命令行方式为
> 将证书复制到 `/usr/local/share/ca-certificates/` 并执行 `sudo update-ca-certificates`。

### 第三步：重启 Chrome 使其生效

1. 地址栏输入 `chrome://restart` 并回车，Chrome 会自动关闭并重新打开。
2. （可选）打开 `chrome://settings/security`，确认"管理设备证书"中能看到新安装的根证书。

### 💡 验证是否成功

1. 确保域名已能解析到网关（hosts 或 DNS，参见附录 A / B）。
2. 用 Chrome 访问网关上的页面，例如：
   ```
   https://test.com:50000/static/index.html
   ```
3. **预期结果**：地址栏出现 🔒 锁形图标，不再显示"您的连接不是私密连接"警告。
4. 点击锁图标 -> "连接安全" -> 【证书有效】，在证书链中应能看到：`test.com` ← **演示根证书**。

---

**⚠️ 仍然提示"证书无效"？请按以下顺序排查：**

| 提示关键词 | 原因 | 解决办法 |
|---|---|---|
| "您的连接不是私密连接"，详情含 **NET_ERR_CERT_AUTHORITY_INVALID** | 根证书未装对位置或未重启 Chrome | 确认装入"受信任的根证书颁发机构"（而非"个人"），并执行 `chrome://restart` |
| 详情含 **NET_ERR_CERT_COMMON_NAME_INVALID** | 访问地址与证书域名不匹配 | 用证书 SAN 中的域名访问（如 `test.com`），配置 hosts/DNS 见附录 A / B；或重新生成包含对应 IP 的证书（生成对话框中填写"IP SAN"） |
| 页面能打开但 WebSocket 连不上 | WebSocket 地址需与页面同域名且路径匹配路由 | 使用 `wss://test.com:50000/ws/` 形式（注意末尾斜杠） |
