# 第 2 章　建立节点

本章作用：把三台**已预装 OpenResty + Edge 的真实机器**登记到平台。节点是配置的最终落点——所有"发布"动作，本质都是平台通过 SSH/管理端口把配置推送到这些机器上并重载网关。不建节点，集群只是一个空壳，无法发布任何东西。

---

## 页面入口

侧边栏「核心功能 → 节点管理」。

![空节点列表](images/02-01-node-list-empty.png)

右上角「+ 添加节点」打开创建弹窗。

---

## 字段逐项解释

![添加节点表单](images/02-02-node-form.png)

| 字段 | 必填 | 含义 |
|---|---|---|
| **所属集群** | ✅ | 该节点归属的集群；一个节点只属于一个集群 |
| **IP 地址** | ✅ | 节点 IP，平台用它发起 SSH / 管理接口调用。例：`192.168.0.13` |
| **服务端口** | ✅ | 网关对外提供 HTTP 服务的端口（OpenResty 监听口），通常为 `80`。用于连通性探测与流量验证 |
| **管理端口** | ✅ | Edge 的 Admin API 管理端口（edge.env 中 `deploy.http.admin.listen`）。**发布配置走这个端口**。演示环境为 `16620` |
| **SSH 端口** |  | 远程执行命令（如 edge.env 读取、自启动管理）用的 SSH 端口，默认 `22`。不填则无法执行 SSH 类操作 |
| **OpenResty 安装路径** | ✅ | 节点上 OpenResty 的安装目录。例：`/work/jboss/uapm/openresty` |
| **Edge 安装路径** | ✅ | Edge 程序与 edge.env 所在目录。例：`/work/jboss/uapm/uap-edge` |
| **启用** |  | 勾选 = 节点参与发布；取消勾选 = 暂时停用该节点 |

> ⚠️ 两个路径必须填写节点上的**真实绝对路径**：发布时平台要往 Edge 路径写配置、按 OpenResty 路径执行 reload。路径错了发布会失败。

---

## 操作步骤

对三台机器重复以下操作（共 3 次）：

1. 点击「+ 添加节点」。
2. 填写（三台仅 IP 不同）：

| 字段 | .13 | .14 | .15 |
|---|---|---|---|
| 所属集群 | 演示集群 | 演示集群 | 演示集群 |
| IP 地址 | 192.168.0.13 | 192.168.0.14 | 192.168.0.15 |
| 服务端口 | 80 | 80 | 80 |
| 管理端口 | 16620 | 16620 | 16620 |
| SSH 端口 | 22 | 22 | 22 |
| OpenResty 安装路径 | `/work/jboss/uapm/openresty` | 同左 | 同左 |
| Edge 安装路径 | `/work/jboss/uapm/uap-edge` | 同左 | 同左 |
| 启用 | ✅ | ✅ | ✅ |

![填写完成的节点表单](images/02-03-node-form-filled.png)

3. 点击「保存」。重复三次后列表如下：

![三个节点创建完成](images/02-04-nodes-created.png)

✅ **验证**

- 列表中出现 3 个节点。
- 「状态」列显示在线/离线——这是平台周期性探测的结果：
  - 在线 = 服务端口与管理端口均可达；
  - 离线 ≠ 不能用，常见原因是网络不通或管理端口未放行，可先继续后续章节，发布前再处理。

## 本章小结

- 节点 = 一台真实的网关机器，四个关键信息：IP、服务端口、管理端口、两个安装路径
- 管理端口是发布的通道，SSH 端口是远程命令的通道
- 节点必须挂在某个集群下
