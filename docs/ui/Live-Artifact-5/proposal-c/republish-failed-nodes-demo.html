适用面与边界
① 四层代理 / DNS-UDP / 插件组 / 全局规则：已有 .lp-notice，改文案 + 加动作即接入（方案 A 直接覆盖）。 ② DNS-HTTP / 插件元数据：连泛化 notice 都没有，推广时一并补齐（同批）。 ③ 静态资源页：保持现状不动——它有真正的持久化 failed_nodes（zip 分发语义），文案取库不取预览，比方案 A 更精确，无需改。 ④ 列表页（路由 / 上游 / 节点 / SSL）：走表格行 + PublishDiffButton 既有形态，本方案不涉及。 ⑤ 若后续要「页面打开即显示具体失败节点」（不点按钮就能看到），才需要方案 B：publish_resource 持久化 failed_nodes 明细（各资源加列 + 迁移），成本显著更高，建议不做。
