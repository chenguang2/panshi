## 三、卡片页的标准解剖（每页都必须遵循）

```
page-header
  h1 + .ph-inline 徽标（首个 .ph-lite.lite-accent = 补充维度数，其余按 tone）
  p 描述（一行，说明职责 + 关键约束，例如「修改后需发布才会在 Edge 节点生效」）
  .page-header-actions 主按钮（+ 新建 / 上传 等），次按钮（批量管理 / 导入）
l5-card
  l5-toolbar        ← 搜索 150 + 筛选下拉 104/120（与列表页同口径）+ 右端簇（刷新/列配置不用于卡片页则省略）
  l5-chiprow        ← 状态 chips（.f-chip.chip-status + .f-count），仅在有「发布态/启用态」的页面出现
  （可选）l5-batchbar ← 有批量操作的页面
  .card-grid        ← 卡片网格：3 列 → ≤1200 两列 → ≤768 一列（theme.css 已有 .card-grid）
    .l5-panel（单卡片，见下）
  l5-pager          ← 「共 N 个X · 每页 [下拉]」+ 页码
```

### 3.1 单卡片 = `.l5-panel`（本任务新增的共享类，写进 theme.css）

```
.l5-panel                 ← 白底、1px --border、radius-lg、hover 抬阴影
  .lp-head                ← padding 12px 14px；display flex；gap 8px；border-bottom 1px --border
    .lp-name              ← 15px/600 --fg（主名称，长名省略 + title）
    .lp-tag               ← 11px mono 胶囊（类型/组/协议等，如 TCP、DoH、limit-count、生产环境）
    .lp-status            ← 右侧状态区（ps-tag 或 badge，见 §四）
  .lp-body                ← padding 12px 14px；键值行 2 行内
    .lp-row               ← 一行：label（11.5px --muted，宽 64px，右对齐不用）+ value（12.5px --fg；数值/地址用 mono）
  .lp-notice              ← 卡片内嵌警示/提示（可选，见 §四），位于 body 末尾
  .lp-foot                ← padding 10px 14px；border-top 1px --border；右侧对齐操作簇
    .op-pub               ← 主操作（发布），复用既有 .op-pub
    .op-btn（⋯ 触发器）    ← 复用既有的三圆横排 26×24 无边框锚点
    .l5-menu              ← 复用既有菜单（CRUD 组 → 分隔 → 危险组 → 动作组）
```

## 四、状态与警示语义（本任务的重点，必须成体系）

### 4.1 状态标签（复用既有）

- `.ps-tag.ps-pub` 已发布（绿 `vN`）/ `.ps-tag.ps-pending` 待发布（黄）/ `.ps-tag.ps-unpub` 未发布（灰）/
  `.ps-tag.ps-partial` 部分失败（红）；
- 已发布条目右侧附 `.ps-date`（mono 时间）。
- 非发布态的状态（如「启用/禁用」「有效/已过期」「可分发/不可分发」）用 `.badge`：
  `.badge.badge-success` / `.badge-neutral` / `.badge-warn` / `.badge-danger`（若无则按 §4.3 补）。

### 4.2 四档提示（已有 `.alert` + `.alert-info/success/warning/error`）

| 语义 | 类名 | 用在哪 | 图标 | 文案原则 |
|---|---|---|---|---|
| **危险 / 阻断** | `.alert.alert-error` | 会导致服务中断或不可恢复的后果 | 三角内感叹号 | 先说后果，再说如何避免。例：「删除后已发布的证书将从所有节点移除，客户端将立即握手失败」 |
| **警告 / 需注意** | `.alert.alert-warning` | 有风险但可继续（即将过期、待发布未生效、分发失败可重发） | 三角内感叹号（描边，不填充） | 说清触发条件与补救动作。例：「有 2 个节点分发失败，配置尚未生效」 |
| **提示 / 说明** | `.alert.alert-info` | 操作须知、口径说明（不需/需要发布、请在别处管理） | 圆内 i | 一句话讲清「为什么」与「去哪里做」 |
| **正常 / 已完成** | `.alert.alert-success` | 全部就绪（谨慎使用，避免噪音） | 圆内对勾 | 只在「刚完成某动作」时出现 |

### 4.3 位置规则（三种落位，同一页可各用一次）

1. **页面级横幅**：位于 `page-header` 之下、`l5-card` 之上，用于**整页级**风险（如「当前集群无可用节点」「证书即将过期」）。用 `.alert.alert-warning/error`，右侧可带一个动作按钮（如「去处理」）。
2. **卡片内嵌**：卡片 `.lp-notice` 内，用于**该条目自身**的问题（分发失败、待发布、即将过期、路由已删除导致静态资源不可达）。样式沿用 `.alert` 但更紧凑（`padding 8px 10px; font-size 12px; margin 0`），**不带标题行**，只一行文案 + 图标。
3. **字段级**：`.lp-row` 的 value 右侧加 `.field-warn`（12px，`--warning`，带「⚠ 」前缀或小图标），用于单字段取值的异常（如「优先级 0 · 与 3 条路由冲突」）。

### 4.4 警示强度与配色（严格用 token，不自造颜色）

`--danger`（oklch 55% .18 28）/ `--warning`（65% .15 85）/ `--info`（55% .12 240）/ `--success`（55% .15 145），
背景一律取同色 8–14% 透明度（`.alert*` 已定义），文字用对应 token 本色。

**不要用红色表达「只是提醒」**，也不要用黄色表达「已阻断」。

## 六、自检清单（每页提交前逐条确认）

1. 打开后**没有**任何外部请求（字体/图标/CDN 一律不用，图标用内联 SVG，风格同现有页面：`stroke-width:2`、`stroke-linecap:round`）。
2. 卡片网格在 1600 视口 3 列、≤1200 两列、≤768 一列（用 `.card-grid`）。
3. 每张卡片都有明确主操作（`.op-pub` 或主按钮）+ `.op-btn` 更多菜单；更多菜单内危险项红色且**带解释小字**。
4. 每页至少出现**一处**该页特有的警示或提示（见 §五右列），且落在 §4.3 规定的三种位置之一。
5. 所有数值/地址/路径/时间用 `--font-mono`；标签与正文用 `--font-body`。
6. 顶部徽标不再重复「卡片总数」（总数已由分页条与状态 chips 承担）：页头徽标放**补充维度**（如「涉及 3 集群」「2 即将过期」）。
7. 页面高度紧凑：单卡片 ≤ 180px，网格间距 16px，`l5-card` 内边距与三份列表页一致。

## 七、集群分组 / 分组·平铺 / 分页 / 批量（2026-11-18 追加，已批准并验证）

### 7.1 适用面

- **有集群维度的卡片页**提供「分组 | 平铺」：插件组、插件元数据、全局规则、静态资源、服务器证书、四层代理、DNS 代理（UDP）、DNS 代理（HTTP）。
- **无集群维度**（插件开关 = 全局开关、CA 根证书 = 平台级）**不显示该开关**。

### 7.2 两种模式

| | 分组（默认） | 平铺 |
|---|---|---|
| 集群标识 | `.l5-band`（跨三列、左 3px 色条、`集群名 + 分组徽标 + N 个X + 次要指标 + 折叠`） | 卡顶 `.lp-strip`（集群名 + 分组徽标 + 右端次要指标）+ 左缘 4px 色条 |
| 卡内集群信息 | 不重复（由 band 承担） | 显示 |
| 折叠 | 整条 band 可点 + chevron；工具条有「全部展开/全部收起」单按钮 | 折叠按钮隐藏 |

- **band 只显示规模**（`N 个X`）+ 一个**次要指标**（四层代理=目标数、插件组=被引用数、全局规则=生效路由数、服务器证书=签发者、DNS 两页=上游名）；**不得**放已发布/待发布计数（状态只归顶部 chips 行）。
- 集群色相固定：`.cluster-c1 … .cluster-c8`，`cluster_id % 8`，同一集群全站同色。
- 卡片在两种模式下均 ≤180px（平铺靠「次要指标移到 strip 右端」换回行高）。
- 进入页面默认**全展开**（不默认折叠组）。

### 7.3 分页（按组分页，第三条路）

卡片页**保留分页能力**，但两种视图的分页单位不同：

| 数据量（服务端总数） | 分组视图 | 平铺视图 |
|---|---|---|
| ≤ 60 | 单页，**不显示分页条** | 同 |
| 60–1000 | **按「组」分页**：每页 3 个集群组，组内全量 | 按「条」分页：20/页 |
| > 1000 | 虚拟滚动 + band sticky（届时另立项） | 同 |

理由：按条分页会让 band 被页边界切断（同名 band 在相邻两页重复、band 上的规模计数变成「本页条数」而自相矛盾、折叠态跨页丢失）。按组分页则 band 永不跨页，规模计数恒等于真实条数。

### 7.4 批量管理

**仅实现里已有批量能力的页面**画批量态（当前：四层代理、DNS 代理（UDP））：进入批量态 → 卡片勾选框 + `.l5-batchbar`（已选 N 项 / 批量发布 / 批量删除 danger / 清除选择）+ 分组模式 band 右端「全选本组 / 取消本组」+「已选 k / N」。其余页面**不虚构**批量功能。

## 八、列表页平铺态的集群标识（2026-11-18 追加，已批准）

三张列表页（节点 / 上游 / 路由）的**平铺视图**每行 SHALL 显示集群标识——分组视图由组头给出，平铺视图必须有等价信息，否则用户无法判断某行属于哪个集群：

- 做法（方案 A）：在**名称列之后**插入「集群」列，宽 **116px**，值 = **6px 集群色点** + 集群名（12.5px `--fg`）；
- 色点 SHALL 复用卡片页的固定色相 `.cluster-c1..c8`（`cluster_id % 8`），与集群分组带、平铺集群条同色；
- 该列**仅平铺视图存在**：切回分组视图时整列移除（含 `<colgroup>`、表头），表格最小宽同步还原；
- 表头「集群」SHALL 可排序（服务端 `sort_by=cluster`，按集群显示名升降序；平铺态生效，分组态无该列）；
- 代价（已评估）：表格最小宽 +116px。实现侧 floors 变为 节点 896 / 上游 688 / 路由 768 —— 1280 及以上视口无横向滚动，**仅 1200 视口节点页会内部横滚约 24px**。

被否决的备选：B（名称下加集群小字，行高 +18px、不可排序）、C（名称前加集群徽标，名称列被吃掉 ~86px、不可排序）。

### 8.1 字段呈现的统一判据（同轮确定）

| 字段类型 | 呈现 | 例子 |
|---|---|---|
| 枚举 / 分类 | **chip**（`.m-tag` / `.lb-chip` / `.scheme-chip` / `.ps-tag` / `BadgeStatus`） | 方法、协议、算法、发布态、节点运行态 |
| 标识（地址 / 路径 / 名称） | **mono 文本**（路径 `--muted`） | IP、监听地址:端口、安装路径、URI |
| 度量（数字 / 时间） | **mono 数字 / muted 小字** | 服务端口、Edge 版本、时间戳 |

据此：**节点页不 chip 化**（现状已合规，12 行逐行扫描非 mono = 0 处）；**路由优先级 `P0/P10` 从 chip 收回 mono**（度量值不是分类）；**上游「目标节点」保持 chip**（它是复合组件：健康点 + 权重条 + 占比，不是纯标识）。
