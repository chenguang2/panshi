# Live-Artifact-5 — 节点 / 上游 / 路由列表页美化方案

针对左侧菜单「节点管理、上游管理、路由管理」三个独立列表页的界面美化提案。
**基色、字体、圆角、阴影全部沿用现行主题 token**（`frontend/src/styles/theme.css` 与 `docs/ui/Live-Artifact-4/styles/theme.css`），仅在现有色板内做层次、密度与状态语言升级，不引入新色系、无外部依赖、图标为手写内联 SVG、文案中文内联。

## 如何查看

- 双击打开 **`index.html`**（本目录）——方案 × 页面切换预览 + 「三方案并排对比」模式。
- 或直接打开任一方案目录下的 `nodes.html` / `upstreams.html` / `routes.html`（自包含，双击即开）。
- 路由页工具条修订对比：**`routes-toolbar-variants.html`**（V1 / V2 / V3 三变体 + 1280/1366 宽度预算标尺；当前三方案暂套 V2）。
- 页面右下角有方案角标，方便对照时识别当前方案。

## 三方案一览

| | 方案 A · 秩序与密度 | 方案 B · 数据概览 + 列表 | 方案 C · 网关控制台感 |
|---|---|---|---|
| **一句话主张** | 骨架不动，纯层次与细节打磨：页头一行式统计 + 工具条收进表格卡 + 状态胶囊 + 分页规范化 | 在 A 的表格语言之上，页首增加一排轻量统计卡，页面更有「产品概览」气息 | 强调网关领域结构：节点按集群分组、上游权重可视化、路由转发链路管线 |
| **改动幅度** | 保守（推荐基线） | 中度 | 较大 |
| **页头统计** | 实底统计徽标 4 枚 | KPI 卡 ×4（**已被用户否决**：与页头/组头三层重复 + 高度成本，理由记录在案） | **轻徽标定稿**：24px 描边胶囊 4 枚，总数段 accent 描边 |
| **打开** | `proposal-a/` | `proposal-b/` | `proposal-c/` |

### 方案 A · 秩序与密度（proposal-a/）

**主张**：参考 Ant Design Pro 的紧凑列表，布局骨架与功能位置尽量不变，解决「工具条元素堆叠无层次、状态标识不统一、操作列拥挤」三个核心病灶。

**变更点**
- 页头一行式：标题 + 统计徽标（共 27 · 运行中 21 · 已停止 4 …）+ 主操作按钮，一眼获得页面上下文。
- 筛选工具条收进表格卡内（table toolbar 形态），右端固定「计数 → 列配置 → 刷新」，左端「搜索 → 筛选下拉」；控件统一 32px 紧凑档。
- 「列配置」弹层重新设计：分区标签（显示字段 / 操作按钮 / 搜索）、拖拽调宽调序提示条、「序号列恒展示」说明、右下角「重置列宽」。
- 表格解剖升级：表头 11px 不再强制大写英文、hover 时表头右缘出现拖拽把手暗示；行 hover 用极浅 accent 底色；选中行 accent 高亮。
- 状态统一为「胶囊 + 圆点」语言：运行中 / 已停止 / 未检测 / 已禁用（虚线框），检测时间移到徽章下方作为次级信息，不再与徽章横向挤在一格。
- 发布状态胶囊化：已发布 vX + 时间、待发布、部分失败（含原因）、未发布，附「差异预览」圆形按钮。
- 操作列按钮统一小号幽灵样式 + 图标，主行动「发布」用 accent 描边按钮突出；「⋯」更多菜单为两行式条目（主文案 + 灰色解释，危险项红色），与现行产品 `ux-action-menu-explanations` 语言一致。
- 节点页批量条：有选中时变为 accent 浅底强调态，按钮在未选中时降透明度；「清除选择」右置。
- 分页规范化：左侧「共 N · 每页选择」，右侧页码按钮 + 快速跳页。

**保持点**：所有筛选项、列集合、行内动作与「更多」菜单项、批量动作集、发布/删除/版本入口全部保留；导航、顶栏、卡片语言与 Live-Artifact-4 一致。

**风险与适用场景**：改动最小、验收成本最低，适合作为**本轮落地基线**；视觉张力有限。

### 方案 B · 数据概览 + 列表（proposal-b/）

**主张**：保留方案 A 的表格语言，页首增加一排轻量统计卡（KPI strip），让页面先回答「整体健康度如何」，再进入明细。

**变更点**（相对 A）
- 页首 4 张轻量统计卡：节点页（节点总数 / 运行中 + 在线率进度条 / 已停止 / 未检测）、上游页（总数 / 已发布 + 发布覆盖率 / 待发布 / 部分失败）、路由页（总数 / 已发布 + 覆盖率 / 待发布 / DNS 路由）。示意数据，接入时取真实聚合接口。
- 页头不再重复统计徽标（信息移入 KPI 卡），其余与 A 完全一致。

**保持点**：同 A。

**风险与适用场景**：需要页面顶部多 ~90px 高度；适合管理汇报视角强、节点/路由规模较大的部署。若后端暂无聚合接口，可先按客户端统计实现。

### 方案 C · 网关控制台感（proposal-c/）

**主张**：让表格结构直接表达网关的领域关系——节点属于集群、上游是一组带权重的目标、路由是「匹配 → 转发」的链路。

**变更点**
- **节点页**：表格按集群分组，分组头行（accent 左侧条 + 集群名 + 「5 节点 / 4 运行中 / 1 已停止」芯片 + 可点击折叠箭头）分组收纳节点；「Edge 安装路径 / OpenResty 安装路径」两列合并为「安装路径」单列两行堆叠（`Edge` / `OR` 小标签）。
- **上游页**：「目标节点」升级为「目标节点与健康」——每个目标芯片带健康圆点 + 权重占比条 + `权重 · 百分比`，下方汇总「3 目标 · 全部健康 / 1 项待验证」。
- **路由页（集群分组定稿）**：方法 + URI 合并为「请求匹配」（chips 行 + mono URI 块）；**按集群分组**（组头 = accent 左条 + 集群名 + 「7 路由 · 6 已发布 · 1 待发布」状态芯片 + 折叠箭头），组内按优先级升序（示意数据中生产集群组含 P10/P11 相邻的同前缀行）；列结构 = 名称（+DNS 徽章+描述）｜请求匹配｜优先级（84px mono 徽章、表头排序箭头）｜上游（accent chip + 「· N 节点」示意）｜发布状态胶囊｜创建时间｜操作；**无集群列**（归属由组头表达）。
- **上游页（集群分组定稿）**：与节点页同款组头（集群名 +「5 上游 · 3 已发布 · 2 待发布」+ 折叠箭头），无集群列；「目标节点与健康」特色列保留（健康圆点 + 权重占比条 + 汇总行）。
- 其余（工具条、批量条、发布状态、操作列、分页）与 A/B 同语言。
- **工具条三形态完整页**（表格区均为集群分组）：`routes.html` = V2；`routes-v1.html` = V1；`routes-v3.html` = V3；`routes-l2.html` = **不分组对照版**（V2 工具条 + 平铺 L2 表格 + 集群列保留）；`routes-sort-demo.html` = **排序平铺交互演示**（V2 + 分组，可真实点击排序/清除）。

**保持点**：全部功能保留；被合并的列在「列配置」中仍为独立字段（合并是**呈现层**行为，实现时由渲染层合并单元格即可，列配置数据结构不变）。

**风险与适用场景**：离现有表格形态最远，行高更高、信息密度略降；分组折叠与列合并需要一定实现工作量。适合作为「控制台风格」深化方向的**单页试点**（建议先试点路由页的转发链路，或节点页的集群分组）。

### 路由页「转发链路」讨论与最终裁决（L1 / L2 → 分组定稿）

初版曾把 优先级 › 上游 › 集群 三段画成一条箭头链路，**已废弃**，用户两条修正：① 集群是路由的**归属**（路由所在集群），不是转发目标，不能画进箭头链路；② 合并列的表头排序必须绑服务端字段——现按 `name / uri / priority / created_at` 走服务端排序。讨论中先后提出 L1（合并 优先级›上游 + 集群独立列）与 L2（全独立列）两版，**最终裁决：采用 L2 全独立，并且路由页与上游页按集群分组（组头包裹）省掉集群列**。

| 形态 | 状态 | 说明 |
|---|---|---|
| 三段箭头链路 | 废弃 | 集群归属语义不进链路 |
| L1 链路瘦版（优先级›上游 + 集群列） | 被裁决取代 | 「转发链路」绑 priority 排序的思路保留在分组版优先级表头 |
| **L2 全独立 + 集群分组**（定稿） | routes.html / routes-v1 / routes-v3 | 无集群列；优先级 84px mono 徽章（表头排序箭头示意）、上游 accent chip 附「· N 节点」（示意） |
| L2 平铺不分组对照 | routes-l2.html | V2 工具条 + 集群列保留；支持跨集群全局排序，作为分组版对照 |

**取舍重述**：分组版让「集群」由组头一次性表达（省一列、同集群路由聚集，组内优先级相邻关系如 P10/P11 一眼可读）；不分组对照版支持跨集群全局排序与紧凑平铺，两者并排供对照。

## 路由页工具条修订（V1 / V2 / V3）

**修订原因**：用户实测 1366 / 1280 视口下，「全部 / GET / POST…」方法 chips 与筛选控件同行放不下，后段控件被挤换行。详见 **`routes-toolbar-variants.html`**（同一页面上下纵向展示三个变体，各带宽度预算标尺）。

### 集群分组的实现注意（路由 / 上游 / 节点同款）

1. **页内分组**：后端分页模型不变时，分组是**当页分组**——当页按「集群 → 优先级/名称」排序后聚组，翻页后组会聚散；「整组翻页」（按集群为单位分页）需后端支持，属后续增强，不在本轮范围。
2. **分组态表头排序（定稿：显式双模式，覆盖此前「隐式切换 + 提示条」方案）**：工具条右端设「分组 | 平铺」切换器（默认分组）。分组模式：组头 + 组内按优先级升序，**表头点击不排序**——弹一次性提示「分组模式下不可排序，切换「平铺」后可按表头排序」（3.2s 自动消失或点击任意处关闭），表头 hover title 同步说明；平铺模式：无组头，表头升 / 降序切换（箭头指示，服务端全局排序语义），「清除排序」恢复平铺默认序（不回分组）。切换模式即清除排序键（避免休眠状态）；折叠记忆只在分组模式生效。裁决理由：排序动作不应隐式改变表格结构——两态显式切换互不偷袭。**可交互演示页：`routes-sort-demo.html`**（正式版三页待演示页认可后统一落地）。**交互已定稿并同步**：nodes / upstreams / routes（及 routes-v1/v3）均已接入同款「分组 | 平铺」切换器与双模式行为（排序仅路由页开放——生产可排序列为 名称/URI/优先级/创建时间，节点/上游生产无表头排序，平铺态仅隐藏组头不提供排序，不发明生产没有的排序）。
   **修订（用户裁决，覆盖「切换即清排序」旧实现）——排序键跨模式保留但只在平铺生效**：平铺设了排序后切分组，排序不参与组内顺序（组内固定优先级升序，箭头与清除按钮隐藏）；再切回平铺，箭头、顺序、清除按钮**原样恢复**，无需重新点表头。理由：保留可无缝往返的分析状态，箭头可见使排序状态不藏。
3. **折叠状态前端记忆**：各组折叠状态写 `localStorage`（键如 `route-groups-folded`），进入页面恢复上次状态；组内行数变化（增删路由）不影响记忆键。
4. **集群列虽移除，集群筛选下拉保留**（工具条「全部集群」）；组头即集群信息的常驻表达，配「全部集群」筛选可快速聚焦单组。列配置中「集群」字段保留（供平铺对照版/未来需要时勾选）。
5. **筛选跨模式永久保留**：筛选是数据集选择（搜索 / 分组 / 集群 / 上游 / 插件 / 发布状态 / 方法等条件在分组与平铺下作用于同一数据集），切换模式不清筛选；分组模式下没有命中行的集群组**不显示**（不出空组）。
6. **排序键跨模式保留但只在平铺生效**：分组期间排序键休眠（箭头与「清除排序」按钮隐藏、不参与组内顺序），切回平铺时箭头、顺序、清除按钮原样恢复——保留可无缝往返的分析状态。此裁决覆盖「切换即清排序」旧实现。
