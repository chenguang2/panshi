# 中继区域管理 · UX 重设计蓝图

> 页面：`frontend/src/views/RelayGateways.vue`（约 1200 行单页）
> 配套静态示例：`docs/refactoring/relay-gateways-ux-redesign-mockup.html`（浏览器直接打开预览）
> 性质：**纯设计文档，不改任何业务代码**。

---

## 1. 问题定义

用户原话：「新建和编辑字段过多，很多意义不明确，用户不知道填什么和含义；整个界面的其他按钮的含义也不知道如何用。」

拆解为三类问题：

| # | 问题 | 现状证据 |
|---|------|----------|
| P1 | **表单字段无分组、含义不明** | 12 个字段一屏铺开；「OpenResty 前缀」「SSH 公共参数」等运维术语无解释；「留空 = 直连」藏在 placeholder 括号里 |
| P2 | **动作按钮含义不明、易混** | 「初始化网关 / 下发配置 / 配置跳板转发」三个 SSE 动作名称相似；菜单项只有名字没有说明；用户不知道何时该点哪个 |
| P3 | **页面缺「这是什么、什么时候用」的开场** | 只有 PageHeader 一行 description；没有结论式引导（对比证书管理页的 cert-banner 范式） |

## 2. 设计目标

1. **三步走心智**：让用户第一眼建立「登记区域 → 初始化网关 → 下发配置」的流程心智。
2. **表单分层**：12 字段按「基础身份 / 网关两腿连接 / SSH 凭据 / 高级参数」分组，每字段一句说人话的帮助文案（填什么 + 不填会怎样）。
3. **直连显性化**：`http_base_url` 与 `ssh_jump` 留空 = 直连区域的语义必须成为显式 UI 状态，而不是括号里的备注。
4. **动作可区分**：三个易混 SSE 动作给出「何时用哪个」的对照引导；每个按钮有 tooltip / 二级描述。
5. **保护语义可视化**：删除的集群挂接保护（409）、清单缺组前置拦截，都体现在按钮态与提示上。

## 3. 整体布局备选对比

| | 方案 A：单页 · 说明卡 + 分组表单（推荐） | 方案 B：新建/编辑改分步向导 | 方案 C：表格精简 + 详情抽屉分层 |
|---|---|---|---|
| 结构 | 保持单页表格；页顶加 cert-banner 说明卡 + `<details>` 动作对照表；表格精简为 6 列；新建/编辑弹窗内字段分 3 组 + 折叠高级组 | 新建/编辑改为 3 步向导（EdgeImport 范式）：①基础身份 → ②两腿连接 → ③凭据与高级，逐步校验 | 表格只留「区域/两腿/状态/健康/操作」；SSH 用户、前缀、更新时间等全部收进点击行打开的详情抽屉，抽屉内再挂编辑入口 |
| 优点 | 改动最小、零后端依赖；一次解决 P1/P2/P3；保留用户肌肉记忆；表格行数少（全站区域数量级 ≤10），无分页/性能压力 | 每步只做一件事、强制顺序，首次创建体验最好；与数据导入页范式一致 | 表格最干净；详情信息可以很完整；为将来区域数量增长留了空间 |
| 缺点 | 弹窗仍是一次呈现 12 字段（但分组+帮助文案后认知负担大降） | **编辑一个字段也要走 3 步**，日常编辑繁琐；向导状态机实现与测试成本最高；本页使用频率低（装机才用），ROI 不足 | 多一层交互（先抽屉再编辑）；实现量最大；对 ≤10 行的小表格属于过度设计 |
| 适用性 | 使用频率低、字段一次性录入、动作多的管理页 | 字段间有强依赖顺序的新建流程 | 高频查阅、行内信息拥挤的大表 |

**推荐：方案 A**，理由：

1. 本页是**低频运维页**（首次装机才走全流程），不是高频录入页——向导的强制顺序价值有限，反而抬高编辑成本（B 的致命伤）。
2. 用户痛点是「不知道填什么、按钮不知道干嘛」，本质是**文案与分层问题**，不是布局问题——方案 A 用说明卡 + 分组 + 帮助文案直接命中，且全部可纯前端落地。
3. 方案 C 的「表格精简」精华已被 A 吸收（SSH 用户 / OpenResty 前缀两列移除，收进编辑弹窗与查看配置弹窗）；详情抽屉可作为将来增强项，不在本期。
4. 风险最低：不动 API、不动 composable、不动 SSE 流程，验收只看渲染层。

## 4. 推荐方案：页面信息架构

```
PageHeader（标题 + 描述 + [全量体检] [＋ 新建区域]）
├─ relay-banner  结论式说明卡（蓝 info 变体，cert-banner 范式）
│    结论句：哪些局需要建中继区域？
│    解释段：两条腿是什么 / 不建会怎样
│    三步走：① 登记区域 → ② 初始化网关 → ③ 下发配置
├─ <details> 动作对照表（install-guide 范式，默认折叠）
│    三列：初始化网关 / 下发配置 / 配置跳板转发（何时用 + 做什么）
│    附：常见症状 → 建议动作 对照
├─ card 区域列表（6 列）
│    区域 | 网关两腿 | 状态 | 健康 | 更新时间 | 操作
│    操作 = [测试] [下发配置] [更多 ▾]
│    更多菜单：每项带一行 11px 二级描述
├─ 弹窗：新建/编辑区域（分组表单，手写 modal-overlay，约定 #25 不变）
├─ 弹窗：体检结果（保留现有分段展示，追加「建议动作」行）
└─ 抽屉：执行过程（NodeExecutionResultDrawer，保留不动）
```

### 4.1 列精简说明

| 现列 | 处置 | 理由 |
|---|---|---|
| 区域码 + 展示名 | 合并为「区域」列（名字加粗 + 蓝色 code 标签） | 同一身份的两半，合读更自然 |
| 网关 HTTP 腿 + SSH 跳板 | 合并为「网关两腿」列（两行 mono；均为空显示「直连」info 徽章） | 建立「两条腿」心智；直连显性化第一层 |
| SSH 用户 | **移除**（收进编辑弹窗 + 查看配置） | 属「配置细节」而非「运行状态」，扫读表格不需要 |
| OpenResty 前缀 | **移除**（查看配置弹窗首行已展示；编辑弹窗可查） | 同上；超长路径在表格里只是噪音 |
| 状态（含健康行） | 拆为「状态」（启用/禁用 + 清单缺组）与「健康」（体检结果 + 时间）两列 | 健康列显式保留（硬约束），且与状态语义正交 |
| 更新时间 / 操作 | 保留 | — |

## 5. 字段文案总表（12 字段 → 3 组 + 折叠高级组）

> 文案风格对齐证书管理页：结论式、说人话、每个 hint 同时回答「填什么」和「不填会怎样」。
> 布局建议：弹窗内改**标签在上**（antd Form 垂直布局），hint 在输入框下方 12px muted——比现状「标签与输入同行」更容纳长 hint。

### 组 ① 基础身份

| 字段 | label | 必填 | placeholder | 帮助文案（form-hint） | 编辑态 |
|---|---|---|---|---|---|
| code | 区域码 | ★ | `小写字母开头，如 luju` | 创建后不可修改；集群靠它挂接本区域，同时用作网关清单分组名（`gateways_区域码`）。 | **只读展示**（input disabled + 锁形图标），保留硬约束 |
| name | 展示名 | ★ | `如：济南局` | 显示给人看的名字：列表、弹窗与执行日志都用它，可随时改。 | 正常编辑 |
| status | 状态 | — | select：`启用` / `禁用（该区域回退直连）` | 禁用只是「改走直连」：网关机上的配置原样保留，随时可再启用。 | 正常编辑 |

### 组 ② 网关两腿连接（组说明：平台到该局的两条通道）

组顶部加**连接方式分段选择**（直连显性化第二层，纯前端派生）：

- ● **有网关机** —— 两腿都经网关中转（默认）
- ○ **直连区域（无网关机）** —— 两腿留空，该局全部操作按直连执行，适合网络本就互通的局

选「直连区域」时 http_base_url / ssh_jump 两个输入禁用并清空；选回「有网关机」恢复。两个字段**任一非空即视为有网关机**，编辑回显按此派生。

| 字段 | label | 必填 | placeholder | 帮助文案（form-hint） |
|---|---|---|---|---|
| http_base_url | 网关 HTTP 腿 | ○ | `如 https://10.10.1.1:8443` | 发布、回滚等管理请求经它进入该局（网关机 8443 反向代理）；留空 = 这条腿不走网关、直接连节点。 |
| ssh_jump | SSH 跳板 | ○ | `如 tunnel@10.10.1.1:22` | 安装、初始化等 SSH 任务先跳到这台网关机再进局内；留空 = SSH 直连节点。 |
| openresty_prefix | OpenResty 前缀 | ○* | `如 /work/jboss/tunnel/openresty-1.21.4.1/nginx` | 网关机上 nginx 的安装目录（含 conf/sbin/logs）；只有要用「初始化网关」时必填，可以先建区域后补。 |

\* 条件必填：点「初始化网关」时校验，不在表单里强制（与现状一致，现状是执行前 message 拦截）。

### 组 ③ SSH 凭据

| 字段 | label | 必填 | placeholder | 帮助文案（form-hint） |
|---|---|---|---|---|
| ssh_user | SSH 用户 | ★ | `网关机上的账号，如 jboss / tunnel` | 平台用这个账号登录网关机执行配置，会写入网关清单。 |
| ssh_password | SSH 口令 | — | 新建：`留空 = 用密钥登录`<br>编辑：`已从服务端加载（加载动作已记录审计）` | 口令不出现在列表里；编辑时自动按需从服务端加载回填，单独查看会记录审计日志。 |
| ssh_port | SSH 端口 | — | 默认 `22` | 网关机的 SSH 端口，默认 22，改过才需要填。 |

> 硬约束落实：口令「不出列表、编辑按需单查」语义完整保留——编辑打开时调 `fetchGatewayCredential` 回填（现状已有），placeholder 明示「已从服务端加载」，hint 明示审计。表单不改变任何加载/保存时序。

### 折叠组 ④ 高级参数（`<details>`，默认收起，组名带「一般不用改」）

| 字段 | label | placeholder | 帮助文案（form-hint） |
|---|---|---|---|
| ansible_python_interpreter | Python 解释器 | `如 /work/jboss/anaconda3/bin/python3` | 仅当网关机系统默认 Python 低于 3.8（老机器常见）时填写。 |
| ssh_common_args | SSH 公共参数 | `-o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null` | 追加给每条 SSH 连接的参数；默认已跳过指纹确认，一般无需修改。 |

### 校验文案（保持现状，随分组移动位置）

- 区域码：`区域码格式错误：小写字母开头，仅含小写字母/数字/中划线，长度 2-32`
- HTTP 腿：`网关 HTTP 腿格式错误：须以 http:// 或 https:// 开头，如 http://10.10.1.1:8443`
- SSH 跳板：`SSH 跳板格式错误：须为 账号@主机[:端口]，如 tunnel@10.10.1.1:22`
- 前缀：`OpenResty 前缀格式错误：须为以 / 开头的绝对路径，如 /work/jboss/tunnel/openresty-1.21.4.1/nginx`
- 直连派生校验：选「有网关机」但两腿全空 → 允许保存（等价直连），但弹一次性 message 提示「两腿均为空，将按直连区域保存」，避免误留空。

## 7. 「初始化网关 vs 下发配置 vs 配置跳板转发」引导设计

三层引导，层层递进：

**第一层：说明卡内的三步走**（常驻，第一眼建立流程心智）

> ① 登记区域（新建，填地址与账号）→ ② 初始化网关（首次装机，写入 8443 监听）→ ③ 下发配置（推送节点白名单）

**第二层：`<details>` 动作对照表**（默认折叠，点开看细节；install-guide 范式三列）

| 动作 | 何时用 | 做什么 | 幂等性 |
|---|---|---|---|
| 初始化网关 | 首次装机、网关机重装 OpenResty 后 | 在网关机写入 8443 监听 server 块 + 当前白名单，校验后 reload | 幂等，可重复执行 |
| 下发配置 | 日常：集群挂接区域、节点增删、节点启停之后 | 只推节点白名单（全量替换），不动 8443 监听 | 幂等；空名单有危险确认 |
| 配置跳板转发 | 仅跳板 SSH 部署，且网关 sshd 默认禁转发时 | root 写 sshd drop-in 放行 PermitOpen 并 reload sshd | 幂等；格式不兼容自动降级 |

**第三层：体检结果里的「建议动作」行**（P1，见 §9 实施拆分）

体检结果每个失败分段后追加一行建议，把症状直接映射到按钮：

- HTTP 腿不可达 → 「建议：确认网关机 8443 服务已启动；首次装机请先执行『更多 ▾ → 初始化网关』」
- SSH 腿不可达 → 「建议：核对 SSH 跳板地址与账号；若报 `administratively prohibited`，执行『配置跳板转发』放行」
- 清单缺组 → 「建议：该局主机组尚未写入网关清单，执行『初始化网关』或『下发配置』前会先被拦截」

## 8. 状态语义设计

| 状态 | 呈现 | 硬约束对应 |
|---|---|---|
| 启用 / 禁用 | badge-success「启用」/ badge-neutral「禁用」 | 保留 |
| 清单缺组 | warning tag「清单缺组」+ title 保留原文案（SSH 主机组未写入网关清单，初始化/下发会被前置拦截） | **语义保留** |
| 健康 | 独立列：`✓ 正常`（绿）/ `✗ HTTP 腿不可达`（红）/ `未检测`（灰）+ 体检时间 mono；title 保留分段明细 | **保留（体检结果+时间）** |
| 直连区域 | 两腿单元格显示 info 徽章「直连 · 无网关机」；编辑弹窗分段选择自动落在「直连区域」 | **新增显性化**（`http_base_url` 与 `ssh_jump` 留空语义） |
| 删除保护 | 菜单删除项禁用 + 「已被 N 个集群挂接」描述（后端字段就绪后）；确认弹窗与 409 message 指引解挂 | **体现**（409 保护） |
| 区域码不可变 | 编辑弹窗 code 输入 disabled + 锁形图标 + hint「创建后不可修改」 | **体现** |

## 9. 实施拆分建议（低风险先行）

### 第一批：纯前端视图层，零后端改动，零行为变化（建议一个会话完成）

1. 页顶 `relay-banner` 说明卡（含三步走）+ `<details>` 动作对照表——静态内容，参照 `ssl-page-shared.css` 的 banner/guide 样式内联进本页 scoped style。
2. 新建/编辑弹窗分组化：3 组 + `<details>` 高级组；全部 label/placeholder/hint 按 §5 替换；标签改竖排。
3. 「更多 ▾」菜单项加二级描述文案。
4. 列精简：移除「SSH 用户」「OpenResty 前缀」两列，「网关 HTTP 腿」「SSH 跳板」合并为「网关两腿」，健康拆独立列；直连区域两腿格显示「直连」徽章。
5. 删除确认弹窗文案强调挂接保护（409 拦截现状不变）。

**验收**：`npx vue-tsc -b` + 既有 RelayGateways 组件测试全绿（表格列变更需同步更新测试断言列集合）。

### 第二批：小交互增强（可拆两个小 PR）
