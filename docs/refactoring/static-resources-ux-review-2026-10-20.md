## 一、主要问题清单

### P0

**P0-1 「已发布」徽章不代表已分发：上传 ZIP 即变「已发布」，与 Edge 真实分发状态脱钩**
- 徽章仅判断 `current_version` 是否存在（`StaticResourceList.vue:53-56`、`ClusterStaticResources.vue:22-23`）；而后端上传即写 `current_version`（`cluster_static_resources.py:384-397`），发布动作不改变任何列表可见字段 → 「仅上传」与「已分发」两种状态在列表上**完全不可区分**（实机截图 05/06/06b 证实）。
- 孤儿实锤：既有资源 id=1 的关联路由（route_id=22）已不存在，两入口仍显示「已发布」（列表端点不校验路由存在性，`static_resources.py` / `cluster_static_resources.py` 均无 join）。
- 基建已备未接入：`PublishStatusTag.vue:24-34` 已内置 `partial`（发布未完全生效）与 `pending`（待发布）两态，但静态资源两入口只传了 `version/published-at` 两个 prop。
- **限制说明**：彻底解决需后端持久化「最近一次发布结果」——当前 publish 响应的逐节点结果返回即弃、未落库（`cluster_static_resources.py:530-534`），纯前端无法感知分发状态。

### P1

**P1-1 全局页上传零反馈，Tab 上传有完整进度弹窗——同一动作两种世界**
- 全局页：静默 `api.post`，无进度、无按钮禁用，成功仅 toast（`StaticResourceList.vue:452-472`）；Tab：进度条 + 逐行日志弹窗（`useClusterStaticResources.ts:197-260`）。
- ~~超限时用户无从知道是超限~~【核验修正】：错误文案其实已完备——上传超限被后端拦截并返回可读中文（`cluster_static_resources.py:43,366-379`「zip 文件过大：上限 32MB」），发布腿 413 已有可读特译（`_publish_error_detail:417-429`）。真实缺口只剩**零进度反馈**本身。

**P1-2 发布日志泄漏英文状态「success」，且同一资源类型存在三份重复日志实现**
- 两入口发布弹窗节点行均原样输出 `r.status`（`StaticResourceList.vue:496`、`useClusterStaticResources.ts:281`），平台共享映射 `resultStatusLabel`（`useClusterUtils.ts:89`，共享流已在 :838 正确使用）未接入。中文运维界面夹生英文，且与其它资源类型发布日志（「成功」）不一致——即仓库约定 #51 点名的复制漂移模式。

**P1-3 编辑弹窗是死胡同：只能改描述，换绑路由必须删除重建**
- PUT 仅提交/接受 description（`StaticResourceList.vue:440-442`、`cluster_static_resources.py:268-269`）；两入口编辑弹窗「关联路由」均为只读。换绑路由 → 删除重建 → 版本历史清零 → 节点文件需重发，常见变更诉求没有安全路径。

**P1-4 覆盖类操作无预警：上传顶掉当前版本、发布覆盖节点文件，均无一句风险提示**
- 发布确认弹窗（`PublishConfirmModal.vue`）无资源摘要、无覆盖提示；上传成功结果无「发布前节点不受影响」说明。对照：删除有完善的双 scope 确认 + danger 红按钮（`useClusterUtils.ts:273-288`）。发布是本模块最高频危险动作，风险感知反而低于低频删除。
- 【核验补充】`PublishConfirmModal` 已有可选 `currentVersion` 提示行（「本次发布将创建新版本 vN+1」），但静态资源**不可直接复用**——静态资源的版本在**上传时**递增，发布不产生新版本，直接传会显示错误信息。应改为「将分发当前版本 vN 并覆盖节点文件」。

**P1-5 重复创建 409 报错只有一句「该路由已关联静态资源」，没有出口**
- `cluster_static_resources.py:163` detail 无资源名、无解法指引；若「元凶」是孤儿资源（路由已删），用户更无从排查。

**P1-6 路由下拉列出不合格路由且无标注，全局页下拉占位文案不显示【核验新增，约束 #204 同类】**
- 两入口路由下拉均未过滤/禁用不合格路由（`StaticResourceList.vue:399-406`、Tab 直接用 `cluster.routes`），选中 `/hello` 这类不合格路由只能靠弹窗内三条检查兜底。
- 全局页添加弹窗路由下拉初始化为 `null`，与占位 `<option value="">` 不匹配（`StaticResourceList.vue:106-109,275,379,414`）→ 按 Vue 原生 select 渲染规则 `selectedIndex=-1`，下拉显示空白而非「请选择路由」（弹窗打开与选集群重置两处均触发）——即约束 #204 记录的同型缺陷（无报错、断言全绿、表象是「下拉空白」）。

## 二、页面信息架构优化建议

1. **以「资源 → 版本 → 分发」三层重构状态叙事**：卡片头部只放身份（名称 + 路径 + 集群），右侧状态徽章（三态，见第六节），下方一行「当前版本 vN · 大小 · 最近分发时间」，把上传时间与分发时间分开。
2. **全局页与 Tab 职责收敛**：全局页 = 跨集群盘点 + 搜索过滤；Tab = 单集群操作台。当前功能集差异（查看 ZIP、上传反馈、弹窗细节）无职责理由，纯属实现漂移——参照 ClusterCard 收敛先例抽公共卡片组件，差异用 slot 表达。
3. **「路由资格」前置为对象属性**：以 `/` 结尾（`/*`）+ 已发布 + 挂 static_resource 插件三条件在路由列表/下拉统一标注，两入口与路由管理页共享同一判定。
4. **危险动作分级**：删除（完善）＞ 发布覆盖（补摘要+覆盖提示）＞ 上传覆盖（补一句说明）。覆盖提示做进确认弹窗静态摘要行，不新增弹层，避免确认疲劳。

## 三、关键页面模块布局建议

- **全局页卡片**：「发布」升唯一主按钮（实心），「版本管理」降次级，编辑/删除收入「⋯」溢出菜单（删除保持红色）；未上传态卡片中央给引导（「上传 ZIP 后可发布到 Edge 节点」+ 主按钮）。
- **发布确认弹窗**：顶部资源摘要条（名称/路由/版本/大小）；节点按「在线可发布 / 离线不可选」分组；计数「已选择 N 个在线节点」；底部一句覆盖提示。
- **Tab 面板**：顶部补一行与全局页一致的定位说明；空态加「或到侧边栏『静态资源』页跨集群管理」跳转。

## 五、交互流程优化建议

1. **「创建 → 上传 → 发布」轻量向导**（可选）：新建成功后内嵌第 2 步上传拖拽区（可跳过），上传完成后引导「立即发布？」。现状六次注视点切换，首次使用极易漏掉发布（且 P0-1 徽章还会谎报「已发布」）。
2. **编辑弹窗解锁换绑路由**（P1-3）：后端 PUT 扩展 route_id + 目标路由资格校验；弹窗内复用三条检查即时反馈。
3. **发布确认记忆上次节点集**：当前每次默认全选在线节点（`PublishConfirmModal.vue:138`），多节点集群重复发布易误扩范围。
4. **删除后保持过滤条件与滚动位置**（现整体 reload 跳回顶部）。
5. **搜索框加 × 清空**（现输入即滤但无复位控件）。
6. **全局页上传复用 Tab 进度弹窗** + 客户端 `file.size` 预检即时拦截（服务端文案已备）。

## 六、状态展示优化建议

目标状态机（徽章 + tooltip 双层）：

```
无 ZIP          → 「待上传」灰（引导上传）
有 ZIP 未分发   → 「待分发」琥珀（tooltip: 上传于 …，尚未分发到任何节点）
已分发 N/M      → 「已分发 N/M 节点」绿（tooltip: 最近分发时间 + 明细入口）
部分失败        → 「N/M 节点失败」红（tooltip 列失败节点与原因，一键重发失败节点）
路由已删除      → 「配置异常」红（tooltip: 关联路由不存在，请删除或重建）
```

- `PublishStatusTag.vue:24-34` 的 partial/pending 态与提示语可直接复用，需传 `pending`/`lastPublishStatus` prop。
- **后端前置**：publish 逐节点结果需持久化（当前返回即弃）；三态徽章是前后端联动改动，非纯前端。
- 时间语义拆分：版本行「上传时间」（updated_at）、徽章 tooltip「最近分发时间」。
- 离线节点在发布确认/结果弹窗已统一灰态 + 标签（予以肯定）；建议卡片在部分节点离线时提示「1 个节点离线，发布将跳过」。
