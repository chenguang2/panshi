## 1. 主要问题清单（按严重度）

### P0 —— 反馈自相矛盾 / 结果语义失真

**P0-1 整体失败也弹「发布完成」绿色成功 toast**
`EdgeEnv.vue` `executePublish` 的 complete 分支（:677-682）无条件 `message.success('发布完成')`，不区分 `publishResult.status`（all_success / partial / all_failed）。全部失败时用户同时看到绿色「发布完成」+ 红色节点失败卡片，反馈自相矛盾。同分支还无条件把 `savedContent` 更新为编辑内容——失败发布的内容成为后续 diff 的「基线」，污染下一次变更对比。

**P0-2 全部失败的部署也创建版本记录并推进「当前版本」**
后端 `deploy_stream`（`cluster_edge_env.py` :166-175）计算 `overall_status` 后**无条件** `create_config_version` 并在 complete 事件携带新版本号——`all_failed` 时同样建版本。版本列表的「v30 当前」徽章语义因此失真：它只表示「最近一次发布动作产生的版本记录」，可能根本没有任何节点在运行该内容。用户据「当前版本」判断线上状态会被误导。

**P0-3 假成功窗口：init/reload 失败仍报「成功」**
`edge_init_env.yml`：`bin/edge init` 步骤（:21-33）`failed_when: false`，`bin/edge reload` 步骤（:35-46）`failed_when: false + ignore_errors: true`——两步无论退出码如何都不产生 ansible 失败，playbook rc 恒 0。平台侧节点成功判定只看 rc==0（+ no-hosts-matched 守卫），于是 `edge init` 崩溃、reload 失败的节点照样显示绿色「成功」。与项目 #21「rc=0 ≠ 执行成功」教训同源，是发布链路残留的假成功窗口（备份/写入两步真实失败可以被发现，init/reload 不能）。

### P1 —— 流程 / 安全 / 一致性

**P1-1 未保存内容保护双标，且缺刷新守卫**
切换**节点**且有未发布修改 → 有确认弹窗（:468-479）；切换**集群** → `onClusterChange`（:456-466）静默清空编辑内容，无任何提示。全页无 `beforeunload` / 路由离开守卫——刷新或跳走直接丢内容。spec「编辑提示与确认」明确要求刷新/切换集群提示（S3 分歧）。

**P1-2 发布进度弹窗可随时关闭且无再入口**
`closePublishProgress`（:706-710）仅隐藏弹窗，SSE 流继续后台执行：进度无法回看、结果汇总错过即丢、无法取消。对照读取弹窗——关闭即 abort（:532-538）。同为「关闭」按钮，一个=中止、一个=放后台，语义双标；用户很可能以为关闭=取消发布。

**P1-3 节点选择弹窗离线节点可选**
spec 要求「非活跃节点置灰不可选」，实际 `.publish-node-item.disabled` 样式类存在但从未绑定，`togglePublishNode` 不检查 status（:625-629），「全选」也把离线节点一并选中（:631-633）。发布到离线节点必失败，白白多一轮 ansible 失败日志（S2 分歧）。

**P1-4 节点选择弹窗开屏红字报错**
弹窗打开时 `selectedPublishNodeIds` 为空（默认全不选，:616），红色「请至少选择一个节点」立即显示——与 SSL 评审 P0「开屏误报」同族：把「尚未操作」当「操作错误」呈现（截图 07）。spec 写的是「默认全选」（S1 分歧）。

**P1-5 diff 呈现不可用**
`computeDiff`（:563-592）按行号位置逐行对比（非 LCS）：中间插入一行，其后**所有行**都被误报为「修改」；同时全文件每行都渲染（无上下文折叠），100+ 行文件里找真实变更要肉眼滚动。无「+N −M」变更摘要、无跳转变更块。实测（文末追加一行注释）diff 弹窗展示整份 108 行内容，变更行在最底部，首屏零高亮（截图 06）。

**P1-6 diff 基线语义不明且有误导**
对比基线是「最近一次读取的内容」（`savedContent`），界面上没有任何说明；从未读取、直接手输内容时基线为空串 → diff 弹窗显示全文绿色「新增」。基线既不是「最近发布版本」也不是「目标节点现行内容」（多节点时各节点内容可能本就不一致），用户无从判断「这次发布到底改了什么」。

**P1-7 部署失败错误文案质量双标**
读取流对常见失败做了友好转译（UNREACHABLE → 「无法连接，请检查网络和 SSH 配置」等，`cluster_edge_env.py` :274-283），部署流却只有裸值 `ansible rc=-1`（:159-160）——同一机制两处处理不一致，失败排障成本不对称。

### P2 —— 易用性 / 文案 / 层级 / 状态

**P2-1 「获取配置模板」名不副实**：实际行为是「读取所选节点**当前**的 edge.env」，不是模板（模板暗示预置样例）。页头主按钮、弹窗标题、日志文案全套沿用该误导命名。
**P2-2 双主色按钮 + 动线割裂**：页头右上「获取配置模板」「发布」两个 `btn-primary` 并列，视觉层级竞争；而上下文选择器（搜索/分组/集群/节点）在工具栏左侧，主流程「选集群→选节点→读取→编辑→发布」横跨页面两角。
**P2-3 编辑器空态提示伪装成内容**：悬浮提示绝对定位在 Monaco 行号槽内（`.ee-empty-hint` top:14px left:64px，:727-734），看起来就像第 1 行文件内容（截图 02）；且集群/节点已选后文案仍是「选择集群与节点后点击…」的过时指引。
**P2-4 无 dirty 标记、无内容来源标识**：编辑器不显示「有未发布修改」，也不显示「内容来自哪个节点、何时读取」。多节点配置可能不一致，页面无任何提示，用户易把 A 节点内容当作全集群现状。
**P2-5 读取完成反馈弱**：内容已填入编辑器但弹窗不自动关、无「已载入编辑器」状态行，唯一线索是日志区一行 ✅（截图 04）；读取中点「关闭」= 中止，按钮语义未说明。
**P2-6 空态无行动指引**：「请先选择一个集群」一行灰字（截图 01），无下拉引导/CTA；「当前集群无节点」态同样只有一句陈述。
**P2-7 读取来源不醒目**：选中集群后静默自动选中第一个节点，节点下拉仅显示 `IP:管理端口`（无名称/备注），「当前内容来自哪台机器」不在视觉焦点内。
**P2-8 版本记录无操作者**：版本列表恒显示「由 system 发布」——`ConfigVersion` 不记录操作人（`edge_sync._create_config_version` 无 created_by），追溯只能绕道审计日志。
**P2-9 失败重试成本高**：部分失败后要重新走「发布→diff→勾选节点」全流程，没有「重试失败节点」快捷入口。
**P2-10 校验错误不定位**：YAML 语法错误有行号、缺字段有字段路径，但都只在 alert 弹窗文本里，不跳转编辑器对应行，用户需自行查找。
**P2-11 URL 不同步**：手动切换集群不更新 `?cluster_id=`（spec 要求跳转同步，S4 分歧），刷新后选择丢失。

### spec–实现分歧（S1–S5，随本变更修正）

| # | spec 说 | 实际 | 处置 |
|---|---|---|---|
| S1 | 发布节点「默认全选」 | 默认全不选 + 开屏红字 | 以「默认全选在线节点」实现，修 spec |
| S2 | 离线节点「置灰不可选」 | 可选 | 补禁选，修 spec |
| S3 | 刷新/切换集群有离开提示 | 仅切换节点有确认 | 补齐实现 |
| S4 | 选集群后「自动跳转 ?cluster_id=」 | 不更新 URL | 补 URL 同步，修 spec |
| S5 | SSE 事件 `{node,step,status,message}` + backup/write/init/reload 步骤卡片 | `{type,node_start/node_done/complete,ip,route}` + ansible 原始行 | spec 陈旧，按实现重写该场景（#45 同类分歧） |

## 2. 信息架构优化建议

现状三层割裂：① 页头右上操作区（读取/发布/版本）② 工具栏左侧上下文区（搜索/分组/集群/节点）③ 编辑器主体。主流程动线横跨两角。

建议收敛为「**一条上下文栏 + 一个编辑区 + 一条状态条**」：

```
PageHeader（标题 + 描述）
──────────────────────────────────────────────────────────────
[集群▼ showSearch] [节点▼]      [读取节点配置] [发布●] [版本管理]
──────────────────────────────────────────────────────────────
 状态条：内容来自 192.168.0.13 · 读取于 10-22 09:55 ｜ ● 未发布修改 ｜ diff 基线：该节点当前配置
──────────────────────────────────────────────────────────────
 Monaco YAML 编辑器
```

- 集群搜索与分组过滤收进集群下拉（`a-select showSearch` 或分组 optgroup），工具栏从 4 控件减为 2。
- 操作按钮与上下文选择同栏，读取（secondary）→ 发布（primary 唯一主色）→ 版本管理（ghost），按流程顺序排列。
- 编辑器与操作之间加**状态条**，承载来源、dirty、diff 基线三信息（详见 §6）。

## 3. 关键模块布局建议

| 模块 | 现状 | 建议 |
|---|---|---|
| 读取弹窗 | 全屏遮罩弹窗 + ansible 原始日志 + 手动关闭 | 保留流式日志（排障价值），成功后自动关闭 + toast「已载入 {ip} 的当前配置」；失败时保留弹窗供看日志，关闭=中止在按钮 title 说明 |
| diff 确认弹窗 | 全文件平铺灰字，变更行靠滚动寻找 | 头部摘要行「+N −M · 基线：{来源}」；unified 视图仅渲染变更块 ±3 行上下文，块间「⋯ 未变更 N 行 ⋯」折叠条 |
| 节点选择弹窗 | 全不选 + 开屏红字 + 离线可选 | 默认全选在线节点；离线行置灰不可点（保留展示，注明「离线」）；红字仅在点击确认且 0 选中时出现；底部加后果行「将把上述内容写入所选节点并执行 edge init / reload 生效」 |
| 发布进度弹窗 | 可随时关闭、无再入口、无取消 | 发布进行中禁用关闭（发布不可取消是事实，诚实呈现）；完成后显示汇总条 + 「重试失败节点」（预填失败节点集）；失败节点错误文案与读取流同款转译 |
| 版本管理弹窗 | 左列表右详情 + 对比模式（已较好） | 「当前」徽章补 tooltip 语义说明；列表补操作者（暂缓，见 D10） |

## 4. 文案优化建议

| 位置 | 现文案 | 建议 | 理由 |
|---|---|---|---|
| 页头按钮 / 弹窗标题 | 获取配置模板 | **读取节点配置** | 行为是读取当前配置，非模板 |
| 完成 toast | 发布完成（无条件） | 全部成功→「发布完成」；部分→「发布完成，N 个节点失败，请查看失败原因」（warning）；全部失败→「发布失败」（error） | 反馈与结果一致（P0-1） |
| 节点选择红字 | 请至少选择一个节点（开屏即红） | 移至确认时机；默认全选后基本不出现 | 开屏误报（P1-4） |
| diff 弹窗标题/按钮 | 确认变更 / 继续选择节点 | 「确认发布内容」/「下一步：选择节点」 | 表达意图而非机制 |
| 空态 | 请先选择一个集群 | 「在上方选择集群后，可读取与编辑该集群的 edge.env」+ 高亮集群下拉 | 可行动 |
| 无节点空态 | 当前集群无节点，无法管理 edge.env | 补指引「请先在「集群管理」中为该集群添加节点」 | 可行动 |
| 部署节点失败 | ansible rc=-1 | 与读取流同款转译（无法连接 / SSH 认证失败 / 不在主机清单 / 保留 rc 兜底） | 错误可行动、两腿一致（P1-7） |
| 版本「当前」徽章 | 当前 | 「当前」+ tooltip「最近一次发布创建的版本；发布全部失败时不产生新版本」 | 语义澄清（P0-2） |

## 5. 交互流程优化建议

1. **读取**：选节点 → 点「读取节点配置」→ 弹窗流式日志 → 成功**自动关闭** + toast；失败留在弹窗看日志。有未发布修改时先确认丢弃（现状保留）。
2. **发布**（5 步减为 4 步且每步防错前置）：编辑器点「发布」→ 前端校验（错误带行号，点击跳转编辑器行）→ diff 确认（摘要 + 紧凑 diff）→ 节点选择（默认在线全选、离线禁选）→ 进度（不可关）→ 完成汇总 + 重试失败节点。
3. **离开保护三面齐**：切节点确认（已有）+ 切集群确认（补）+ beforeunload / 路由守卫（补）。
4. **发布中断语义诚实化**：发布中弹窗不可关闭；若用户离开页面，SSE 断开后台仍会执行完（后端特性），页面在重新进入时以「集群卡片版本徽章 + 版本管理」承接结果——本轮不在 UI 伪造「已取消」。

## 6. 状态展示优化建议

- **编辑器状态条（新增）**：`内容来自 {ip} · 读取于 {MM-DD HH:mm}`（无读取时「未读取，手动输入」）｜ `● 未发布修改`（dirty 徽章，editorContent !== savedContent 时出现）｜ 发布成功后 dirty 清零。
- **发布节点卡**：成功/失败/发布中 + 「（经中继）/（直连）」标注保留现状（已是全站一致范式）；失败卡错误文案按 P1-7 转译。
- **完成汇总条**：全部成功（绿）/ 部分成功（橙，列失败节点）/ 全部失败（红）+ 「成功 N / 失败 M」+「重试失败节点」按钮。
- **版本列表**：「当前」徽章补语义 tooltip；空状态区分「从未发布」与「筛选无结果」（当前仅后者形态存在）。
