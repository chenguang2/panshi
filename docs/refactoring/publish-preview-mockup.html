发布差异预览（待发布 vs Edge 节点实况）

解决「保存后显示待发布，但不知道待发布版本与各 Edge 节点数据差在哪」：把逐节点找数据库对比的排查，收敛为一次点击的逐节点差异报告。

设计示例页（静态假数据，非生产代码）· 上游 user-service · 集群 demo-cls · 3 节点

推荐

方案 A · 单资源差异预览（交互演示见下）

入口：「待发布 / 发布未完全生效」标签旁的小三角按钮
  • 点击 → 只读查询各活跃节点的该资源实况，弹窗汇总报告
  • 矩阵表：字段路径 × 待发布值 × 各节点当前值，逐格标差异
  • 头部结论条直接回答「能不能直接发布」：节点是否落后于上次发布
  • 复用漂移检测的采集与 diff 机器（EdgeClient HTTP 腿，中继感知）
✓ 正面回答你描述的痛点，一次点击、逐节点、秒级
✗ 逐资源查询（批量场景另有方案 C 兜底）

方案 B · 版本管理内对比（纯平台侧）

入口：版本管理弹窗，待发布时显示「当前配置 vs vN」
  • 平台侧 diff：上次发布快照 vs 当前 DB 行，零网络请求
  • 回答「我改了什么」，不回答「各节点现在是什么样」
✓ 便宜、稳定、离线可看
✗ 看不到节点差异/落后节点（可并入 A 作为弹窗内的一个段落）

方案 C · 集群级「发布预检」批量报告

入口：集群卡片/列表工具栏「发布预检」按钮
  • 一次拉取全部待发布资源 × 全部节点，一份批量报告
  • 适合「发布前最后检查一遍」的批量场景
✓ 发布前总览，顺带发现落后节点
✗ 单资源「这个待发布改了啥」路径变长；与漂移检测入口职责接近

推荐组合：A 为核心（本页演示），A 的弹窗内含 B 的平台侧变更段（零额外成本）；C 作为后续独立立项，非本批范围。
