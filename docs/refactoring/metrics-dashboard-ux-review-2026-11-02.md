# 指标总览 UX 评审报告（2026-11-02）

> 评审对象：指标总览页 `/metrics/dashboard`（`MetricsDashboard.vue` + 6 个子组件 + `metricsDashboard` store + `metrics.py`/`metrics_service.py`）。
> 评审方法：① 通读前端页面/组件/store/API 层与后端 `metrics_service.py` 全量源码；② 在运行中的开发环境实测——Playwright 全页截图 3 张（默认态 / 展开更多指标 / 周对比尝试）+ DOM 布局测量 + 8 个 API 直接探针（登录态）。
> 关联能力主 spec：`metrics-dashboard`、`time-comparison`、`node-health-monitoring`、`route-traffic-stats`、`http-status-analysis`、`metrics-source-status`。
> 结论：共 19 项问题——**高 4 / 中 7 / 低 8**；其中 1 项为功能性缺陷（周对比恒空态），3 项为「数据可信度」缺陷（裸值直出、字节不人性化、数据质量语义失真）。修复提案见 `openspec/changes/metrics-dashboard-ux-optimization/`。

## 一、实测证据摘录

| 证据 | 结果 |
|---|---|
| `GET /metrics/time-comparison?comparison_type=week_over_week` | 返回 `this_week_requests / last_week_requests / change_rate / data_quality / this_week_sample_count / last_week_sample_count` |
| `TimeComparisonCard.loadData` 字段守卫 | 仅接受 `typeof d.today_requests === 'number'` → 周对比载荷**永远不满足**，`dayData` 恒 null → 卡片恒显「当前无数据」 |
| `GET /metrics/node-health?health_type=status` | `{"node_ip":"192.168.100.42","status":1,"last_seen":"2026-11-02 08:20:42.887000"}` —— 状态列直出裸 `0/1`，时间列直出微秒字符串 |
| `GET /metrics/node-health?health_type=resource` | `capacity_bytes:52428800`、`usage_percent:0.6` —— 卡片直出裸字节与无 % 裸数 |
| `GET /metrics/summary` | `source_ok: true`（采集健康），但 `day_over_day` 返回 `today_requests: 0, data_quality: "partial"`（今日采样 501/1440，属「统计日未结束」）→ 前端显示黄色「部分」警示，**零流量 + 采集健康也被标黄** |
| 展开更多指标截图 | 「共享字典容量 30498760」「共享字典剩余 10428232」——原始字节直出 |
| DOM 测量 | `.app-main` 1200px 居中、卡片 568px×2 列——布局宽度正常，与全站一致（排除「内容挤左」疑点） |
| `NodeHealthCard.onTypeChange` | `currentType.value = val` 触发 `watch(currentType)` 又手动 `loadData()` → 每次切换发两个相同请求 |

## 二、五维评审结论

### 1. 易用性

- **全局刷新半途而废（中）**：手动「刷新」与自动定时器只调 `store.loadAllCharts()`——路由统计、HTTP 状态码分析、时间对比、节点健康四卡不参与；基础设施区仅手动刷新（展开时）覆盖、自动刷新永不覆盖。页面下半部分静默陈旧，与上半部分时间基准脱节。
- **无「数据更新于」时间戳（中）**：自动刷新不可感知，运维无法判断看到的是多久前的数据。
- **加载态缺失（中）**：`MetricChartCard` 无 loading 态——首次加载与切换时间范围期间（`setTimeRange` 会清空 `chartDataMap`）所有业务卡先显示「当前无数据」再弹出数据；仅控制区一颗小「加载中…」tag。
- **错误不可重试（中）**：失败后只能整页刷新或等待自动刷新，无单卡重试。
- **高频目标可达性良好**：数据源横幅带「查看 ClickHouse 配置」直链（前轮评审成果），时间范围/刷新控件就近——这部分保持。

### 2. 易于理解

- **周对比恒空态（高，功能性缺陷）**：下拉里有「周对比」选项，选了永远「当前无数据」——功能承诺与实现脱节的最典型形态。
- **裸值直出（高）**：节点状态 `0/1`、最后上报 `2026-11-02 08:20:42.887000`、使用率 `0.6`（无 %）、共享字典容量 `30498760`（字节）、带宽列原始 bytes/s、错误率无 %、延迟无 ms。
- **「Nginx 连接状态」头部数字语义不明（中）**：头部大数字是 active 序列最新值，但值旁无「活跃」标注，第一眼不知道「1」是什么。
- **数据质量「部分」语义失真（高）**：把「统计日未结束」（每天必然大半时段如此）呈现成黄色警示，且不展示样本数（后端已返回 `today/yesterday_sample_count`）——制造无谓焦虑（本维度「避免不必要警示」实锤）。
- **空态无语境（中）**：采集健康、流量为零时（当前环境实况），业务卡显示「当前无数据」，无法区分「没有流量」与「采集断了」。
- **「采集错误率」放错组（中）**：它是采集链路健康指标，却排在「业务指标」网格里，与节点健康（同为链路健康）分离。

### 3. 界面美观与信息层级

- **无分区标题（低）**：页面是 10+ 张同尺寸卡的平铺序列，路由统计全宽、其余半宽、业务 3 卡占 2 列（第三卡独占一行左格）、节点健康单卡占半行（右格空白）——卡片顺序无叙事、网格节奏不齐。
- **图表无任何坐标轴（低）**：sparkline 极简风格，24h/7d 范围下无时间刻度，只能靠 tooltip 逐点摸索；属有意权衡，本轮保留，仅记录。
- **时间对比卡细节（低）**：「数据质量」tag 用 `margin-top:4px` 与数值基线错位；变化率红涨绿跌把「流量上升」标成负面色（语义存疑，本轮不动，加 tooltip 说明）。
- **正例**：卡片风格统一（白底圆角、12px 弱色标题、等宽字体大数值）、数据源横幅配色克制——视觉基线良好。

### 4. 安全与风险感知

本页为只读观测页，无危险操作；风险维度落在**数据可信与新鲜度感知**上：

- **数据源不可用**：横幅（既有，source_ok=false 时出现，含目标地址与修复入口）+ 业务卡「数据加载失败」——这部分合格。
- **缺口一（中）**：同一个「ClickHouse 不可用」故障，业务卡显示「数据加载失败」（红字）、扩展四卡显示「当前无数据」（灰字）——三种表述并存，扩展卡把「读不到」伪装成「没有数据」。
- **缺口二（中）**：自动刷新不可见（无更新时间、无最后刷新标记），陈旧数据无感知。

## 三、问题清单（按严重度）

### 高（P0，4 项）

| # | 问题 | 证据 |
|---|---|---|
| H1 | **「周对比」选项恒空态**——前端仅接受 `today_requests` 字段，周对比载荷为 `this_week_requests/last_week_requests`，永远渲染「当前无数据」 | 代码 + API 实证（第一节） |
| H2 | **节点健康裸值直出**——状态列 `0/1` 无 badge；最后上报原始微秒字符串；资源视图使用率无 %、无进度条、无阈值色 | 截图 + API |
| H3 | **数值不人性化**——共享字典容量/剩余原始字节；路由带宽 bytes/s 原始字节；错误率无 %；延迟无 ms；与全站 `utils/format.ts`（formatFileSize 等）约定脱节 | 截图 + 代码 |
| H4 | **「数据质量=部分」语义失真**——统计日未结束即标黄警示；样本数已返回但不展示；零流量+采集健康也呈现「数据存疑」观感 | API：`today_requests:0, data_quality:"partial"` |

### 中（P1，7 项）

| # | 问题 |
|---|---|
| M1 | 手动刷新与自动刷新不覆盖扩展四卡与（自动刷新时的）基础设施区；页面上下两部分时间基准脱节 |
| M2 | 无「数据更新于」时间戳，自动刷新不可感知 |
| M3 | `MetricChartCard` 无加载态：首载/切时间范围先闪「当前无数据」再出数据 |
| M4 | 错误无归因、无单卡重试；数据源不可用时扩展卡显示「当前无数据」而非「数据源不可用」（同一故障三种表述） |
| M5 | 「Nginx 连接状态」头部数字无「活跃」标注，语义不明 |
| M6 | 空态无语境：流量类与上报类空态同文案「当前无数据」，无法区分「无流量」与「无上报」 |
| M7 | `NodeHealthCard` 类型切换双请求（watch + 手动各触发一次） |

### 低（P2，8 项）

| # | 问题 |
|---|---|
| L1 | 无分区标题；业务 3 卡占 2 列、节点健康单卡半行空白、全宽/半宽混排——网格节奏不齐、顺序无叙事 |

## 四、本轮修复范围建议

- **P0**：H1–H4 全部修复（周对比修复、节点健康呈现、数值人性化、数据质量语义）。
