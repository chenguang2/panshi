# 中继区域管理 · 拓扑视图设计蓝图（relay-region-topology-view）

> 状态：**已批准（2026-11-06 用户逐项拍板：D1=A / D2=A / D3=A / D4=批次1+2，D5 默认采用）**。配套静态示例页：`relay-region-topology-mockup.html`（同目录，浏览器直接打开）。
> 变更工件：`openspec/changes/relay-region-topology-view/`。

## 1. 背景与动机

用户诉求（2026-11-06）：中继区域管理比较复杂，希望**加入一张图表示各方的关系**，并能在图中**添加、设置、编辑各字段的值**；参考形态 = MobaXterm「添加隧道」界面。

MobaXterm 隧道界面的本质：每条隧道呈现为一条**链式图形**（`[MyClient] → [SSH server] → [Remote server]`），链上每个节点显示关键参数、点击即编辑；新建隧道 = 在图上补一条链。它不是自由画布，而是**固定形状的链路图 + 分段编辑**。

中继区域管理恰好是同构问题：每个区域就是一条「进局链路」——

```
              ┌── HTTP 腿（管理面）：发布/回滚/状态查询 → 网关机 8443 反代（X-Edge-Target）
中控平台 ──────┤
（武清本地）    └── SSH 腿（任务面）：安装/初始化/节点任务 → 先跳网关机再进局
                        │
              ┌─────────┴─────────┐
        网关机（济南局）        nginx: 8443 白名单 edge_targets.conf / sshd PermitOpen
              │
      ┌───────┼────────┐
   集群A(挂接)  集群B(挂接)  …
   ├ 节点1      ├ 节点3
   └ 节点2      └ 节点4
```

现状（RelayGateways.vue 表格 + 弹窗）把这条链**压扁成两行文字**（「网关两腿」列的 HTTP/SSH 两行），挂接了哪些集群、哪些节点在白名单里、哪些还没下发，全靠用户脑补。拓扑视图把这些关系摊开在图上。

## 2. 可行性结论：可行，且不需要引入图库

| 依赖项 | 现状 | 结论 |
|---|---|---|
| 关系数据 | `relay_gateways`（区域注册 + 两腿 + 凭据 + 下发快照 `last_pushed_nodes`）、`ps_cluster.region_code`（挂接）、`ps_node.ip/management_port/status` | 全部现成 |
| 状态数据 | 体检三段（`网关HTTP腿` / `SSH跳板` / `抽样节点两腿`，含逐节点 error/note）、下发漂移 `push_drift`（added/removed）、清单缺组 `inventory_group_missing` | 全部现成，前端已有 |
| 写路径 | 编辑区域 `PUT /relay/gateways/{id}`、挂接/解挂 `PUT /clusters/{id}`（`region_code`，空串=解挂，已确认 exclude_unset 部分更新）、init/push/sshd SSE 流、体检 GET | 全部复用，**零新增写路径** |
| 读路径 | 缺一个聚合端点：列表只回计数，不回集群/节点明细 | 新增只读 `GET /relay/topology`（见 §6） |
| 图形 | 拓扑是**固定形状的链/树**（平台→网关→集群→节点），不需要拖拽画布 | 自绘 HTML/CSS 组件即可（见 §5 D2） |

不触碰的既有语义：SSE 流时序、`_INFLIGHT` 并发、口令单查审计、`#29` commit-before-IO、`#50` 两腿判定——全部原样复用。

## 5. 交互与技术选型（备选 + 推荐）

### D1 视图形态
| 备选 | 说明 | 评价 |
|---|---|---|
| **A（推荐）拓扑为默认视图 + 顶栏「表格视图」切换** | 拓扑卡承载全部关系；表格原样保留兜底（信息密度、多区域扫视） | 本功能目的就是看关系；区域通常个位数；两视图共存零风险 |
| B 表格默认，拓扑为切换视图 | 保守 | 拓扑入口弱化，功能价值打折 |
| C 表格行内展开拓扑（expand/drawer） | 最保守 | 图被藏在点击后，「在图中编辑」体验不成立 |

### D2 图形实现
| 备选 | 说明 | 评价 |
|---|---|---|
| **A（推荐）自绘链式组件**（HTML/CSS 为主，连线用伪元素/CSS 三角） | 零新依赖、样式全控、与站内 oklch 视觉一致；固定形状下完全够用 | 纯增量代码，无 bundle 代价 |
| B Vue Flow（React Flow 的 Vue 版） | 自由画布 + 节点拖拽 | +100KB 级依赖；自由拖拽对本场景是**负资产**（用户可拖乱固定链路），图内嵌表单反而别扭 |
| C AntV X6 | 同上更重 | 国内生态好但场景不匹配 |

### D3 编辑交互
| 备选 | 说明 | 评价 |
|---|---|---|
| **A（推荐）点图元 → 复用现有弹窗体系**；点两腿标签时弹窗打开并滚动聚焦对应分组 | 网关机=现有「编辑区域」弹窗（4 分组 + 高级折叠，上一轮 UX 重设计已批准）；集群=新小弹窗；节点=只读 popover | 字段全集（口令/高级参数）不适合内联；复用 = 零新表单逻辑、测试全继承 |
| B MobaXterm 式分段内联表单（图元旁就地展开 input） | 观感最像参考物 | 12 字段内联破坏图布局；口令内联体验差；要重写校验/审计回填 |
| C 右侧常驻详情面板 | 桌面端顺手 | 窄屏差，与站内既有弹窗范式不一致 |

### D4 图内写操作范围（按批次）
- **批次 1（推荐必做）**：只读拓扑渲染 + 视图切换 + 卡头动作区平移（测试/下发/更多菜单/体检，逐字复用现有逻辑）。
- **批次 2（推荐必做）**：图内编辑——点网关机/两腿（编辑弹窗+聚焦）、集群挂接/解挂弹窗（复用 `PUT /clusters/{id}` 的 `region_code`）、`+挂接集群`、节点只读 popover。
- **批次 3（可选，默认不做）**：节点 popover 内加 启用/停用 开关（复用节点启停 API）；直连区域引导卡细化。
- **不做**：图内节点增删/编辑节点字段（属集群域，跳转节点管理页）；自由拖拽布局。

### D5 拓扑数据端点（我的判断，默认 A）
- **A（采用）**：`GET /relay/topology` 一次返回全部区域 + 挂接集群 + 节点明细 + 服务端算好的 `whitelist_state`。区域规模小，单请求最简单；`whitelist_state` 在服务端单点派生，前端不再各自推导（防 #51 式多实现漂移）。
- B 每区域懒加载——仅当单页区域很多才有意义，当前无此需求。

## 6. 新端点设计（唯一后端新增）

```
GET /api/v1/relay/topology
权限/总闸：沿用 router 级 require_permission("relay_gateway") + _require_relay_feature（零改动）
响应：
{ "regions": [ {
    id, code, name, status, http_base_url, ssh_jump, openresty_prefix,
    last_pushed_at,
    clusters: [ { id, name, display_name, nodes: [
        { ip, management_port, status,
          whitelist_state: "synced" | "pending_add" | "pending_remove" | "off" }
    ] } ] } ],
  "unregistered_bound_codes": ["xxx"]   // 集群挂了但无网关注册行的区域码
}
```

- `whitelist_state` 派生规则（服务端单点实现，与 `list_gateways` 的 `push_drift` 同一快照语义）：
  - `synced`：`status==1` 且 `ip:管理端口 ∈ last_pushed_nodes`
  - `pending_add`：`status==1` 且不在快照（对应 `push_drift.added`）
  - `pending_remove`：`status!=1` 且在快照（对应 `push_drift.removed`）
  - `off`：`status!=1` 且不在快照
  - 快照为 `None`（从未成功下发）：全部 enabled 节点按 `pending_add`、disabled 按 `off`，前端以「尚无成功下发记录」提示
- 无模型/列改动 → 不触发 #118 `COLUMN_MIGRATIONS`、不触发 #31 PG 冒烟强制品（只读 select）；仍跑该文件的常规 API 测试。

## 7. 验收标准

1. 拓扑视图完整渲染：全部注册区域（含直连、禁用、清单缺组）、挂接集群、节点行、`whitelist_state` 徽章、体检徽章（体检后实时更新，未检测显示「未检测」）、悬空区域码 ghost 卡。

3. **表格视图与现有页面逐像素/逐行为一致**：现有 `RelayGateways.test.ts` 全部用例零改动通过（本变更为增量视图，不改既有 DOM 与行为——对齐 #217 断言继承原则）。
4. 新端点测试：权限 401/403、feature 关闸 404、直连区域、悬空码、whitelist_state 四态、快照 None 兼容。
5. 前端组件测试：图元渲染、徽章派生、点击回调（弹窗/聚焦/popover）。
6. 交互文案与本蓝图 §4 逐字一致；mockup.html 为视觉基准。
